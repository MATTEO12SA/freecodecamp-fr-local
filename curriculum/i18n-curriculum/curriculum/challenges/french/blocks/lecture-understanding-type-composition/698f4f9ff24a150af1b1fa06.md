# --description--

Dans les leçons précédentes, tu as appris à travailler avec les types primitifs ainsi qu’avec les types union et les interfaces.

Mais TypeScript a quelques types spéciaux que tu dois connaître. Commençons par examiner le type `any`.

Le type `any` est utilisé pour représenter n’importe quel type de valeur.

```ts
let randomValue: any;

randomValue = 42;

randomValue = "Hello";

randomValue = true;

randomValue = { name: "Alice" };
```

Avec ce type, tu dois être prudent car il peut facilement être surutilisé et mal utilisé. Tu ne veux pas tout typer avec le type `any` juste pour faire taire les messages d’erreur de TypeScript. Cela va à l’encontre de l’intérêt d’utiliser TypeScript et d’ajouter la sûreté des types.

Un équivalent plus sûr du type `any` serait le type `unknown`. `unknown` est similaire à `any`, mais avec le type `unknown`, tu dois faire une vérification de type sur la variable avant de l’utiliser.

Voici un exemple :

```ts
function doubleValue(value: unknown) {
  if (typeof value === "number") {
    console.log(value * 2);
  } else if (typeof value === "string") {
    console.log(value + value);
  }
}

doubleValue(10);
doubleValue("Hi ");
doubleValue(true);
```

Dans cet exemple, les vérifications de type garantissent que les opérations ne sont effectuées que sur des valeurs du type correct. Les valeurs qui ne correspondent pas aux types attendus sont ignorées.

Le prochain type que nous allons examiner est le type `never`. Ce type représente quelque chose qui n’arrivera jamais.

Dans la plupart des situations, tu n’écriras pas d’annotations de type avec `never`. Au contraire, tu verras très probablement le type `never` apparaître dans des messages d’erreur comme celui-ci :

```ts
function processValue(value: string | number) {
  if (typeof value === "string") {
    console.log("String value:", value.toUpperCase());
  } else if (typeof value === "number") {
    console.log("Number value:", value * 2);
  } else {
    console.log(value);
  }
}
```

Dans la clause `else` de l’exemple ci-dessus, la `value` a un type `never`. C’est parce que la branche `else` est désormais impossible à atteindre et qu’il ne reste aucun type. Si tu essayais d’appeler la fonction avec une valeur autre que `string` ou `number`, cela afficherait une erreur comme celle-ci :

```ts
function processValue(value: string | number) {
  if (typeof value === "string") {
    console.log("String value:", value.toUpperCase());
  } else if (typeof value === "number") {
    console.log("Number value:", value * 2);
  } else {
    console.log(value);
  }
}

// Argument of type 'boolean' is not assignable to parameter of type 'string | number'.
processValue(true);
```

Le dernier type que nous allons examiner est le type `void`. Quand tu as une fonction qui ne renvoie pas de valeur, ce serait un type `void`.

Voici un exemple :

```ts
type Status = "loading" | "success" | "error";

type Handler = {
  status: Status;
  onChange: (newStatus: Status) => void;
};
```

Dans cet exemple, la propriété `onChange` pour le type `Handler` ne renvoie rien, c’est pourquoi `void` est utilisé.
