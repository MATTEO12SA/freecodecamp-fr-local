# --description--

Dans une leçon précédente, tu as appris à travailler avec les alias de type et tu as vu des exemples pour nommer des types d’objets.

Comme tu te souviens, une façon de nommer un type d’objet est d’utiliser le mot-clé `type` comme ceci :

```ts
type ID = number | string;

type User = {
  id: ID;
  name: string;
};
```

Une autre façon de nommer un type d’objet est d’utiliser une déclaration `interface` comme ceci :

```ts
type ID = number | string;

interface User {
  id: ID;
  name: string;
}
```

`type` et `interface` sont similaires, mais une différence clé est que les interfaces utilisent le mot-clé `extends` pour s’appuyer sur d’autres interfaces, tandis que les alias `type` utilisent des types d’intersection (`&`) pour combiner des types.

Regardons quelques exemples :

```ts
interface User {
  id: number | string;
  name: string;
}

interface Admin extends User {
  role: string;
}

const adminUser: Admin = {
  id: 101,
  name: "Alice",
  role: "superadmin"
};
```

Dans cet exemple, `User` commence avec `id` et `name`. L’interface `Admin` étend `User`, ce qui signifie qu’elle inclut `id` et `name` et ajoute une nouvelle propriété appelée `role`.

Si tu voulais étendre un `type`, tu utiliserais un type d’intersection (`&`) comme ceci :

```ts
type User = {
  id: number | string;
  name: string;
};

type Admin = User & {
  role: string;
};

const adminUser: Admin = {
  id: 101,
  name: "Alice",
  role: "superadmin"
};
```

`Admin` combine le type `User` avec un nouveau type d’objet qui inclut `role`. Le résultat a la même forme que l’exemple d’interface : un objet avec `id`, `name` et `role`.

Les `type` et les `interface` peuvent tous deux décrire la forme d’un objet. Si tu n’es pas sûr de celui à utiliser, rappelle-toi que `interface` est spécifiquement conçu pour les formes d’objets, tandis que `type` est plus flexible et peut aussi représenter des types union, des primitifs et des combinaisons de types plus complexes.
