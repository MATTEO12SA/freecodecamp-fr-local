# --description--

Parfois, tu te retrouveras dans des situations où tu en sauras plus sur un type que TypeScript. C’est là que les assertions de type deviennent utiles.

Voici un exemple utilisant la méthode `querySelector()` pour accéder à un élément avec l’`id` `submit` :

```ts
const submitBtn = document.querySelector("#submit");
```

Pour l’instant, TypeScript sait seulement que ce `submitBtn` est une sorte d’`Element` ou éventuellement `null`. TypeScript ne regardera pas le HTML correspondant pour le déterminer.

C’est un bon endroit pour utiliser une assertion de type afin de dire à TypeScript de quel type d’élément il s’agit. Voici un exemple :

```ts
const submitBtn = document.querySelector("#submit") as HTMLButtonElement;
```

Maintenant, TypeScript traitera ceci comme un élément `button` grâce à cette assertion de type.

Il y a des limites à l’utilisation du mot-clé `as`. Par exemple, tu ne peux pas faire des choses comme ceci sans que TypeScript lève une erreur :

```ts
// Conversion of type 'string' to type 'number' may be a mistake because neither type sufficiently overlaps with the other. If this was intentional, convert the expression to 'unknown' first.
const age = "awesome" as number;
```

Dans cet exemple, cela n’a pas beaucoup de sens d’essayer d’affirmer que la chaîne `"awesome"` devrait être vue comme un type number. TypeScript n’autorise les assertions de type qu’entre des types compatibles ou qui se chevauchent.

Une façon de supprimer cette erreur serait d’utiliser une double assertion comme ceci :

```ts
const age = "awesome" as unknown as number;
```

Même si cela fonctionne en TypeScript, ce n’est toujours pas recommandé car logiquement cela n’a pas beaucoup de sens.

Une autre façon d’écrire des assertions de type est d’utiliser la syntaxe entre chevrons comme ceci :

```ts
const submitBtn = <HTMLButtonElement>document.querySelector("#submit");
```

Tu dois faire attention avec cette syntaxe quand tu utilises des fichiers `tsx`, car TypeScript pensera que tu essaies de rendre un composant et lèvera une erreur comme celle-ci :

```ts
// file: index.tsx
// This JSX tag requires 'React' to be in scope, but it could not be found.
// JSX element 'HTMLButtonElement' has no corresponding closing tag.
const submitBtn =  <HTMLButtonElement>document.querySelector("#submit");
```

Dans la plupart des situations, tu verras la première syntaxe utilisant le mot-clé `as` être utilisée plutôt que la seconde option.
