# --description--

Même si des outils comme Lighthouse et Chrome DevTools sont excellents, parfois tu as besoin d'insights personnalisés adaptés à ton site.

C'est là qu'interviennent les Performance Web APIs !

Dans cette leçon, on découpera comment utiliser trois Web APIs clés pour mesurer et analyser la vitesse de ton site.

Mais d'abord, que sont les Performance Web APIs ?

Les Performance Web APIs permettent aux développeurs de suivre dans le code l'efficacité du chargement et de la réactivité d'une page. Ces APIs te permettent de mesurer les temps de chargement, de suivre les délais de rendu et d'interaction, et d'analyser le temps d'exécution JavaScript.

Avec ces APIs, tu peux construire tes propres outils de suivi de performance sans dépendre de logiciels tiers !

Explorons trois Web APIs puissantes que tu peux utiliser dès aujourd'hui.

Pour commencer, `performance.now()`.

Cette API te donne des horodatages haute précision (en millisecondes) pour mesurer combien de temps différentes parties de ton site mettent à charger.

Disons que tu veux mesurer la vitesse d'exécution d'une fonction :

```js
const start = performance.now();
// Run some code here
const end = performance.now();

console.log(`Execution time: ${end - start}ms`);
```

C'est plus précis que d'utiliser `Date.now()` car elle mesure le temps en millisecondes avec une précision à la microseconde, en évitant les problèmes de dérive d'horloge. Tu peux l'utiliser pour suivre le temps d'exécution des scripts, les délais de réponse aux événements, et la performance des animations.

Ensuite, la Performance Timing API.

Cette API te donne une décomposition de chaque étape du chargement de page, de la résolution DNS à `DOMContentLoaded`.

Tu veux mesurer combien de temps ta page met à charger entièrement ?

```js
let [navigationTiming] = performance.getEntriesByType("navigation");

if (navigationTiming instanceof PerformanceNavigationTiming) {
  // Calculate time from navigation start to DOM content loaded
  const pageLoadTime =
    navigationTiming.domContentLoadedEventEnd - navigationTiming.startTime;

  console.log("DOM Content Loaded Time:", pageLoadTime, "ms");
}
```

Les métriques clés que tu peux suivre avec cette API sont le temps de résolution DNS — autrement dit la vitesse de connexion, le Time to First Byte (TTFB) — autrement dit la vitesse de réponse serveur, et `DOMContentLoaded` — autrement dit quand la page est prête pour l'interaction.

Si les temps de chargement de ta page sont lents, cette API pinpointe exactement où se trouve le délai !

Et enfin, parlons de `PerformanceObserver`.

Cette API écoute les événements de performance comme les layout shifts, les longues tâches et les interactions utilisateur.

Tu veux surveiller les longues tâches JavaScript ?

```js
const observer = new PerformanceObserver((list) => {
  list.getEntries().forEach((entry) => {
    console.log(`Long task detected: ${entry.duration}ms`);
  });
});

observer.observe({ type: "longtask", buffered: true });
```

Et que peut suivre cette API ? Eh bien, elle peut suivre les longues tâches — autrement dit le JavaScript qui bloque le rendu, les layout shifts pour détecter le jank UI, et le First Input Delay (FID) — autrement dit la vitesse à laquelle une page répond à une saisie utilisateur.

Si tu veux un suivi de performance en temps réel, cette API change la donne.

Alors, quelle API utiliser ? Voici une comparaison rapide :

| Performance API        | Best For                                           |
| :--------------------- | :------------------------------------------------- |
| `performance.now()`    | Precise timing of functions and scripts            |
| Performance Timing API | Measuring full page load performance               |
| Performance Observer   | Real-time monitoring of interactions and rendering |

En combinant ces APIs, tu peux construire tes propres outils de mesure de performance et suivre exactement ce qui compte le plus pour ton site.
