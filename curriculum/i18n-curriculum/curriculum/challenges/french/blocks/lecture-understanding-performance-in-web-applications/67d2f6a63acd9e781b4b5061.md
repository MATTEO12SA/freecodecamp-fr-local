# --description--

Pourquoi certains sites semblent-ils vifs et réactifs, tandis que d'autres semblent lents ? La réponse se trouve dans des concepts clés de performance qui affectent le chargement et le rendu d'une page. Comprendre ces concepts est essentiel pour construire des sites rapides, fluides et agréables à utiliser.

Décortiquons l'ordre source, le critical rendering path, la latence, et plus encore.

Regardons d'abord l'ordre source.

L'ordre source désigne la façon dont les éléments HTML sont structurés dans le document. Cela détermine ce qui se charge en premier et peut fortement impacter la performance et l'accessibilité.

Quelques bonnes pratiques incluent :

- Placer le contenu critique comme les titres, la navigation ou le texte principal plus haut dans la structure HTML.

- Différer les scripts non essentiels comme ceux d'analytique ou les widgets tiers, pour qu'ils ne bloquent pas le rendu.

- Utiliser l'amélioration progressive, pour que l'expérience de base fonctionne même avant le chargement des styles et scripts. L'amélioration progressive consiste à construire des sites et applications en partant du principe que ta page doit d'abord fonctionner avec HTML.

Voici un exemple de bon ordre source, en suivant les bonnes pratiques qu'on vient de voir.

```html
<!-- Good source order: Essential content first -->
<h1>Welcome to FastSite!</h1>
<p>Critical information loads first.</p>
<script src="slow-script.js" defer></script>
```

En optimisant l'ordre source, on s'assure que les utilisateurs voient le contenu important dès que possible.

Regardons maintenant le critical rendering path.

Le critical rendering path est la séquence d'étapes que suit le navigateur pour convertir le code en pixels à l'écran.

Voici les étapes clés qu'on détaillera plus tard :

1. Parsing HTML : construit le DOM (Document Object Model)

2. Parsing CSS : construit le CSSOM (CSS Object Model)

3. Exécution JavaScript : peut modifier le DOM et le CSSOM

4. Construction de l'arbre de rendu : combine le DOM et le CSSOM

5. Layout et painting : détermine les tailles des éléments et dessine les pixels

6. Optimisations :

    - Minimiser les ressources qui bloquent le rendu (par ex. gros fichiers CSS, JS inutilisé).

    - Utiliser les attributs async et defer pour les scripts :

    - Charger d'abord uniquement les styles essentiels ; différer le CSS non critique.

Dans l'ensemble, un critical rendering path plus court égale une performance perçue plus rapide. On y reviendra plus en détail plus tard.

Et enfin, regardons la latence.

La latence est le temps qu'une requête met pour aller du navigateur au serveur. Autrement dit, une latence élevée égale des pages lentes.

Quelques façons de réduire la latence :

- Utiliser des CDN, autrement dit des Content Delivery Networks, pour servir les fichiers depuis des emplacements plus proches.

- Activer la compression avec des outils comme Gzip pour réduire la taille des fichiers.

- Optimiser les images et utiliser le lazy loading — qu'on détaillera aussi plus tard.

En réduisant la latence, on fait ressentir les interactions comme instantanées.

En conclusion, en optimisant l'ordre source, en réduisant le critical path et en coupant la latence, tu peux faire sentir ton site rapide.
