# --description--

Comme on le sait, la performance perçue ne concerne pas seulement la vitesse réelle d'un site — c'est la vitesse à laquelle il se sent pour les utilisateurs. Par exemple, as-tu déjà utilisé un site qui semblait lent, même s'il ne l'était pas ? C'est la performance perçue — la vitesse à laquelle un site se sent pour l'utilisateur.

De petits ajustements peuvent faire une énorme différence dans l'expérience utilisateur. Explorons quelques façons pratiques d'améliorer la performance perçue !

Les spinners peuvent faire sentir aux utilisateurs qu'ils attendent plus longtemps qu'en réalité. À la place, essaie les skeleton screens — des placeholders gris qui imitent le vrai contenu et se chargent progressivement :

```html
<div class="skeleton"></div>
<script>
  setTimeout(() => {
    document.querySelector(".skeleton").innerHTML = "✅ Content Loaded!";
  }, 2000);
</script>
```

Les utilisateurs sentent que la page charge progressivement, plutôt que d'attendre dans le noir.

En plus de cela, les utilisateurs ne devraient pas avoir à tout attendre avant de pouvoir commencer à interagir. Charge d'abord le contenu important, puis le reste en arrière-plan. On a déjà vu cela avec le lazy loading :

```html
<img src="placeholder.jpg" data-src="real-image.jpg" class="lazy">
<script>
  document.addEventListener("DOMContentLoaded", function () {
    const lazyImages = document.querySelectorAll("img.lazy");
    lazyImages.forEach(img => {
      img.src = img.dataset.src;
    });
  });
</script>
```

Cela rend la page réactive, même si tout n'est pas encore chargé.

Maintenant — et si ton site pouvait prédire ce que l'utilisateur cliquera ensuite ? Avec le preloading, tu peux récupérer la page suivante avant qu'il ne la demande :

```html
<link rel="preload" href="next-page.html" as="document">
```

Cela réduit le temps de chargement perçu quasi à zéro quand les utilisateurs naviguent.

Et enfin, les utilisateurs n'aiment pas l'incertitude. Quand ils cliquent sur un bouton, accuse réception de leur action instantanément :

```html
<button onclick="this.innerText='⏳ Processing...'; setTimeout(() => this.innerText='✅ Done!', 2000);">
  Click Me
</button>
```

Cela signifie que, même s'il y a un délai, l'utilisateur sent que quelque chose se passe.

En conclusion, améliorer la performance perçue ne concerne pas seulement la vitesse brute : c'est la façon dont la vitesse se sent pour l'utilisateur. Utilise des skeleton screens, priorise le contenu important, précharge intelligemment, et donne un retour instantané pour que ton site se sente plus rapide.
