# --description--

Servir des fichiers statiques est une exigence courante dans les applications web. Les fichiers statiques incluent des assets comme des images, des fichiers CSS, du JavaScript côté client, des polices, et d'autres ressources qui ne changent pas dynamiquement.

Express rend le service de ces fichiers simple avec son middleware intégré `express.static()`.

Dans Express, servir des fichiers statiques signifie livrer des fichiers directement depuis le système de fichiers du serveur vers le navigateur du client sans aucun traitement supplémentaire côté serveur.

Par exemple, quand un navigateur demande des fichiers comme `/styles.css`, `/script.js` ou `/images/logo.png`, Express peut localiser ces fichiers dans un dossier spécifié et les servir directement. Si un fichier n'est pas trouvé, Express répondra automatiquement avec un 404. Comme ces fichiers n'ont pas besoin d'être générés ou modifiés sur le serveur, on les appelle *statiques*.

Cela rend le service d'assets comme les feuilles de style et les images facile, et retire le besoin de définir manuellement des routes pour chaque fichier.

Voici comment tu peux configurer le service de fichiers statiques dans Express :

```javascript
const express = require("express");
const path = require("path");
const app = express();
const port = 3000;

// Serve static files from the "public" directory
app.use(express.static(path.join(__dirname, "public")));

app.get("/", (req, res) => {
  res.send("Welcome to the static file demo!");
});

app.listen(port, () => {
  console.log(`Server running at http://localhost:${port}`);
});
```

D'abord, on importe `express` pour créer notre serveur et `path` pour construire en toute sécurité des chemins de fichiers sur différents systèmes d'exploitation.

Ensuite, `app.use(express.static(path.join(__dirname, "public")))` dit à Express de servir les fichiers depuis le dossier `public`. Le middleware `express.static()` dit à Express de servir les fichiers depuis le dossier `public`. Tout fichier à l'intérieur de ce répertoire devient accessible au navigateur.

On définit aussi une route `GET` simple pour `/` qui envoie un message de bienvenue. Cela montre que le service de fichiers statiques peut coexister avec des routes dynamiques.

Enfin, `app.listen()` démarre le serveur sur le port 3000. Une fois le serveur en marche, les requêtes pour les assets statiques dans le dossier `public` sont gérées automatiquement.

Pour que cela fonctionne, tu as besoin d'un dossier nommé `public` pour stocker tes fichiers statiques. Une structure de projet typique pourrait ressembler à ceci :

```md
my-app/
│
├── app.js
└── public/
    ├── index.html
    ├── styles.css
    └── image.png
```

Quand un utilisateur fait une requête, par exemple en visitant `http://localhost:3000/index.html`, Express vérifie si le fichier demandé existe dans le répertoire `public`. Si le fichier existe, Express l'envoie directement au navigateur. Si le fichier n'existe pas, Express passe au middleware suivant ou renvoie une réponse 404.

Rappelle-toi que tu n'as pas besoin de définir des routes pour chaque fichier, donc une requête vers `http://localhost:3000/styles.css` signifie qu'Express cherche `public/styles.css` et y répond automatiquement.

Tu peux aussi personnaliser comment les fichiers statiques sont servis. Par exemple, tu pourrais servir des fichiers depuis plusieurs répertoires ou configurer le comportement de cache.

Imagine que ton app a cette structure de fichiers :

```md
my-app/
│
├── app.js
│
├── public/
│   ├── index.html
│   └── styles.css
│
└── images/
    └── image.png
```

Voici comment tu peux enregistrer plusieurs répertoires pour servir des fichiers statiques :

```javascript
app.use(express.static(path.join(__dirname, "public")));
app.use("/images", express.static(path.join(__dirname, "images")));
```

Ici on utilise `app.use(express.static(path.join(__dirname, "public")));` comme avant, ce qui signifie que les fichiers dans le répertoire `public` sont servis depuis le chemin racine, comme avant.

Mais si tu regardes la ligne suivante, tu verras qu'on passe `"/images"` comme premier argument à `app.use()`, suivi de `express.static(path.join(__dirname, "images"))`. Dans ce cas, `"/images"` est un chemin de montage, qui dit à Express de n'utiliser ce middleware que quand il reçoit une requête vers `/images`. Quand c'est le cas, `express.static()` se déclenche et cherche des fichiers dans le répertoire `images`.

Donc avec cette configuration, voici comment fonctionneraient les requêtes suivantes :

*   GET `http://localhost:3000/styles.css` : Express cherche dans le répertoire `public` pour `styles.css`, trouve le fichier, et l'envoie au client.

*   GET `http://localhost:3000/images/image.png` : Comme cette requête commence par `/images`, Express cherche dans le répertoire `images` pour `image.png`, trouve le fichier, et l'envoie au client.

Servir des fichiers statiques avec Express est simple et puissant. En utilisant `express.static()`, tu peux facilement servir des assets comme des images, des feuilles de style et du JavaScript côté client.

Garder les fichiers statiques dans un dossier dédié comme `public`, ou en utilisant plusieurs répertoires et chemins de montage, aide à garder ton application organisée, maintenable et facile à faire évoluer.
