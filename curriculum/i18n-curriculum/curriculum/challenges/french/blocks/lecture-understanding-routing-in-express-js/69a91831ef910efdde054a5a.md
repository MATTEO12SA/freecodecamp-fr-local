# --description--

Dans Express, les paramètres de route sont des valeurs dynamiques intégrées dans le chemin d'URL. Ils laissent ton application capturer des parties de l'URL qui peuvent changer à chaque requête. C'est utile pour construire des pages dynamiques, comme afficher un utilisateur, un article de blog ou un produit spécifique selon l'URL.

Voici un exemple :

```javascript
// Route with a parameter in the path
app.get("/post/:postId", (req, res) => {
  const postId = req.params.postId;
  res.send(`Viewing post with ID: ${postId}`);
});
```

Ici, la route écoute les requêtes GET vers `/post/:postId`.

* `:postId` est un paramètre de route, un placeholder dans l'URL qui sera remplacé par une valeur réelle. Par exemple, une requête vers `/post/42` correspond à cette route, et `42` devient la valeur de `postId`.

* Tu peux accéder aux paramètres de route avec `req.params`. L'objet `req.params` contient tous les paramètres de route, et dans ce cas, `req.params.postId` contient la valeur de l'URL, `42`.

Enfin, `res.send()` envoie une réponse au client. Donc si l'URL est `/post/42`, le client voit `Viewing post with ID: 42`.

Comme tu peux le voir, les paramètres de route rendent tes routes flexibles et dynamiques sans avoir besoin d'une route séparée pour chaque valeur possible.

Maintenant que tu comprends comment fonctionnent les paramètres de route, revenons à un exemple de la leçon précédente et voyons comment tu peux utiliser des routes dynamiques pour différents types de menus :

```javascript
app.get("/menu/:category", (req, res) => {
  const category = req.params.category;
  res.send(`You are viewing the ${category} menu!`);
});
```

Et voici une décomposition de comment cela fonctionne :

1. Un utilisateur visite [`http://localhost:3000/menu/drinks`](http://localhost:3000/menu/drinks).

2. Le serveur fait correspondre cette requête à la route `/menu/:category` et capture le paramètre `category` comme `drinks`.

3. Le serveur envoie cette réponse au navigateur : `You are viewing the drinks menu!`

De même, si l'utilisateur visite [`http://localhost:3000/menu/food`](http://localhost:3000/menu/food), le serveur répond avec ce qui suit : `You are viewing the food menu!`

Les paramètres de route te laissent afficher du contenu dynamique selon l'URL. Au lieu de créer une route séparée pour chaque catégorie, tu peux utiliser une seule route pour gérer plusieurs catégories comme drinks, food, desserts, et plus, simplement en changeant l'URL.

Quel est le rôle de `:postId` dans la route `/post/:postId` ?

## --answers--

C'est une partie statique de l'URL.

### --feedback--

`:` indique un paramètre, pas un segment fixe.

---

Il capture une valeur dynamique depuis l'URL.

C'est un paramètre de requête.

### --feedback--

Les paramètres de requête apparaissent après `?`, pas dans le chemin.

---

Il définit un en-tête personnalisé.

Les paramètres de route vivent dans le chemin d'URL, pas dans les en-têtes.

## --text--

Comment peux-tu utiliser les paramètres de route dans ton application ?

## --answers--

Pour stocker des valeurs statiques dans l'URL.

### --feedback--

Les valeurs statiques ne bénéficient pas des placeholders de paramètres.

---

Pour capturer dynamiquement des parties de l'URL pour le traitement.

---

Pour valider l'entrée utilisateur.

### --feedback--

La validation peut avoir lieu après la capture de la valeur, mais le paramètre lui-même capture des données.

---

Pour définir des en-têtes pour les requêtes.

### --feedback--

Les paramètres de route appartiennent au chemin et ne définissent pas d'en-têtes.
