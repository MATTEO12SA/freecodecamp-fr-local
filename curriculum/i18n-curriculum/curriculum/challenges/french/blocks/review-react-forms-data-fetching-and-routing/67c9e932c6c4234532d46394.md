## Travailler avec les formulaires en React

- **Entrées contrôlées (Controlled Inputs)** : C'est quand tu stockes la valeur du champ de saisie dans l'état et la mets à jour via des événements `onChange`. Cela te donne un contrôle complet sur les données du formulaire et permet une validation instantanée et un rendu conditionnel.

```jsx
import { useState } from "react";

function App() {
  const [name, setName] = useState("");

  const handleChange = (e) => {
    setName(e.target.value);
  };

  const handleSubmit = (e) => {
    e.preventDefault();
    console.log(name);
  };

  return (
    <>
      <form onSubmit={handleSubmit}>
        <label htmlFor="name">Your name</label> <br />
        <input value={name} id="name" onChange={handleChange} type="text" />
        <button type="submit">Submit</button>
      </form>
    </>
  );
}

export default App;
```

- **Entrées non contrôlées (Uncontrolled Inputs)** : Au lieu de gérer les entrées via le Hook `useState`, les entrées non contrôlées en HTML maintiennent leur propre état interne avec l'aide du DOM. Comme le DOM contrôle les valeurs des entrées, tu dois récupérer les valeurs des champs avec une `ref`.

```jsx
import { useRef } from "react";

function App() {
 const nameRef = useRef();

 const handleSubmit = (e) => {
   e.preventDefault();
   console.log(nameRef.current.value);
 };

 return (
   <form onSubmit={handleSubmit}>
     <label htmlFor="name">Your</label>{" "}
     <input type="text" ref={nameRef} id="name" />
     <button type="submit">Submit</button>
   </form>
 );
}

export default App;
```

## Travailler avec le Hook `useActionState`

- **Server Actions** : Ce sont des fonctions qui s'exécutent sur le serveur pour permettre la gestion de formulaires directement sur le serveur sans besoin d'endpoints API. Voici un exemple d'une application Next.js :

```js
"use server";

async function submitForm(formData) {
 const name = formData.get("name");
 return { message: `Hello, ${name}!` };
}
```

La directive `"user server"` marque la fonction comme une server action.

- **Hook `useActionState`** : Ce Hook met à jour l'état selon le résultat d'une soumission de formulaire. Voici la syntaxe de base du Hook `useActionState` :

```js
const [state, action, isPending] = useActionState(actionFunction, initialState, permalink);
```

- `state` est l'état actuel que l'action renvoie.
- `action` est la fonction qui déclenche la server action.
- `isPending` est un booléen qui indique si l'action est en cours d'exécution ou non.
- Le paramètre `actionFunction` est la server action elle-même.
- `initialState` est le paramètre qui représente le point de départ de l'état avant que l'action ne s'exécute.
- `permalink` est une chaîne optionnelle qui contient l'URL unique de la page que le formulaire modifie.

## Récupération de données en React

- **Options pour récupérer des données** : Il y a de nombreuses façons de récupérer des données en React. Tu peux utiliser l'API Fetch native, ou des outils tiers comme Axios ou SWR.
- **Variables d'état couramment utilisées lors de la récupération de données** : Quelle que soit la façon dont tu choisis de récupérer tes données en React, il y a des morceaux d'état que tu devras suivre. Le premier est les données elles-mêmes. Le second indiquera si les données sont encore en cours de récupération. Le troisième est une variable d'état qui capturera toute erreur pouvant survenir pendant le processus de récupération.

```js
const [data, setData] = useState(null);
const [loading, setLoading] = useState(true);
const [error, setError] = useState(null);
```

Comme la récupération de données est un effet de bord, il vaut mieux utiliser la `Fetch API` dans un Hook `useEffect`.

```js
useEffect(() => {
  const fetchData = async () => {
    try {
      const res = await fetch("https://jsonplaceholder.typicode.com/posts");

      if (!res.ok) {
        throw new Error("Network response was not ok");
      }

      const data = await res.json();
      setData(data);
    } catch (err) {
      setError(err);
    } finally {
      setLoading(false);
    }
  };

  fetchData();
}, []);
```

Ensuite tu peux afficher un message de chargement si la récupération n'est pas terminée, un message d'erreur s'il y a eu une erreur, ou les résultats.

```jsx
if (loading) {
  return <p>Loading...</p>;
}

if (error) {
  return <p>{error.message}</p>;
}

return (
  <ul>
    {data.map((post) => (
      <li key={post.id}>{post.title}</li>
    ))}
  </ul>
);
```

Si tu veux utiliser Axios, tu dois l'installer et l'importer :

```bash
npm i axios
```

```js
import axios from "axios";
```

Ensuite tu peux récupérer les données avec `axios.get` :

```jsx
const [data, setData] = useState(null);
const [loading, setLoading] = useState(true);
const [error, setError] = useState(null);

useEffect(() => {
  const fetchData = async () => {
    try {
      const res = await axios.get(
        "https://jsonplaceholder.typicode.com/users"
      );
      setData(res.data);
    } catch (err) {
      setError(err);
    } finally {
      setLoading(false);
    }
  };

  fetchData();
}, []);
```

Pour récupérer des données avec le Hook `useSWR`, tu dois d'abord l'installer et l'importer.

```bash
npm i swr
```

```js
import useSWR from "swr";
```

Voici comment tu peux utiliser le Hook pour récupérer des données :

```jsx
import useSWR from "swr";

const fetcher = (url) => fetch(url).then((res) => res.json());

const FetchTodos = () => {
 const { data, error } = useSWR(
   "https://jsonplaceholder.typicode.com/todos",
   fetcher
 );

 if (!data) {
   return <h2>Loading...</h2>;
 }
 if (error) {
   return <h2>Error: {error.message}</h2>;
 }

 return (
   <>
     <h2>Todos</h2>
     <div>
       {data.map((todo) => (
         <h3 key={todo.id}>{todo.title}</h3>
       ))}
     </div>
   </>
 );
};

export default FetchTodos;
```

## Travailler avec le Hook `useOptimistic`

- **Hook `useOptimistic`** : Ce Hook sert à garder les UI réactives en attendant qu'une action asynchrone se termine en arrière-plan. Il aide à gérer les « mises à jour optimistes » dans l'UI, une stratégie où tu fournis des mises à jour immédiates à l'UI selon le résultat attendu d'une action, comme attendre une réponse serveur.

Voici la syntaxe de base :

```js
const [optimisticState, addOptimistic] = useOptimistic(actualState, updateFunction);
```

- `optimisticState` est l'état temporaire qui se met à jour tout de suite pour une meilleure expérience utilisateur.
- `addOptimistic` est la fonction qui applique la mise à jour optimiste avant que l'état réel ne change.
- `actualState` est la vraie valeur d'état qui vient du résultat d'une action, comme récupérer des données depuis un serveur.
- `updateFunction` est la fonction qui détermine comment l'état optimiste doit se mettre à jour quand elle est appelée.

Voici un exemple d'utilisation du Hook `useOptimistic` dans un composant `TaskList` :

```jsx
"use client";

import { useOptimistic } from "react";

export default function TaskList({ tasks, addTask }) {
  const [optimisticTasks, addOptimisticTask] = useOptimistic(
    tasks,
    (state, newTask) => [...state, { text: newTask, pending: true }]
  );

  async function handleSubmit(e) {
    e.preventDefault();
    const formData = new FormData(e.target);

    addOptimisticTask(formData.get("task"));

    addTask(formData);
    e.target.reset();
  }

  return <>{/* UI */}</>;
}
```

- **`startTransition`** : Ceci sert à rendre une partie de l'UI et à marquer une mise à jour d'état comme une transition non urgente. Cela permet à l'UI de rester réactive pendant des mises à jour coûteuses. Voici la syntaxe de base :

```js
startTransition(action);
```

L'`action` effectue une mise à jour d'état ou déclenche une logique liée à la transition. Cela assure que les mises à jour UI urgentes (comme taper ou cliquer) ne sont pas bloquées.

## Travailler avec le Hook `useMemo`

- **Mémoïsation** : C'est une technique d'optimisation où le résultat d'appels de fonctions coûteux est mis en cache (mémorisé) selon des arguments précis. Quand les mêmes arguments sont fournis à nouveau, le résultat en cache est renvoyé au lieu de recalculer la fonction.
- **Hook `useMemo`** : Ce Hook sert à mémoïser des valeurs calculées. Voici un exemple de mémoïsation du résultat du tri d'un grand tableau. La `expensiveSortFunction` ne s'exécutera que quand `largeArray` change :

```js
const memoizedSortedArray = useMemo(
  () => expensiveSortFunction(largeArray),
  [largeArray]
);
```

- **`React.memo`** : Ceci sert à mémoïser un composant pour l'empêcher de se re-rendre inutilement quand sa prop n'a pas changé.

```jsx
const MemoizedComponent = React.memo(({ prop }) => {
 return (
   <>
     {/* Presentation */}
   </>
 )

```

## Outils de gestion des dépendances

- **Définition d'une dépendance** : En logiciel, une dépendance est le cas où un composant ou module d'une application s'appuie sur un autre pour fonctionner correctement. Les dépendances sont courantes dans les applications logicielles car elles permettent aux développeurs d'utiliser des fonctions ou outils préconstruits créés par d'autres. Les deux dépendances centrales nécessaires pour un projet React seront les paquets `react` et `react-dom` :

```json
"dependencies": {
  "react": "^18.3.1",
  "react-dom": "^18.3.1"
}
```

- **Définition d'un gestionnaire de paquets** : Pour gérer les dépendances logicielles d'un projet, tu devras utiliser un gestionnaire de paquets. Un gestionnaire de paquets est un outil utilisé pour l'installation, les mises à jour et la suppression des dépendances. De nombreux langages populaires comme JavaScript, Python, Ruby et Java utilisent tous des gestionnaires de paquets. Les gestionnaires de paquets populaires pour JavaScript incluent npm, Yarn et pnpm.
- **Fichier `package.json`** : C'est un fichier de configuration clé dans les projets qui contient des métadonnées sur ton projet, y compris son nom, sa version et ses dépendances. Il définit aussi des scripts, des infos de licence, et d'autres réglages qui aident à gérer le projet et ses dépendances.
- **Fichier `package-lock.json`** : Ce fichier verrouille les versions exactes de tous les paquets que ton projet utilise. Quand tu mets à jour un paquet, les nouvelles versions seront aussi mises à jour dans le fichier lock.
- **Dossier `node_modules`** : Ce dossier contient le code réel des dépendances listées dans ton fichier `package.json`, y compris les dépendances directes de ton projet et les dépendances de ces dépendances.
- **Dépendances de développement** : Ce sont des paquets utilisés seulement pour le développement et pas en production. Un exemple serait une bibliothèque de tests comme Jest. Tu installerais Jest comme dépendance de développement parce qu'elle est nécessaire pour tester ton application localement mais pas pour faire tourner l'application en production.

## React Router

- **Introduction** : React Router est une bibliothèque tierce qui te permet d'ajouter du routage à tes applications React. Pour commencer, tu devras installer React Router dans un projet React existant comme ceci :

```bash
npm i react-router
```

Ensuite, dans ton fichier `main.jsx` ou `index.jsx`, tu devras configurer la structure des routes comme ceci :

```jsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import { BrowserRouter, Routes, Route } from "react-router";
import App from "./App.jsx";

import "./index.css";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<App />} />
      </Routes>
    </BrowserRouter>
  </StrictMode>
);
```

Le `path` et l'`element` servent à coupler l'URL et les composants UI. Dans ce cas, on configure une route pour la page d'accueil qui pointe vers le composant `App`.

- **Plusieurs vues et configuration de routes** : Il est courant dans les plus grandes applications d'avoir plusieurs vues et routes configurées comme ceci :

```jsx
<Routes>
  <Route index element={<Home />} />
  <Route path="about" element={<About />} />

  <Route path="products">
    <Route index element={<ProductsHome />} />
    <Route path=":category" element={<Category />} />
    <Route path=":category/:productId" element={<ProductDetail />} />
    <Route path="trending" element={<Trending />} />
  </Route>
</Routes>
```

La prop `index` dans ces exemples représente la route par défaut pour un segment de chemin donné. Donc le composant `Home` sera affiché au chemin racine `/` tandis que le composant `ProductsHome` sera affiché au chemin `/products`.

- **Imbriquer des routes** : Tu peux imbriquer des routes à l'intérieur d'autres routes, ce qui fait que le chemin de la route enfant est ajouté au chemin de la route parent.

```jsx
<Route path="products">
  <Route path="trending" element={<Trending />} />
</Route>
```

Dans l'exemple ci-dessus, le chemin pour les produits tendance sera products/trending.

- **Segments dynamiques** : Un segment dynamique est le cas où une partie quelconque du chemin URL est dynamique.

```jsx
<Route path=":category" element={<Category />} />
```

Dans cet exemple on a un segment dynamique appelé `category`. Quand un utilisateur navigue vers une URL comme products/brass-instruments, alors la vue changera vers le composant `Category` et tu pourras récupérer dynamiquement les données appropriées selon le segment.

- **Hook `useParams`** : Ce Hook sert à accéder aux paramètres dynamiques d'un chemin URL.

```jsx
import { useParams } from "react-router";

export default function Category() {
  let params = useParams();
  {/* Accessing the category param: params.category */}
  {/* rest of code goes here */}
}
```

## Prop Drilling

- **Définition** : Le prop drilling est le processus de passer des props d'un composant parent à des composants enfants profondément imbriqués, même quand certains des composants enfants n'ont pas besoin des props.

## Gestion d'état

- **API Context** : Le context désigne le cas où un composant parent rend de l'information disponible aux composants enfants sans avoir besoin de la passer explicitement via des props. `createContext` sert à créer un objet context qui représente le context que d'autres composants liront. Le `Provider` sert à fournir des valeurs de context aux composants enfants.

```jsx
import { useState, createContext } from "react";

const CounterContext = createContext();

const CounterProvider = ({ children }) => {
  const [count, setCount] = useState(0);

  return (
    <CounterContext.Provider value={{ count, setCount }}>
      {children}
    </CounterContext.Provider>
  );
};

export { CounterContext, CounterProvider };
```

- **Redux** : Redux gère l'état en fournissant un store central et un contrôle strict sur les mises à jour d'état. Il utilise un modèle prévisible avec actions, reducers et middleware. Les actions sont des payloads d'information qui envoient des données de ton application au store Redux, souvent déclenchées par des interactions utilisateur. Les reducers sont des fonctions qui spécifient comment l'état doit changer en réponse à ces actions, en s'assurant que l'état est mis à jour de façon immuable. Le middleware, lui, agit comme un pont entre le dispatch d'action et le reducer, te permettant d'étendre la fonctionnalité de Redux (par ex. logging, gestion d'opérations asynchrones) sans modifier le flux central.

- **Zustand** : Cette solution de gestion d'état est idéale pour les applications de petite à moyenne échelle. Elle fonctionne en utilisant un Hook `useStore` pour accéder à l'état directement dans les composants et pages. Cela te laisse modifier et accéder aux données sans avoir besoin d'actions, reducers ou provider.

## Déboguer les composants React avec les React DevTools

- **React Developer Tools** : C'est une extension de navigateur que tu peux utiliser dans Chrome, Firefox et Edge pour inspecter les composants React et identifier les problèmes de performance. Pour Safari, tu devras installer le paquet npm `react-devtools`. Après avoir installé React DevTools et ouvert une app React dans le navigateur, ouvre les outils de développement du navigateur pour accéder aux deux onglets supplémentaires fournis pour déboguer React – Components et Profiler.
- **Onglet Components** : Cet onglet affiche chaque composant pour toi dans un format d'arborescence. Voici quelques choses que tu peux faire dans cet onglet :
  - voir la hiérarchie des composants de l'app
  - vérifier et modifier props, états et valeurs de context en temps réel
  - vérifier le code source de chaque composant sélectionné
  - journaliser les données du composant dans la console
  - inspecter les éléments DOM du composant
- **Onglet Profiler** : Cet onglet t'aide à analyser les performances des composants. Tu peux enregistrer les performances des composants pour identifier les re-rendus inutiles, voir les durées de commit, et ensuite optimiser les composants lents.

## React Server Components

Cela signifie que ces composants peuvent accéder directement aux ressources côté serveur et réduire dramatiquement la quantité de JavaScript envoyée au navigateur.
