# --description--

En logiciel, une dépendance est le cas où un composant ou module d'une application s'appuie sur un autre pour fonctionner correctement. Les dépendances sont courantes dans les applications logicielles car elles permettent aux développeurs d'utiliser des fonctions ou outils préconstruits créés par d'autres.

Si tu veux construire une application React, tu devras installer les dépendances React. Sans ces dépendances, aucun de tes codes ne fonctionnera correctement et l'application affichera une liste d'erreurs.

Quand tu travailles sur des projets plus complexes, tu auras souvent besoin de t'appuyer sur de nombreuses dépendances. Si un ensemble de dépendances n'est pas bien géré ou défini dans un projet, cela mènera à ce qu'on appelle l'enfer des dépendances.

Pour gérer les dépendances logicielles d'un projet, tu devras utiliser un gestionnaire de paquets. Un gestionnaire de paquets est un outil utilisé pour l'installation, les mises à jour et la suppression des dépendances. De nombreux langages populaires comme JavaScript, Python, Ruby et Java utilisent tous des gestionnaires de paquets.

Dans une leçon précédente, on t'a brièvement présenté un gestionnaire de paquets populaire appelé npm.

Pour créer un nouveau projet React avec Vite et npm, tu peux exécuter la commande suivante :

```sh
npm create vite@latest my-react-app -- --template react
```

Comme tu te souviens des leçons précédentes, cela créera tout le code de base nécessaire pour lancer une nouvelle application React. Avant de pouvoir lancer l'application, tu devras installer les dépendances en exécutant `npm install` ou `npm i` en abrégé.

Tu peux voir toutes les dépendances dans le fichier `package.json` situé à la racine de ton projet.

Le fichier `package.json` est un fichier de configuration clé dans les projets qui contient des métadonnées sur ton projet, y compris son nom, sa version et ses dépendances. Il définit aussi des scripts, des infos de licence, et d'autres réglages qui aident à gérer le projet et ses dépendances.

Quand tu installes des dépendances, un dossier `node_modules` sera ajouté à ton projet.

Le dossier `node_modules` est l'endroit où tous les paquets et bibliothèques requis par ton projet sont stockés. Ce dossier contient le code réel des dépendances listées dans le fichier `package.json`, y compris les dépendances directes de ton projet et les dépendances de ces dépendances.

Les deux dépendances centrales nécessaires pour un projet React seront les paquets `react` et `react-dom` :

```json
"dependencies": {
  "react": "^18.3.1",
  "react-dom": "^18.3.1"
}
```

Le `package.json` listera les versions actuelles que tu utilises pour ces paquets. Si tu dois mettre à jour des paquets localement, tu peux exécuter la commande `npm update`. Ou tu peux mettre à jour tous les paquets globalement en exécutant la commande `npm update -g`.

En plus du fichier `package.json`, tu auras aussi un fichier `package-lock.json`. Ce fichier verrouille les versions exactes de tous les paquets que ton projet utilise. Quand tu mets à jour un paquet, les nouvelles versions seront aussi mises à jour dans le fichier lock.

Un autre aspect important du fichier `package.json` sont les dépendances de développement :

```json
"devDependencies": {
  "@eslint/js": "^9.17.0",
  "@types/react": "^18.3.18",
  "@types/react-dom": "^18.3.5",
  "@vitejs/plugin-react": "^4.3.4",
  "eslint": "^9.17.0",
  "eslint-plugin-react": "^7.37.2",
  "eslint-plugin-react-hooks": "^5.0.0",
  "eslint-plugin-react-refresh": "^0.4.16",
  "globals": "^15.14.0",
  "vite": "^6.0.5"
}
```

Les dépendances de développement (dev dependencies) sont des paquets utilisés seulement pour le développement et pas en production. Un exemple serait une bibliothèque de tests comme Jest. Tu installerais Jest comme dépendance de développement parce que tu ne l'utilises que pour tester ton projet localement, et ce n'est pas nécessaire pour que l'application tourne en production.

Pendant la majeure partie de cette leçon, on s'est concentré sur npm. Mais il y a d'autres gestionnaires de paquets comme yarn et pnpm. Alors quel gestionnaire de paquets devrais-tu utiliser pour ton projet ?

Eh bien, la réponse courte est : ça dépend.

Si tu rejoins un projet existant avec une équipe, alors toutes ces décisions seront déjà prises et tu utiliseras le gestionnaire de paquets existant. Si tu construis un projet from scratch, tu devras rechercher les avantages et inconvénients de chaque gestionnaire et décider lequel conviendra mieux à tes besoins.
