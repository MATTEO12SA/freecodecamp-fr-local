# --interactive--

La programmation fonctionnelle consiste à écrire du code propre, prévisible, et plus facile à tester et à déboguer. Deux concepts clés que nous allons explorer aujourd'hui sont les fonctions pures et l'évitement des effets de bord.

Commençons par les fonctions pures.

Une fonction pure est une fonction qui, pour la même entrée, renvoie toujours la même sortie, et qui ne modifie rien en dehors d'elle-même.

Voici un exemple de fonction pure :

```js
function add(a, b) {
  return a + b;
}
```

Cette fonction est pure car elle renvoie toujours le même résultat pour les mêmes entrées, et elle ne change rien en dehors d'elle-même. Peu importe combien de fois tu appelles `add(2, 3)`, elle renverra toujours `5`, et elle n'affectera aucune autre partie de ton programme.

Maintenant, contrastons cela avec une fonction impure :

```js
let total = 0;
function addToTotal(value) {
  total += value;
  return total;
}
```

Cette fonction est impure car elle modifie une variable en dehors d'elle-même (`total`). Le résultat de `addToTotal(5)` sera différent selon ce qu'était `total` avant l'appel de la fonction. Cette imprévisibilité peut rendre notre code plus difficile à comprendre et à déboguer.

Cela nous amène à notre prochain concept important : les effets de bord.

Un effet de bord est tout changement qui se produit dans l'état du programme lorsqu'une fonction est appelée. Cela peut inclure la modification d'une variable globale, l'écriture dans un fichier, ou un appel API.

Les fonctions pures n'ont pas d'effets de bord, contrairement aux fonctions impures.

Éviter les effets de bord est un principe clé de la programmation fonctionnelle. Lorsque nous minimisons les effets de bord, notre code devient plus prévisible et plus facile à tester.

En écrivant du code, notre objectif principal devrait être de faire en sorte que les fonctions fassent une seule chose et qu'elles le fassent très bien, sans changer d'autres parties de notre programme.

Voici un exemple de fonction avec un effet de bord :

:::interactive_editor

```js
function greet(name) {
  console.log(`Hello, ${name}!`);
}

greet("Alice");
```

:::

Cette fonction a un effet de bord car elle interagit avec le monde extérieur en journalisant dans la console.

En programmation fonctionnelle, on pourrait la réécrire ainsi :

:::interactive_editor

```js
function greet(name) {
  return `Hello, ${name}!`;
}
console.log(greet("Alice"));
```

:::

Maintenant `greet` est une fonction pure qui renvoie simplement une chaîne, et on gère l'effet de bord (journalisation dans la console) séparément.

La programmation fonctionnelle nous encourage à composer nos programmes à l'aide de fonctions pures en décomposant notre code en petits morceaux prévisibles. Ainsi, on peut construire des programmes plus faciles à comprendre, à tester et à maintenir.
