# --interactive--

## Valider des formulaires avec JavaScript

- **Constraint Validation API** : certains éléments HTML, comme les éléments `textarea` et `input`, exposent une Constraint Validation API. Cette API te permet de vérifier que la valeur fournie par l'utilisateur pour cet élément passe toute validation au niveau HTML que tu as écrite, comme une longueur minimale ou une correspondance de motif.
- **Méthode `checkValidity()`** : cette méthode renvoie `true` si l'élément correspond à toute la validation HTML (selon ses attributs), et `false` s'il échoue.

:::interactive_editor

```html
<form>
  <label>
    Email:
    <input
      id="email"
      type="email"
      required
      pattern=".+\.com$"
      placeholder="example@site.com"
    />
  </label>
</form>

<script>
  const input = document.getElementById("email");

  input.addEventListener("input", (e) => {
    if (!e.target.checkValidity()) {
      e.target.setCustomValidity("You must use a .com email.");
    } else {
      e.target.setCustomValidity("");
    }
  });
</script>
```

:::

- **Méthode `reportValidity()`** : cette méthode indique au navigateur que l'`input` est invalide.

:::interactive_editor

```html
<form>
  <label>
    Email:
    <input
      id="email2"
      type="email"
      required
      pattern=".+\.com$"
      placeholder="example@site.com"
    />
  </label>
</form>

<script>
  const input = document.getElementById("email2");

  input.addEventListener("input", (e) => {
    if (!e.target.checkValidity()) {
      e.target.reportValidity();
    }
  });
</script>
```

:::

- **Propriété `validity`** : cette propriété sert à obtenir ou définir l'état de validité des contrôles de formulaire (comme `<input>`, `<select>`, etc.) et fournit des informations sur le fait que la saisie de l'utilisateur respecte les contraintes définies pour cet élément (par ex. champs `required`, contraintes de motif, longueur maximale, etc.).

:::interactive_editor

```html
<input
  id="age"
  type="number"
  min="18"
  placeholder="Enter age (18+)"
/>

<script>
  const input = document.getElementById("age");

  input.addEventListener("input", (e) => {
    console.log(e.target.validity);
  });
</script>
```

:::

- **Propriété `patternMismatch`** : elle vaudra `true` si la valeur ne correspond pas au motif d'expression régulière spécifié.

## Méthode `preventDefault()`

- **Définition** : chaque événement déclenché dans le DOM a une sorte de comportement par défaut. L'événement click sur une case à cocher bascule l'état de cette case, par défaut. Appuyer sur la barre d'espace sur un bouton focalisé active le bouton. La méthode `preventDefault()` sur ces objets `Event` empêche ce comportement de se produire.

:::interactive_editor

```html
<form id="form">
  <input type="text" placeholder="Try to submit" />
  <button type="submit">Submit</button>
</form>

<p id="status"></p>

<script>
  const form = document.getElementById("form");
  const status = document.getElementById("status");

  form.addEventListener("submit", (event) => {
    event.preventDefault();
    status.textContent = "Form submission prevented.";
  });
</script>
```

:::

## Soumettre des formulaires

- **Définition** : il y a trois façons de soumettre un formulaire. La première est lorsque l'utilisateur clique sur un bouton du formulaire dont l'attribut `type` vaut `submit`. La deuxième est lorsque l'utilisateur appuie sur la touche `Enter` sur n'importe quel champ `input` éditable du formulaire. La troisième passe par un appel JavaScript aux méthodes `requestSubmit()` ou `submit()` de l'élément `form`.
- **Attribut `action`** : l'attribut `action` doit contenir soit une URL, soit un chemin relatif pour le domaine actuel. Cette valeur détermine où le formulaire tente d'envoyer les données — si tu ne définis pas d'attribut `action`, le formulaire enverra les données à l'URL de la page actuelle.

```html
<form action="https://freecodecamp.org" method="GET">
  <input
    type="number"
    name="number"
    placeholder="Enter a number"
  />
  <button type="submit">Submit</button>
</form>
```

- **Attribut `method`** : cet attribut accepte une méthode `HTTP` standard, comme `GET` ou `POST`, et utilise cette méthode lors de la requête vers l'URL d'action. Lorsqu'aucune méthode n'est définie, le formulaire utilise par défaut une requête `GET`. Les données du formulaire seront encodées en URL sous forme de paires `name=value` et ajoutées à l'URL d'action comme paramètres de requête.

```html
<form action="/data" method="POST">
  <input
    type="number"
    id="input"
    placeholder="Enter a number"
    name="number"
  />
  <button type="submit">Submit</button>
</form>
```

- **Attribut `enctype`** : l'élément `form` accepte un attribut `enctype`, qui représente le type d'encodage à utiliser pour les données. Cet attribut n'accepte que trois valeurs : `application/x-www-form-urlencoded` (la valeur par défaut, qui envoie les données comme corps de formulaire encodé en URL), `text/plain` (qui envoie les données en texte brut, sous forme de paires `name=value` séparées par des sauts de ligne), ou `multipart/form-data`, destinée spécifiquement aux formulaires avec téléversement de fichier.
