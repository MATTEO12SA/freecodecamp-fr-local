## Qu’est-ce que TypeScript

- **JavaScript** : JavaScript est un langage à typage dynamique. Cela signifie que les variables peuvent recevoir n’importe quelles valeurs à l’exécution. Le défi d’un langage à typage dynamique est que l’absence de sûreté des types peut introduire des erreurs.

Par exemple, même si ta fonction JavaScript attend un tableau, tu peux quand même l’appeler avec un nombre :

```javascript
const getRandomValue = (array) => {
  return array[Math.floor(Math.random() * array.length)];
}

console.log(getRandomValue(10));
```

La sortie de la `console` pour l’exemple ci-dessus sera `undefined`.

- **TypeScript** : TypeScript étend le langage JavaScript pour inclure le typage statique, ce qui aide à attraper les erreurs causées par des incompatibilités de types avant d’exécuter ton code.

Par exemple, tu peux définir un type pour le paramètre `array` comme suit :

```typescript
const getRandomValue = (array: string[]) => {
  return array[Math.floor(Math.random() * array.length)];
}
```

Cette définition de type indique à TypeScript que le paramètre `array` doit être un tableau de chaînes. Ensuite, quand tu appelles `getRandomValue` et que tu lui passes un nombre, tu obtiens une erreur appelée erreur de compilateur.

- **Compilateur** : Tu dois d’abord compiler le code TypeScript en JavaScript classique. Quand tu lances le compilateur, TypeScript évalue ton code et lève une erreur pour tout problème où les types ne correspondent pas.

## Types de données en TypeScript

- **Types de données primitifs en TypeScript** : Pour les types de données primitifs `string`, `null`, `undefined`, `number`, `boolean` et `bigint`, TypeScript offre des mots-clés de type correspondants.

```typescript
let str: string = "Naomi";
let num: number = 42;
let bool: boolean = true;
let nope: null = null;
let nada: undefined = undefined;
```

- **Tableau** : Tu peux définir un tableau d’un type spécifique avec deux syntaxes différentes.

```typescript
const arrOne: string[] = ["Naomi"];
const arrTwo: Array<string> = ["Camperchan"];
```

- **Objets** : Tu peux définir la structure exacte d’un objet.

```typescript
const obj: { a: string, b: number } = { a: "Naomi", b: 42 };
```

Si tu veux un objet avec n’importe quelles clés, mais où toutes les valeurs doivent être des chaînes, il y a deux façons de le définir :

```typescript
const objOne: Record<string, string> = {};
const objTwo: { [key: string]: string } = {};
```

- **Autres types utiles en TypeScript** :
  - **`any`** : `any` indique qu’une valeur peut avoir n’importe quel type. Il dit au compilateur d’arrêter de se soucier du type de cette variable.
  - **`unknown`** : `unknown` indique à TypeScript que tu _te soucies_ du type de la valeur, mais que tu ne sais pas réellement ce qu’il est. `unknown` est généralement préféré à `any`.
  - **`void`** : C’est un type spécial que tu n’utiliseras typiquement que pour définir des fonctions. Les fonctions qui n’ont pas de valeur de retour utilisent un type de retour `void`.
  - **`never`** : Il représente un type qui n’existera jamais.

- **Mot-clé `type`** : Ce mot-clé est comme `const`, mais au lieu de déclarer une variable, tu peux déclarer un type.

Il est utile pour déclarer des types personnalisés comme des types union ou des types qui n’incluent que des valeurs spécifiques :

```typescript
type stringOrNumber = string | number;
type bot = "camperchan" | "camperbot" | "naomi";
```

- **`interface`** : Les interfaces sont comme des classes pour les types. Elles peuvent implémenter ou étendre d’autres interfaces, sont spécifiquement des types d’objets, et sont généralement préférées sauf si tu as besoin d’une fonctionnalité spécifique offerte par une déclaration `type`.

```typescript
interface wowie {
  zowie: boolean;
  method: () => void;
}
```

- **Définir le type de retour** : Tu peux aussi définir le _type de retour_ de la fonction.

L’exemple ci-dessous définit la valeur de retour comme une chaîne. Si tu essaies de renvoyer autre chose, TypeScript donnera une erreur de compilateur.

```typescript
const getRandomValue = (array: string[]): string => {
  return array[Math.floor(Math.random() * array.length)];
}
```

## Generics

- **Définir un type générique** : Tu peux définir un type générique et y faire référence dans ta fonction. On peut le voir comme un paramètre spécial que tu fournis à une fonction pour contrôler le comportement de sa définition de type.

Voici un exemple de définition d’un type générique pour une fonction :

```typescript
const getRandomValue = <T>(array: T[]): T => {
  return array[Math.floor(Math.random() * array.length)];
}
const val = getRandomValue([1, 2, 4])
```

La syntaxe `<T>` indique à TypeScript que tu définis un type générique `T` pour la fonction. `T` est un nom courant pour les types génériques, mais tu peux utiliser n’importe quel nom.

Ensuite, tu dis à TypeScript que le paramètre `array` est un tableau de valeurs correspondant au type générique, et que la valeur renvoyée est un seul élément de ce même type.

- **Spécifier un argument de type dans un appel de fonction** : Tu peux passer un argument de type à un appel de fonction avec des chevrons entre le nom de la fonction et ses paramètres.

Voici un exemple de passage d’un argument de type à un appel de fonction :

```typescript
const email = document.querySelector<HTMLInputElement>("#email");
console.log(email.value);
```

Cela indique à TypeScript que l’élément que tu t’attends à trouver sera un élément input.

## Type Narrowing

- **Narrowing par truthiness** : Dans l’exemple ci-dessous, tu obtiens une erreur de compilateur en essayant d’accéder à la propriété `value` de `email` car `email` _pourrait_ être `null`.

```typescript
const email = document.querySelector<HTMLInputElement>("#email");
console.log(email.value);
```

Tu peux utiliser une instruction conditionnelle pour confirmer que `email` est _truthy_ avant d’accéder à la propriété :

```typescript
const email = document.querySelector<HTMLInputElement>("#email");
if (email) {
  console.log(email.value);
}
```

Les vérifications de truthiness peuvent aussi fonctionner dans le sens inverse :

```typescript
const email = document.querySelector<HTMLInputElement>("#email");
if (!email) {
  throw new ReferenceError("Could not find email element!")
}
console.log(email.value);
```

Lever une erreur met fin à l’exécution logique de ce code, ce qui signifie que lorsqu’on atteint l’appel `console.log()`, TypeScript sait que `email` _ne peut pas_ être `null`.

- **Chaînage optionnel** : Le chaînage optionnel `?.` est aussi une forme de type narrowing, selon le même principe : l’accès à la propriété ne peut pas se produire si la valeur `email` est `null`.

```typescript
const email = document.querySelector<HTMLInputElement>("#email");
console.log(email?.value);
```

- **Opérateur `typeof`** : Tu peux utiliser une condition pour vérifier le type de la variable avec l’opérateur `typeof`.

```typescript
const myVal = Math.random() > 0.5 ? 222 : "222";
if (typeof myVal === "number") {
  console.log(myVal / 10);
}
```

- **Mot-clé `instanceof`** : Si l’objet vient d’une classe, tu peux utiliser le mot-clé `instanceof` pour restreindre le type.

```typescript
const email = document.querySelector("#email");

if (email instanceof HTMLInputElement) {
    console.log(email.value);
}
```

- **Casting** : Quand TypeScript ne peut pas déterminer automatiquement le type d’une valeur, comme le résultat de la méthode `request.json()` dans l’exemple ci-dessous, tu obtiendras une erreur de compilateur. Une façon de résoudre cela est de caster le type, mais cela affaiblit la capacité de TypeScript à attraper d’éventuelles erreurs.

```typescript
interface User {
    name: string;
    age: number;
}

const printAge = (user: User) =>
  console.log(`${user.name} is ${user.age} years old!`)

const request = await fetch("url")
const myUser = await request.json() as User;
printAge(myUser);
```

- **Type Guard** : Au lieu de caster le type, tu peux écrire un type guard :

```typescript
interface User {
    name: string;
    age: number;
}

const isValidUser = (user: unknown): user is User => {
  return !!user &&
    typeof user === "object" &&
    "name" in user &&
    "age" in user;
}
```

La syntaxe `user is User` indique que ta fonction renvoie une valeur booléenne, qui lorsqu’elle est true signifie que la valeur `user` satisfait l’interface `User`.

## Fichier `tsconfig`

- **`tsconfig.json`** : Les réglages du compilateur TypeScript se trouvent dans un fichier `tsconfig.json` à la racine de ton projet.

```json
{
  "compilerOptions": {
    "rootDir": "./src",
    "outDir": "./prod",
    "lib": ["ES2023"],
    "target": "ES2023",
    "module": "ES2022",
    "moduleResolution": "Node",
    "esModuleInterop": true,
    "skipLibCheck": true,
    "strict": true
  },
  "exclude": ["test/"]
}
```

Voici les descriptions des options de compilateur utilisées dans l’exemple ci-dessus :

- **`compilerOptions`** : La propriété `compilerOptions` est l’endroit où tu contrôles le comportement du compilateur TypeScript.
- **`rootDir` et `outDir`** : Les propriétés `rootDir` et `outDir` indiquent à TypeScript quel répertoire contient tes fichiers source, et quel répertoire doit contenir le code JavaScript transpilé.
- **`lib`** : La propriété `lib` détermine quelles définitions de types le compilateur utilise, et te permet d’inclure le support de versions ES spécifiques, du DOM, et plus encore.
- **`module` et `moduleResolution`** : Les propriétés `module` et `moduleResolution` travaillent de concert pour gérer la façon dont ton package utilise les modules — CommonJS ou ECMAScript.
- **`esModuleInterop`** : L’option `esModuleInterop` permet une meilleure interopérabilité entre CommonJS et les modules ES en créant automatiquement des objets namespace pour les imports.
- **`skipLibCheck`** : L’option `skipLibCheck` saute la validation des fichiers `.d.ts` qui ne sont pas référencés par des imports dans ton code.
- **`strict`** : Le flag `strict` active plusieurs vérifications, comme s’assurer de la bonne gestion des types nullable et avertir quand TypeScript retombe sur `any`.
- **`exclude`** : La propriété de premier niveau `exclude` dit au compilateur d’ignorer ces fichiers TypeScript pendant la compilation.
