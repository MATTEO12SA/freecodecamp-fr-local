# --description--

Dans les leçons précédentes, tu as appris à travailler avec les imports et exports en JavaScript. Dans cette leçon, nous allons voir comment importer et exporter des composants dans React.

Un export rend un composant disponible pour d'autres fichiers. Un import permet à un fichier d'utiliser un composant qui a été exporté ailleurs. Dans les projets React, c'est ainsi que les composants sont réutilisés et combinés pour construire des interfaces utilisateur.

Dans cette leçon, tu apprendras comment exporter des composants React avec des exports par défaut et des exports nommés, et comment les importer là où ils sont nécessaires.

Dans cet exemple, nous avons un composant `Cat` qui appartient à un fichier appelé `Cat.jsx`. Pour l'extension de fichier, nous utilisons l'extension `.jsx` car ce fichier travaille surtout avec JSX.

Ce composant `Cat` renvoie un markup JSX avec un titre et une image pour un chat appelé Mr. Whiskers :

```jsx
function Cat() {
  return (
    <div className="card">
      <h2>Mr. Whiskers</h2>
      <img
        src="https://cdn.freecodecamp.org/curriculum/cat-photo-app/running-cats.jpg"
        alt="Tuxedo cats running on dirt ground."
      />
    </div>
  );
}
```

Si nous voulons utiliser notre composant `Cat` dans un autre fichier, nous devons d'abord l'exporter comme ceci :

```jsx
function Cat() {
  return (
    <div className="card">
      <h2>Mr. Whiskers</h2>
      <img
        src="https://cdn.freecodecamp.org/curriculum/cat-photo-app/running-cats.jpg"
        alt="Tuxedo cats running on dirt ground."
      />
    </div>
  );
}

export default Cat;
```

Nous utilisons le mot-clé `default` car ce sera l'export par défaut du module. Tu peux aussi choisir d'exporter le composant sur la même ligne que la définition du composant comme ceci :

```jsx
export default function Cat() {
  return (
    <div className="card">
      <h2>Mr. Whiskers</h2>
      <img
        src="https://cdn.freecodecamp.org/curriculum/cat-photo-app/running-cats.jpg"
        alt="Tuxedo cats running on dirt ground."
      />
    </div>
  );
}
```

Tu peux choisir d'importer des composants enfants dans d'autres fichiers de composants parents, ou de les importer dans le fichier du composant racine. Pour cet exemple, nous importerons le composant `Cat` dans le fichier du composant racine.

Chaque projet React aura un composant de plus haut niveau, typiquement appelé `App.jsx` :

```jsx
export default function App() {
  return (
    // return component here
  );
}
```

Ce fichier se trouve généralement dans le répertoire `src` de ton projet. Tu en apprendras plus sur les dispositions courantes de projets dans une prochaine leçon.

Pour utiliser le composant `Cat` à l'intérieur du composant racine `App`, tu auras besoin de l'importer comme ceci :

```jsx
import Cat from "./Cat";

export default function App() {
  return (
    // return component here
  );
}
```

Maintenant, tu peux renvoyer le composant `Cat` à l'intérieur du composant `App` comme ceci :

```jsx
import Cat from "./Cat";

export default function App() {
  return (
    <Cat />
  );
}
```

Cette approche fonctionne bien quand un fichier est responsable d'exporter un seul composant principal, ce qui garde la syntaxe d'import simple et facile à lire. Souviens-toi qu'un fichier ne peut avoir qu'un seul export par défaut, ce qui le rend idéal pour un fichier qui contient principalement un seul composant.


Maintenant que tu sais comment utiliser les exports par défaut, regardons les exports nommés. Les exports nommés permettent à un fichier de partager plusieurs composants ou fonctions. Contrairement aux exports par défaut, ceux-ci doivent être importés avec le nom exact sous lequel ils ont été exportés (sauf si tu les renommes avec le terme `as`).

C'est utile quand un fichier sert de bibliothèque de composants. Par exemple, voici un fichier contenant deux composants, Cat et Dog :

```jsx
// Animals.jsx
export function Cat() {
  return <h2>Mr. Whiskers</h2>;
}

export function Dog() {
  return <h2>Fido</h2>;
}
```

Nous utilisons le mot-clé export individuellement sur chaque composant. Pour les utiliser dans un autre fichier, nous les importons avec des accolades :


```jsx
import { Cat, Dog } from "./Animals";

export default function App() {
  return (
    <div>
      <Cat />
      <Dog />
    </div>
  );
}
```

La syntaxe `{ Cat, Dog }` dit à JavaScript d'importer les exports nommés spécifiques depuis le fichier `Animals.jsx`. Les noms à l'intérieur des accolades doivent correspondre exactement aux noms exportés. Si tu as besoin d'éviter des conflits de noms, ou si tu préfères un nom différent dans le fichier actuel, tu peux renommer un composant pendant l'import avec le mot-clé as.

```jsx
import { Cat as Kitty } from "./Animals";

export default function App() {
  return <Kitty />;
}
```

Enfin, un fichier peut avoir un export par défaut et plusieurs exports nommés.

```jsx
// Animals.jsx
export default function Cat() {
  return <h2>Mr. Whiskers</h2>;
}

export function Dog() {
  return <h2>Fido</h2>;
}
```

Quand tu importes des exports mixtes, l'export par défaut vient en premier (sans accolades), suivi des exports nommés (entre accolades) :

```jsx
// App.jsx
import Cat, { Dog } from "./Animals";

export default function App() {
  return (
    <div>
      <Cat />
      <Dog />
    </div>
  );
}
```

Dans cet exemple, `Cat` est l'export par défaut, donc il n'utilise pas d'accolades. `Dog` est un export nommé, donc il en a besoin.

En comprenant comment fonctionnent les exports par défaut et nommés, tu peux organiser des composants React sur plusieurs fichiers et les réutiliser là où c'est nécessaire. En construisant de plus grandes applications, choisir le bon style d'export aidera à garder ton code clair et maintenable, et facilitera le travail avec des composants créés par d'autres.
