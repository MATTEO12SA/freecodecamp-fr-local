# --interactive--

Les éléments de contrôle de formulaire sémantiques comme `input`, `select`, `textarea`, `button` et `fieldset` ont des états intégrés transmis aux technologies d'assistance.

Par exemple, tu peux utiliser l'attribut `disabled` pour désactiver un bouton, ou l'attribut `checked` pour indiquer qu'une case à cocher est cochée.

Mais si tu crées un élément de contrôle personnalisé, tu dois utiliser des attributs ARIA pour transmettre l'état du contrôle aux technologies d'assistance.

Dans cette leçon, nous verrons quelques états ARIA courants que tu peux utiliser sur des éléments de contrôle personnalisés.

Le premier état ARIA dont nous parlerons est `aria-selected`. Cet état indique qu'un élément est sélectionné. Tu peux l'utiliser sur des contrôles personnalisés comme une interface à onglets, une listbox ou une grille.

Voici un exemple d'utilisation de `aria-selected` sur un contrôle d'onglet personnalisé :

:::interactive_editor

```html
<link rel="stylesheet" href="styles.css">
<div role="tablist">
  <button role="tab" aria-selected="true">Tab 1</button>
  <button role="tab" aria-selected="false">Tab 2</button>
  <button role="tab" aria-selected="false">Tab 3</button>
</div>
<script src="index.js"></script>
```

```css
[role="tablist"] {
  display: flex;
  border-bottom: 2px solid #ddd;
  gap: 0.25rem;
  font-family: system-ui, sans-serif;
}

[role="tab"] {
  appearance: none;
  border: none;
  background: none;
  padding: 0.5rem 1rem;
  cursor: pointer;
  font-size: 1rem;
  color: #444;
  border-radius: 4px 4px 0 0;
  transition: background-color 0.2s, color 0.2s;
}

[role="tab"]:hover {
  background-color: #f3f3f3;
}

[role="tab"][aria-selected="true"] {
  background-color: #fff;
  color: #0078d4;
  border: 2px solid #0078d4;
  border-bottom: 2px solid #fff;
  font-weight: 600;
  position: relative;
  z-index: 1;
}

[role="tab"]:focus {
  outline: 2px solid #0078d4;
  outline-offset: 2px;
}

```

```js
document.addEventListener("click", (event) => {
  const clickedTab = event.target.closest('[role="tab"]');
  if (!clickedTab) return;

  const tablist = clickedTab.closest('[role="tablist"]');
  const tabs = tablist.querySelectorAll('[role="tab"]');

  tabs.forEach((tab) => {
    const isSelected = tab === clickedTab;
    tab.setAttribute("aria-selected", isSelected);
    tab.tabIndex = isSelected ? 0 : -1;
  });
});

document.addEventListener("keydown", (event) => {
  const activeTab = document.activeElement;
  if (activeTab.getAttribute("role") !== "tab") return;

  const tablist = activeTab.closest('[role="tablist"]');
  const tabs = Array.from(tablist.querySelectorAll('[role="tab"]'));
  const index = tabs.indexOf(activeTab);

  let newIndex = index;
  if (event.key === "ArrowRight") newIndex = (index + 1) % tabs.length;
  if (event.key === "ArrowLeft") newIndex = (index - 1 + tabs.length) % tabs.length;

  if (newIndex !== index) {
    tabs[newIndex].focus();
    tabs[newIndex].click();
  }
});

```

:::

Les onglets servent à afficher plusieurs panneaux de contenu dans un espace limité. L'état `aria-selected` indique quel onglet est actuellement sélectionné.

Quand l'utilisateur sélectionne un onglet, l'état `aria-selected` de l'onglet sélectionné passe à `true`, et l'état `aria-selected` des autres onglets passe à `false`.

Un autre état ARIA courant est `aria-disabled`. Cet état indique qu'un élément est désactivé uniquement pour les personnes qui utilisent des technologies d'assistance, comme les lecteurs d'écran. Important : `aria-disabled` ne désactive pas réellement l'élément. C'est à toi, le développeur, de le faire paraître et se comporter comme un élément désactivé. Cet attribut s'utilise aussi souvent sur des éléments HTML natifs à la place de `disabled`. Le choix dépend du contexte d'utilisation du bouton.

Voici un exemple d'utilisation de `aria-disabled` sur un bouton d'édition personnalisé :

:::interactive_editor

```html
<link rel="stylesheet" href="styles.css">
<div role="button" tabindex="-1" aria-disabled="true">Edit</div>
```

```css
[role="button"] {
  display: inline-block;
  background-color: #0078d4;
  color: #fff;
  padding: 0.5rem 1rem;
  border-radius: 6px;
  font-family: system-ui, sans-serif;
  font-size: 1rem;
  text-align: center;
  cursor: pointer;
  user-select: none;
  transition: background-color 0.2s, transform 0.1s, opacity 0.2s;
}

[role="button"]:not([aria-disabled="true"]):hover {
  background-color: #005fa3;
}

[role="button"]:not([aria-disabled="true"]):focus {
  outline: 2px solid #005fa3;
  outline-offset: 2px;
}

[role="button"]:not([aria-disabled="true"]):active {
  transform: scale(0.97);
}

[role="button"][aria-disabled="true"] {
  opacity: 0.5;
  pointer-events: none;
  cursor: not-allowed;
  background-color: #b0b0b0;
  color: #f2f2f2;
}
```

:::

L'attribut `aria-disabled` indique aux utilisateurs de lecteurs d'écran que le bouton d'édition est désactivé et qu'on ne peut pas interagir avec. Encore une fois, il ne désactive pas réellement le bouton. Avec `aria-disabled`, tu devras appliquer du style et du JavaScript pour que le contrôle ressemble et se comporte comme un bouton désactivé.

Dans la plupart des cas, tu utiliseras probablement l'élément bouton natif, mais il y a des cas où tu pourrais avoir besoin d'un contrôle personnalisé. Il est donc essentiel de savoir transmettre l'état du contrôle aux technologies d'assistance.

Le prochain état ARIA dont nous parlerons est `aria-haspopup`. Cet état indique qu'un élément interactif déclenchera un élément popup une fois activé. Tu ne peux utiliser `aria-haspopup` que si le popup a l'un des rôles suivants : `menu`, `listbox`, `tree`, `grid` ou `dialog`. La valeur de `aria-haspopup` doit être l'un de ces rôles ou `true`, qui correspond par défaut au rôle `menu`.

Voici un exemple de menu d'éditeur de fichiers qui utilise `aria-haspopup` :

:::interactive_editor

```html
<link rel="stylesheet" href="styles.css">
<button id="menubutton" aria-haspopup="menu" aria-controls="filemenu" aria-expanded="false">File</button>
<ul id="filemenu" role="menu" aria-labelledby="menubutton" hidden>
  <li role="menuitem" tabindex="-1">Open</li>
  <li role="menuitem" tabindex="-1">New</li>
  <li role="menuitem" tabindex="-1">Save</li>
  <li role="menuitem" tabindex="-1">Delete</li>
</ul>
```

```css
#menubutton {
  background-color: #0078d4;
  color: #fff;
  border: none;
  padding: 8px 14px;
  border-radius: 4px;
  cursor: pointer;
  font-size: 14px;
  position: relative;
}

#menubutton:hover,
#menubutton:focus {
  background-color: #005ea2;
  outline: none;
}

#filemenu {
  list-style: none;
  padding: 4px 0;
  margin: 4px 0 0;
  border: 1px solid #ccc;
  border-radius: 4px;
  background-color: #fff;
  width: 160px;
  position: absolute;
  z-index: 1000;
  box-shadow: 0 4px 6px rgba(0,0,0,0.1);
}

#filemenu[hidden] {
  display: none;
}

#filemenu [role="menuitem"] {
  display: block;
  padding: 8px 12px;
  font-size: 14px;
  color: #333;
  cursor: pointer;
}

#filemenu [role="menuitem"]:hover,
#filemenu [role="menuitem"]:focus {
  background-color: #e5f1fb;
  outline: none;
}

#filemenu [role="menuitem"]:focus-visible {
  box-shadow: inset 0 0 0 2px #0078d4;
}

```

:::

L'état `aria-haspopup` indique que le bouton de menu `File` ouvrira un menu popup une fois activé. Les utilisateurs de lecteurs d'écran peuvent entendre cette information supplémentaire quand ils naviguent jusqu'au bouton.

Tu devras utiliser JavaScript pour afficher et masquer le menu popup, et pour implémenter un support clavier correct pour interagir avec le menu. Note aussi que le rôle ARIA `menu` désigne un type de menu très spécifique. Il s'agit en général d'une liste d'actions que l'utilisateur peut invoquer, comme un menu d'application de bureau. Cela n'inclut pas les usages plus courants de ce qu'on appelle souvent des « menus », comme les menus de navigation. En pratique, la plupart des « menus » que tu crées sur le web ne seront pas des menus ARIA, et tu n'utiliseras pas `aria-haspopup` avec eux.

Le prochain état ARIA dont nous parlerons est `aria-required`. L'attribut `aria-required` indique qu'un champ doit être rempli avant l'envoi du formulaire.

Voici un exemple d'utilisation de l'attribut `aria-required` pour un contrôle de formulaire personnalisé.

:::interactive_editor

```html
<link rel="stylesheet" href="styles.css">
<div id="name-label">Full Name*</div>
<div role="textbox" contenteditable aria-labelledby="name-label" aria-required="true" id="name"></div>
```

```css
#name-label {
  font-family: system-ui, sans-serif;
  font-size: 0.95rem;
  font-weight: 600;
  margin-bottom: 0.25rem;
  color: #333;
}

[role="textbox"] {
  display: block;
  width: 100%;
  min-height: 2rem;
  padding: 0.5rem 0.75rem;
  border: 1.5px solid #ccc;
  border-radius: 4px;
  font-family: system-ui, sans-serif;
  font-size: 1rem;
  color: #222;
  background-color: #fff;
  line-height: 1.4;
  transition: border-color 0.2s, box-shadow 0.2s;
}

[role="textbox"]:hover {
  border-color: #999;
}

[role="textbox"]:focus {
  outline: none;
  border-color: #0078d4;
  box-shadow: 0 0 0 3px rgba(0, 120, 212, 0.25);
}

[role="textbox"]:empty::before {
  content: attr(data-placeholder);
  color: #aaa;
  pointer-events: none;
}

[role="textbox"][aria-required="true"] {
  border-left: 3px solid #e81123;
  padding-left: calc(0.75rem - 3px);
}
```

:::

Nous devons utiliser l'attribut `contenteditable` pour que les utilisateurs puissent saisir leur entrée. Nous utilisons aussi `aria-required` défini à `true` pour indiquer que ce contrôle de formulaire personnalisé est obligatoire.

Pour que le contrôle de formulaire ressemble à un contrôle normal, tu devras ajouter du CSS. Tu devras aussi ajouter du JavaScript pour empêcher l'envoi du formulaire sans contenu.

Si le libellé contient déjà le mot `required`, tu dois omettre l'attribut `aria-required`. Ainsi, les lecteurs d'écran n'annoncent le mot « requis » qu'une seule fois.

Dans la plupart des cas, tu utiliseras probablement les éléments natifs `label` et `form` avec l'attribut `required`. Mais si tu dois créer un contrôle de formulaire personnalisé, il est important d'ajouter `aria-required` quand c'est nécessaire.

De plus, `aria-required` peut aussi s'utiliser sur des entrées de formulaire natives, comme les éléments `input`, `textarea` et `select`. On le préfère souvent à l'attribut required natif, car celui-ci peut poser des problèmes d'utilisabilité et d'accessibilité, surtout avec la gestion d'erreurs par défaut du navigateur. Au final, tu devras tester pour déterminer quel attribut convient le mieux à ta situation.

Le dernier état ARIA dont nous parlerons est `aria-checked`. Cet attribut indique si un élément est dans l'état coché. On l'utilise surtout pour créer des cases à cocher, boutons radio, interrupteurs et listboxes personnalisés.

Voici un exemple d'utilisation de `aria-checked` sur un contrôle de case à cocher personnalisé :

:::interactive_editor

```html
<link rel="stylesheet" href="styles.css">
<div role="checkbox" aria-checked="true" tabindex="0">Checkbox</div>
```

```css
[role="checkbox"] {
  display: inline-flex;
  align-items: center;
  gap: 0.5rem;
  font-family: system-ui, sans-serif;
  font-size: 1rem;
  cursor: pointer;
  user-select: none;
  color: #222;
}

[role="checkbox"]::before {
  content: "";
  display: inline-block;
  width: 1rem;
  height: 1rem;
  border: 2px solid #666;
  border-radius: 4px;
  background-color: #fff;
  transition: all 0.2s ease;
  box-sizing: border-box;
}

[role="checkbox"]:hover::before {
  border-color: #0078d4;
}

[role="checkbox"]:focus::before {
  outline: 2px solid #0078d4;
  outline-offset: 2px;
}

[role="checkbox"][aria-checked="true"]::before {
  background-color: #0078d4;
  border-color: #0078d4;
  background-image: url("data:image/svg+xml;utf8,<svg xmlns='http://www.w3.org/2000/svg' width='14' height='14' viewBox='0 0 14 14'><path fill='white' d='M5.2 10.4L2 7.2l1.1-1.1 2.1 2.1L10.9 2.5 12 3.6z'/></svg>");
  background-repeat: no-repeat;
  background-position: center;
}

[role="checkbox"][aria-disabled="true"] {
  opacity: 0.5;
  pointer-events: none;
  cursor: not-allowed;
}

```

:::

Les éléments de case à cocher natifs ont un état `checked` intégré transmis aux technologies d'assistance. Mais si tu crées une case à cocher personnalisée, tu devras utiliser `aria-checked` pour indiquer son état.

Quand l'utilisateur interagit avec la case à cocher personnalisée, tu devras utiliser l'état `aria-checked` pour refléter le nouvel état. Quand la case est cochée, `aria-checked` vaut `true`. Quand elle est décochée, il vaut `false`.

Les éléments natifs ont en général un meilleur support et des fonctionnalités d'accessibilité intégrées.

Cependant, si tu dois créer des contrôles personnalisés, utiliser des attributs ARIA est essentiel pour transmettre efficacement leur état aux technologies d'assistance.

Comme toujours, teste ton travail pour t'assurer que les attributs ARIA sont appliqués correctement et que le contrôle personnalisé fonctionne de façon accessible et conviviale.
