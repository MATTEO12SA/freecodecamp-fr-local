# --interactive--

L'attribut `aria-controls` crée une relation programmatique entre un élément qui contrôle la présence d'un autre élément sur la page, et l'élément qu'il contrôle. Cette relation aide les utilisateurs de lecteurs d'écran à mieux comprendre comment le contrôle fonctionne. Les usages courants incluent un ensemble d'onglets qui contrôlent la visibilité de différentes sections de contenu, ou un bouton qui bascule la visibilité d'un menu.

Regardons un exemple pour voir comment cela fonctionne. Dans cet exemple d'interface à onglets, nous avons un élément `div` avec un ensemble de trois boutons :

:::interactive_editor

```html
<link rel="stylesheet" href="styles.css">
<div role="tablist">
  <button role="tab" id="tab1" aria-controls="section1" aria-selected="true">
    Tab 1
  </button>
  <button role="tab" id="tab2" aria-controls="section2" aria-selected="false">
    Tab 2
  </button>
  <button role="tab" id="tab3" aria-controls="section3" aria-selected="false">
    Tab 3
  </button>
</div>
```

```css

[role="tab"] {

  background: #fff;
  border-color: #ccc;
  border-bottom: 2px solid #fff;

```

:::

Le `div` utilise `role="tablist"` pour indiquer qu'il sert de conteneur pour un groupe d'onglets.

Chaque bouton représente un onglet et a un attribut `role` défini à `tab`. Dans la plupart des interfaces à onglets, le premier panneau est visible par défaut, donc le premier bouton d'onglet a `aria-selected` défini à `true` pour indiquer que sa section de contenu associée est actuellement visible. L'attribut `aria-controls` associe chaque bouton à la section de contenu qu'il contrôle.

Voici les trois sections de contenu qui correspondent aux onglets :

```js
const tabs = document.querySelectorAll('[role="tab"]');
const tabList = document.querySelector('[role="tablist"]');

tabs.forEach(tab => {
  tab.addEventListener('click', () => {
    activateTab(tab);
  });

  tab.addEventListener('keydown', (e) => {
    const key = e.key;
    const currentIndex = Array.from(tabs).indexOf(tab);
    let newIndex = null;

    if (key === 'ArrowRight') {
      newIndex = (currentIndex + 1) % tabs.length;
    } else if (key === 'ArrowLeft') {
      newIndex = (currentIndex - 1 + tabs.length) % tabs.length;
    } else if (key === 'Home') {
      newIndex = 0;
    } else if (key === 'End') {
      newIndex = tabs.length - 1;
    }

    if (newIndex !== null) {
      tabs[newIndex].focus();
      activateTab(tabs[newIndex]);
    }
  });
});

function activateTab(tab) {
  const tabPanels = document.querySelectorAll('[role="tabpanel"]');

  tabs.forEach(t => {
    t.setAttribute('aria-selected', 'false');
    t.setAttribute('tabindex', '-1');
  });

  tabPanels.forEach(panel => panel.hidden = true);

  tab.setAttribute('aria-selected', 'true');
  tab.removeAttribute('tabindex');

  const panelId = tab.getAttribute('aria-controls');
  const panel = document.getElementById(panelId);
  panel.hidden = false;
  tab.focus();
}

```

:::

Chaque section de contenu a un attribut `role` défini à `tabpanel` et un attribut `aria-labelledby` qui pointe vers l'onglet correspondant pour donner un nom accessible au panneau. L'attribut `hidden` masque les sections qui ne sont pas actuellement sélectionnées. Chaque ID de section correspond à la valeur de `aria-controls` sur le bouton correspondant. L'ID `section1` correspond à l'attribut `aria-controls` du premier bouton, `section2` correspond à l'attribut `aria-controls` du deuxième bouton, et `section3` correspond à l'attribut `aria-controls` du troisième bouton. C'est ainsi que l'association entre les onglets et leurs sections de contenu est établie.

Pour basculer entre les différentes sections, tu devras utiliser JavaScript pour mettre à jour l'attribut `hidden` sur la section et l'attribut `aria-selected` sur le bouton selon la section actuellement visible. Une seule section peut être visible à la fois : elle ne doit pas avoir l'attribut `hidden`, et `aria-selected` doit valoir `true` sur son bouton. Les sections masquées restantes doivent toutes avoir `hidden`, et `aria-selected` doit valoir `false` sur leurs boutons.

Les onglets sont un cas d'usage courant pour `aria-controls`, mais on peut l'utiliser dans d'autres scénarios où un élément contrôle la visibilité ou le comportement d'un autre. D'autres exemples incluent les accordéons, les menus déroulants et les modales.

La prochaine fois que tu conçois une interface qui implique de contrôler la visibilité d'éléments, considère d'utiliser l'attribut `aria-controls` pour établir la relation entre l'élément de contrôle et l'élément contrôlé.
