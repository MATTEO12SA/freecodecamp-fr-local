# --interactive--

L'attribut `aria-expanded` sert à l'accessibilité pour indiquer si un contrôle est développé ou réduit. On l'utilise avec des widgets repliables comme les menus, les accordéons et d'autres widgets de dévoilement qui contrôlent la visibilité du contenu. L'attribut `aria-expanded` vaut `true` si le contrôle est développé, ou `false` s'il est réduit.

Les informations fournies par `aria-expanded` permettent aux personnes qui utilisent un lecteur d'écran de comprendre l'état actuel du contrôle (développé ou réduit).

L'attribut `aria-expanded` s'applique à l'élément interactif qui bascule la visibilité d'un widget repliable. Par exemple, si un bouton ouvre un menu dépliable, `aria-expanded` est placé sur le bouton.

Quand le menu est développé, l'attribut `aria-expanded` doit valoir `true`, comme dans cet exemple :

```html
<button aria-expanded="true">Menu</button>
```

Quand le menu est réduit, il doit valoir `false` à la place.

```html
<button aria-expanded="false">Menu</button>
```

Tu dois toujours avoir l'attribut `aria-expanded` défini à `true` ou `false` sur l'élément de contrôle. Par exemple, si un bouton bascule la visibilité d'un menu, la valeur par défaut de `aria-expanded` doit reposer sur la visibilité par défaut du menu.

Si le menu est développé par défaut, `aria-expanded` doit d'abord valoir `true`. S'il est réduit par défaut, `aria-expanded` doit d'abord valoir `false`.

La valeur de `aria-expanded` doit être mise à jour dynamiquement avec JavaScript quand l'utilisateur interagit avec l'élément.

De plus, les propriétés `aria-controls` et `aria-owns` peuvent s'utiliser avec `aria-expanded` pour créer un lien programmatique entre l'élément de contrôle et l'élément qu'il contrôle.

Commençons par `aria-controls`. Avec `aria-expanded`, l'attribut `aria-controls` indique l'élément contrôlé. Par exemple, un bouton peut développer ou réduire une liste qui sert de menu. La valeur de `aria-controls` sera l'`id` de l'élément contrôlé (la liste du menu dans cet exemple).

:::interactive_editor

```html
<link rel="stylesheet" href="styles.css">

<button aria-expanded="false" aria-controls="menu1">Menu</button>
<ul id="menu1" hidden>
  <li>...</li>
  <li>...</li>
</ul>

<script src="index.js"></script>
```

```css
button {

}

button:hover {
  background-color: #005ea2;
}

ul {
  list-style: none;
  padding: 0;
  margin: 8px 0 0;

  padding: 8px;

```

```js
const button = document.querySelector('button');
const menu = document.getElementById(button.getAttribute('aria-controls'));

button.addEventListener('click', () => {
  const expanded = button.getAttribute('aria-expanded') === 'true';
  button.setAttribute('aria-expanded', String(!expanded));
  menu.hidden = expanded;
});

```

Remarque que la liste suit immédiatement le bouton de contrôle. Pour ce type de contrôles dépliables, le mieux est que le contenu développé suive tout de suite l'élément qui le contrôle dans le DOM. Ainsi, les utilisateurs de lecteurs d'écran n'ont pas à chercher le contenu développé, et les utilisateurs clavier naviguent plus facilement parmi les contrôles interactifs de ce contenu.

S'il n'est pas possible de placer le contenu développé juste après l'élément de contrôle, l'attribut `aria-owns` te permet de le déplacer virtuellement après le contrôle dans l'arbre d'accessibilité. Les technologies d'assistance comme les lecteurs d'écran peuvent alors faire comme si ce contenu était placé directement après le contrôle dans le DOM.

:::interactive_editor

```html
<link rel="stylesheet" href="styles.css">

<button aria-owns="menu1" aria-expanded="true">Menu</button>
<main>
  <!-- an entire page worth of content --->
</main>
<ul id="menu1">
  <li>...</li>
  <li>...</li>
</ul>

<script src="index.js"></script>
```

```css
button {
  background-color: #0078d4;
  color: white;
  padding: 8px 12px;
  border: none;
  border-radius: 4px;
  cursor: pointer;
  margin-bottom: 10px;
}

button:hover {
  background-color: #005ea2;
}

ul {
  list-style: none;
  padding: 0;
  margin: 8px 0;
  border: 1px solid #ccc;
  border-radius: 4px;
  width: 150px;
  background: #fff;
  position: absolute;
  z-index: 10;
}

li {
  padding: 8px;
  cursor: pointer;
}

li:hover {
  background-color: #f2f2f2;
}

```

```js
const button = document.querySelector('button');
const menu = document.getElementById(button.getAttribute('aria-owns'));

button.addEventListener('click', () => {
  const expanded = button.getAttribute('aria-expanded') === 'true';
  button.setAttribute('aria-expanded', String(!expanded));
  menu.hidden = expanded;
});

// Close the menu if user clicks outside
document.addEventListener('click', (e) => {
  if (!button.contains(e.target) && !menu.contains(e.target)) {
    button.setAttribute('aria-expanded', 'false');
    menu.hidden = true;
  }
});

```

:::

Utiliser `aria-owns` a des inconvénients. Cela crée une verbosité inutile pour les utilisateurs de lecteurs d'écran, car la plupart liront automatiquement tout le contenu de l'élément développé dès qu'il s'ouvre. Cela ne change pas non plus l'ordre de tabulation : les utilisateurs clavier peuvent devoir tabuler à travers tous les autres contrôles interactifs de la page avant d'atteindre le contenu développé, sauf si tu gères l'ordre de tabulation avec JavaScript.

Idéalement, le contenu dépliable doit être placé après l'élément de contrôle, et `aria-owns` ne doit servir qu'en dernier recours quand ce n'est pas possible. S'il faut l'utiliser, tu devras tester soigneusement avec un large éventail de lecteurs d'écran et de navigateurs pour garantir que ton implémentation est accessible pour tout le monde.

Et un rappel : quand tu utilises `aria-controls` ou `aria-owns`, la valeur de `aria-expanded` doit continuer à être mise à jour quand le contrôle est développé et réduit.

L'attribut `aria-expanded` indique si un contrôle est développé ou réduit. Cette information est essentielle pour les utilisateurs de lecteurs d'écran : elle les aide à comprendre l'état actuel des éléments repliables comme les menus, les accordéons et d'autres widgets de dévoilement similaires.

En utilisant `aria-expanded` correctement, tu peux créer une expérience utilisateur intuitive pour tout le monde.
