# --description--

Apprenons les codes de réponse HTTP courants.

Les codes de réponse HTTP sont des codes numériques à trois chiffres que les serveurs web utilisent pour communiquer avec les clients afin de leur faire savoir ce qui s'est passé avec leurs requêtes.

Ils fournissent des informations sur le fait que la requête a été traitée avec succès ou s'il y a eu une erreur lors du traitement de la requête.

Nous couvrirons certains des plus courants dans cette leçon.

## Codes de succès

Commençons par les **codes de succès**. Ces codes commencent par le chiffre 2.

Le code **200 OK** est le code de réponse HTTP le plus courant. Il signifie que la requête a réussi et que le serveur a renvoyé les informations demandées par le client.

Le code **201 Created** est renvoyé par le serveur quand le client demande la création d'une ressource et que le processus est terminé avec succès. Par exemple, si un nouveau compte utilisateur est créé avec succès, le serveur renvoie ce code de réponse au client.

Le code **204 No Content** est renvoyé quand la requête a été traitée avec succès mais que le serveur n'a aucun contenu à renvoyer. Cela peut être utilisé pour des processus qui suppriment ou mettent à jour une ressource dans une base de données mais n'ont aucune donnée à renvoyer.

## **Codes de redirection**

Parlons maintenant des **codes de redirection**.

Ces codes sont renvoyés par le serveur quand la ressource demandée par le client a été déplacée vers un autre emplacement ou quand le client doit prendre des mesures supplémentaires pour compléter la requête.

Ces codes commencent par le chiffre 3.

Le code **301 Moved Permanently** est renvoyé quand la ressource demandée par le client a été déplacée de façon permanente vers un autre emplacement. Dans ce cas, le serveur devrait inclure une URL vers le nouvel emplacement dans la réponse et une fois que le client reçoit la réponse, l'utilisateur devrait être redirigé vers cette URL.

Le code **302 Found** indique que la ressource demandée par le client a été temporairement déplacée vers un autre emplacement. Le serveur devrait fournir la nouvelle URL dans la réponse et le client devrait rediriger l'utilisateur vers cette URL. Cependant, l'URL originale pourrait être disponible à l'avenir puisque le changement est temporaire. C'est la principale différence entre les codes de réponse 301 et 302.

Le code **304 Not Modified** est renvoyé par le serveur pour indiquer au client que la ressource demandée n'a pas été modifiée depuis la dernière fois qu'elle a été demandée. Le serveur envoie ce code pour éviter d'envoyer des données déjà envoyées si le contenu n'a pas changé. C'est une technique d'optimisation des performances.

## Codes d'erreur client

Nous allons maintenant plonger dans les **codes d'erreur**.

Les erreurs peuvent être causées par le client et par le serveur. Nous parlerons d'abord des codes d'erreur client.

Les codes d'erreur client sont renvoyés quand la requête n'a pas pu être complétée à cause d'un problème généré par le client.

Ces codes d'erreur commencent par le chiffre 4.

Le code **400 Bad Request** est renvoyé quand le serveur n'a pas pu comprendre la requête envoyée par le client. Cela peut se produire quand le client envoie une requête avec une syntaxe incorrecte, des paramètres invalides, ou des données invalides.

Le code **401 Unauthorized** est lié à l'authentification. Il indique que le client doit fournir certains identifiants d'authentification pour accéder à la ressource demandée. Ces identifiants peuvent inclure un nom d'utilisateur et un mot de passe.

Le code **403 Forbidden** est renvoyé quand le client n'est pas autorisé à accéder à la ressource demandée. La différence entre 401 et 403 est que dans 403, le client n'a pas les permissions nécessaires pour la ressource particulière qu'il demande, même s'il a des identifiants d'authentification valides.

Le code **404 Not Found** est renvoyé quand la ressource n'a pas pu être trouvée sur le serveur. Peut-être qu'elle a été supprimée ou qu'il y a une faute de frappe dans l'URL qui empêche le serveur de trouver la ressource. Le serveur peut aussi rencontrer un problème temporaire qui résulte en ce code d'erreur.

## Codes d'erreur serveur

Ensuite, nous avons les **codes d'erreur serveur**. Ces codes sont renvoyés par le serveur quand la requête n'a pas pu être traitée à cause d'un problème du côté du serveur.

Le code d'erreur **500 Internal Server Error** indique qu'il y a eu une erreur inattendue sur le serveur. Cette erreur peut être causée par un large éventail de problèmes, allant des problèmes de configuration aux problèmes temporaires.

Le code d'erreur **502 Bad Gateway** est renvoyé quand le serveur essayait de communiquer avec un autre serveur mais a reçu une réponse invalide de ce serveur. Il y a un large éventail de causes pour ce type d'erreur.

Le code d'erreur **503 Service Unavailable** indique que le serveur ne pourra pas traiter la requête temporairement, donc le client devrait réessayer plus tard. Les causes courantes de cette erreur incluent des tâches de maintenance et un volume élevé de requêtes que le serveur ne peut actuellement pas gérer.

Les codes de réponse HTTP sont essentiels pour comprendre la communication entre les clients et les serveurs web. En comprenant ces codes, tu peux dépanner et déboguer tes applications web.
