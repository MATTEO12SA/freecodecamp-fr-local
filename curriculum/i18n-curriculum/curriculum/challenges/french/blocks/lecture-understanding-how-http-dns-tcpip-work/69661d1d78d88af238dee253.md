# --description--

Le monde numérique tel que nous le connaissons aujourd'hui repose sur la notion que les appareils peuvent communiquer entre eux, en envoyant et recevant des données selon les besoins.

Mais as-tu déjà réfléchi à la façon dont ce processus fonctionne en coulisses ?

Quand tu navigues sur Internet, tu demandes et envoies constamment des données à travers le réseau. Cela est possible grâce à un processus détaillé basé sur des règles et procédures standard qui s'assurent que l'information est envoyée et reçue correctement par les appareils appropriés.

Cet ensemble de règles et procédures est connu sous le nom de **protocole**.

Les protocoles permettent essentiellement à deux ou plusieurs appareils de communiquer entre eux en s'assurant qu'ils suivent tous certaines normes, comme le format des données qui seront échangées.

Les protocoles s'assurent que tous les appareils impliqués dans le processus d'échange de données pourront se comprendre. Au figuré, ils sauront tous « parler la même langue ».

À leur cœur, TCP/IP sont les protocoles qui rendent Internet possible.

**TCP/IP** est une suite de protocoles de communication qui déterminent comment les données sont empaquetées, envoyées, routées et reçues à travers un réseau. Elle s'assure que l'information est transportée de façon fiable.

Plus précisément, le **IP**, où IP signifie **Internet Protocol** (protocole Internet), est un protocole qui s'assure que les données vont de la source à la bonne destination dans le réseau.

Pourquoi est-ce important ? Souviens-toi qu'Internet est un réseau mondial d'appareils interconnectés. Pour que ton appareil envoie une requête, il doit d'abord savoir où envoyer ces données. C'est le but principal des adresses IP, le fondement du protocole Internet (IP). Elles identifient de façon unique les appareils sur le réseau, pour que l'appareil source sache où envoyer les données.

À lui seul, le protocole Internet est sans connexion, ce qui signifie que chaque unité de données (appelée un « paquet ») est envoyée indépendamment vers sa destination à travers le réseau, sans établir préalablement une connexion ni s'assurer qu'elle sera livrée correctement ou dans le bon ordre. Si elles atteignent leur destination, la source n'en est pas notifiée du tout.

C'est là que des protocoles comme TCP deviennent vraiment importants.

Le protocole **TCP**, connu sous le nom de **Transmission Control Protocol** (protocole de contrôle de transmission), découpe les données en petits segments. Ces unités de données fondamentales sont numérotées et réassemblées à leur arrivée à destination à l'aide d'algorithmes spécifiques qui détectent si les données sont complètes et correctes. Ces algorithmes vérifient aussi les erreurs et les paquets perdus, pour pouvoir demander à la source de les renvoyer si nécessaire, en s'assurant que l'information est reçue correctement.

Ensemble, le Transmission Control Protocol et l'Internet Protocol établissent les règles et normes nécessaires pour garantir que les données sont transmises de façon fiable à travers Internet.

En plus de TCP/IP, il existe un autre protocole très important pour Internet moderne : HTTP.

HTTP fonctionne au niveau application.

**HTTP** signifie **HyperText Transfer Protocol** (protocole de transfert hypertexte). Il définit les règles et normes pour la communication entre le client (comme ton navigateur) et le serveur.

Quand tu essaies d'accéder à un site web dans ton navigateur, le navigateur envoie une requête HTTP au serveur demandant cette ressource spécifique et ses assets associés. Le serveur reçoit la requête HTTP, exécute sa logique, et renvoie une réponse HTTP au client avec le contenu demandé ou des informations indiquant pourquoi la requête n'a pas réussi.

Les requêtes HTTP et les réponses HTTP ont des structures très similaires, incluant :

* Une ligne de requête (la ligne de début)

* Des en-têtes

* Un corps (optionnel)

## **Requêtes HTTP**

La **ligne de requête** d'une requête HTTP est divisée en trois parties principales :

* Une méthode, qui décrit l'action demandée. Par exemple, `GET` pour récupérer des données et `POST` pour soumettre des données. D'autres méthodes courantes incluent `PUT`, `PATCH`, `DELETE` et `HEAD`.

* Un chemin ou URI, qui décrit la ressource spécifique que le client demande.

* La version du protocole HTTP utilisée pour le processus de communication. Par exemple, `HTTP/1.1`.

Voici un exemple avec la méthode `GET` sur le chemin racine `/` et la version HTTP 1.1 :

`GET / HTTP/1.1`

L'**en-tête** contient des paires clé-valeur avec des informations sur la requête.

Par exemple : `Content-Type: application/json`.

Sous l'en-tête, il y a une ligne vide pour indiquer que les métadonnées (informations supplémentaires sur la requête) sont complètes.

Et enfin, le **corps**. Il est optionnel. Il est envoyé quand le client doit envoyer des informations au serveur, comme lors de la soumission de nouvelles données avec la méthode `POST`.

Voici un exemple de requête HTTP :

```md
GET / HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)
Accept: text/html
Connection: keep-alive
```

## **Réponses HTTP**

Elles ont une structure très similaire :

* Une ligne de statut

* En-tête

* Corps

D'abord, la **ligne de statut** contient des informations sur le résultat de la requête. Tu y trouveras généralement ceci :

* La version de HTTP utilisée pour le processus de communication. Par exemple, `HTTP/1.1`.

* Le code de statut, qui indique le résultat de la requête.

* Une phrase de raison, une brève description lisible par un humain du code de statut. Cela aide à comprendre ce qui s'est passé.

Les codes de statut courants incluent :

* `200 OK`

* `201 CREATED`

* `400 BAD REQUEST`

* `404 NOT FOUND`

* `403 FORBIDDEN`

* `500 INTERNAL SERVER ERROR`

Il existe de nombreux codes de statut. Ils sont catégorisés par leur premier chiffre de gauche à droite.

* `1xx` pour les réponses informatives.

* `2xx` pour les réponses réussies.

* `3xx` pour les messages de redirection.

* `4xx` pour les réponses d'erreur client.

* `5xx` pour les réponses d'erreur serveur.

Sous la ligne de statut d'une réponse HTTP, on trouve l'**en-tête** avec des métadonnées sur la réponse. Par exemple, `Content-Type: text/html`. Cela peut aussi inclure la longueur du contenu, la date, l'emplacement, et des informations supplémentaires que le client peut trouver utiles.

Et enfin, on trouve le **corps** de la réponse HTTP, qui contient les données que le client demandait ou une explication de ce qui s'est passé si la requête n'a pas réussi. Il est optionnel, mais il est inclus dans la plupart des réponses.

Voici un exemple de réponse HTTP :

```md
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 105
Connection: keep-alive

<!DOCTYPE html>
<html>
<head><title>Home</title></head>
<body><h1>Welcome!</h1></body>
</html>
```

Maintenant que tu connais HTTP, tu pourrais être curieux d'en savoir plus sur HTTPS.

Tu peux penser à HTTPS comme une version « sécurisée » de HTTP, où les données envoyées entre le navigateur et le serveur sont chiffrées à des fins de sécurité. La plupart du trafic web moderne utilise HTTPS.

Des protocoles comme TCP/IP et HTTP ont fait du World Wide Web et d'Internet dans son ensemble l'outil essentiel sur lequel la plupart d'entre nous comptons chaque jour. Grâce à eux, les appareils peuvent communiquer correctement sur un réseau et échanger des données partout dans le monde.
