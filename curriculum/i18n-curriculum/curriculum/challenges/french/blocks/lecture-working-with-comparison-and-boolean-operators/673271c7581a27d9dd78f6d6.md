# --interactive--

Dans une leçon précédente, on t'a présenté pour la première fois le concept de booléens, mais dans cette leçon, nous allons approfondir le fonctionnement des booléens ainsi que celui des opérateurs d'égalité et d'inégalité.

Les booléens sont un type de données qui n'a que les valeurs `true` et `false`. Ils sont utiles car ils te permettent de faire quelque chose en fonction de certaines conditions. Les booléens sont essentiels quand tu veux évaluer si quelque chose doit se produire ou non, comme décider si une personne peut accéder à une certaine fonctionnalité de ton application. Voici un exemple d'affectation de la valeur `true` à une variable appelée `isOldEnoughToDrive` :

:::interactive_editor

```js
let isOldEnoughToDrive = true;

console.log(isOldEnoughToDrive); // true
```

:::

Tu peux utiliser cette variable à l'intérieur d'une condition comme ceci :

:::interactive_editor

```js
let isOldEnoughToDrive = true;

if (isOldEnoughToDrive) {
 console.log("You're old enough to drive"); // You're old enough to drive
} else {
 console.log("Sorry, you are not old enough to drive");
}
```

:::

Une condition t'aide à prendre des décisions dans ton code en fonction d'une condition. Cet exemple utilise ce qu'on appelle une instruction `if/else`.

Si `isOldEnoughToDrive` vaut `true`, alors la phrase `You're old enough to drive` sera affichée dans la console. Sinon, si `isOldEnoughToDrive` vaut `false`, alors la phrase `Sorry, you are not old enough to drive` sera affichée dans la console. Comme la variable `isOldEnoughToDrive` est définie à `true`, c'est la première phrase qui sera affichée dans la console. Tu en apprendras davantage sur les instructions `if/else` dans une prochaine leçon.

Pour comparer deux valeurs, tu peux utiliser soit l'opérateur d'égalité, soit l'opérateur d'égalité stricte. Le résultat de la comparaison sera un booléen, soit `true`, soit `false`. Voici un exemple d'utilisation de l'opérateur d'égalité pour comparer une chaîne et un nombre. L'opérateur d'égalité est représenté par un double signe égal (`==`).

:::interactive_editor

```js
console.log(5 == "5"); // true
```

:::

Dans cet exemple, JavaScript convertit la chaîne `"5"` en le nombre `5`, puis vérifie s'ils sont égaux. Comme les deux valeurs sont désormais identiques, le résultat est true. L'opérateur d'égalité utilise la coercition de type avant de vérifier si chaque valeur est égale.

Cela diffère de l'opérateur d'égalité stricte, qui n'effectue pas de coercition de type. L'opérateur d'égalité stricte vérifie si les types sont identiques et si les valeurs sont identiques. Voici un exemple utilisant l'opérateur d'égalité stricte pour comparer un nombre et une chaîne. Cet opérateur est représenté par un triple signe égal (`===`).

:::interactive_editor

```js
console.log(5 === '5'); // false
```

:::

La comparaison suivante sera `false`, car un type de données chaîne n'est pas identique à un type de données nombre. Si tu as besoin de vérifier si quelque chose n'est pas égal à une autre valeur, tu peux utiliser les opérateurs d'inégalité ou d'inégalité stricte. Voici un exemple d'utilisation de l'opérateur d'inégalité (`!=`) pour comparer un nombre avec une chaîne.

:::interactive_editor

```js
console.log(5 != "5"); // false
```

:::

Dans cet exemple, le résultat serait `false` car l'opérateur d'inégalité convertit d'abord la valeur chaîne en nombre, puis compare les valeurs. Comme les valeurs seraient identiques, il renverra `false`. Si tu essayais d'utiliser l'opérateur d'inégalité stricte, tu obtiendrais un résultat différent. L'opérateur d'inégalité stricte est représenté par un point d'exclamation suivi de deux signes égal (`!==`).

:::interactive_editor

```js
console.log(5 !== "5"); // true
```

:::

Le résultat serait `true` car l'opérateur d'inégalité stricte n'effectue aucune coercition de type. Comme le nombre `5` n'est pas égal à la chaîne `"5"`, le résultat est `true`.

Il est considéré comme une bonne pratique d'utiliser les opérateurs d'égalité et d'inégalité strictes chaque fois que possible, car ils n'effectuent pas de coercition de type. La plupart du temps dans les projets professionnels, tu verras des bases de code qui préfèrent généralement ces deux opérateurs aux opérateurs d'égalité et d'inégalité.
