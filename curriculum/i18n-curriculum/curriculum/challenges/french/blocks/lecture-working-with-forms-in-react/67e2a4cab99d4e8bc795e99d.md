# --description--

React 19 est arrivé avec deux nouvelles fonctionnalités notables appelées server components et server actions.

À partir de cette version, les server components sont devenus la valeur par défaut dans des frameworks comme Next.js qui les prennent déjà en charge.

Les server actions, elles, sont des fonctions qui s'exécutent sur le serveur pour permettre la gestion des formulaires directement sur le serveur sans besoin de points d'API.

Une server action ressemble à ceci :

```js
"use server";

async function submitForm(formData) {
  const name = formData.get("name");
  return { message: `Hello, ${name}!` };
}
```

Cette server action extrait un champ `name` d'un formulaire et renvoie une chaîne de salutation avec ce nom.

Pour simplifier la gestion du state des server actions et supprimer le besoin de JavaScript côté client pour des formulaires simples, l'équipe React a introduit le hook `useActionState` en version 19.

Regardons de plus près ce hook et voyons comment il fonctionne.

La documentation React décrit le hook `useActionState` comme un hook qui « te permet de mettre à jour le state selon le résultat d'une action de formulaire. »

Mais cela ne signifie pas que tu ne peux utiliser le hook `useActionState` qu'avec des formulaires. Tu peux aussi l'utiliser pour gérer des clics de bouton et d'autres événements, tant que tu as une action en place.

Et garde à l'esprit que, comme `useActionState` est un hook, tu ne peux pas l'utiliser dans un server component.

Voici la syntaxe de base du hook `useActionState` :

```js
const [state, action, isPending] = useActionState(actionFunction, initialState, permalink);
```

- `state` est le state actuel que l'action renvoie.

- `action` est la fonction qui déclenche la server action.

- `isPending` est un booléen qui indique si l'action est en cours d'exécution ou non.

- Le paramètre `actionFunction` est la server action elle-même.

- `initialState` est le paramètre qui représente le point de départ du state avant que l'action ne s'exécute.

- `permalink` est une chaîne optionnelle qui contient l'URL unique de la page que le formulaire modifie.

Pour utiliser le hook `useActionState`, assure-toi d'avoir d'abord une action en place. Utilisons l'action de l'exemple précédent pour cela, avec une petite variante :

```js
"use server";

export async function submitForm(_, formData) {
  const name = formData.get("name");

  const hour = new Date().getHours();
  let greeting;

  if (hour < 12) {
    greeting = "Good morning";
  } else if (hour < 18) {
    greeting = "Good afternoon";
  } else {
    greeting = "Good evening";
  }

  return { message: `${greeting}, ${name}` };
}
```

Dans ton composant, tu dois ensuite importer le hook `useActionState` et l'appeler au niveau supérieur du corps du composant (avant le return) comme les autres hooks. Tu dois aussi importer l'action :

```jsx
"use client";

// Import the useActionState hook
import { useActionState } from "react";

// Import the submitForm action
import { submitForm } from "./actions/submitForm";

const Greeter = () => {

 // Initialize the hook
 const [state, submit, isPending] = useActionState(submitForm, {
   message: "",
 });

  return (
    <div className="flex flex-col items-center justify-center min-h-screen bg-gray-100 p-6">
      {/* Rest of component */}
    </div>
  );
};

export default Greeter;
```

Voici à quoi ressemble le code complet avec un peu de style :

```jsx
"use client";

import { useActionState } from "react";
import { submitForm } from "./actions/submitForm";

const Greeter = () => {
  const [state, submit, isPending] = useActionState(submitForm, {
    message: "",
  });

  return (
    <div className="flex flex-col items-center justify-center min-h-screen bg-gray-100 p-6">
      <form
        action={submit}
        className="bg-white p-6 rounded-2xl shadow-md w-full max-w-md"
      >
        <h2 className="text-2xl text-center font-semibold text-gray-700 mb-4">
          Greet Someone
        </h2>

        <input
          type="text"
          name="name"
          placeholder="Enter your name"
          required
          className="w-full p-3 border border-gray-300 rounded-lg focus:outline-none focus:ring-2 focus:ring-green-400"
        />

        <button
          type="submit"
          disabled={isPending}
          className="w-full mt-4 p-3 bg-green-500 text-white font-semibold rounded-lg hover:bg-green-600 disabled:bg-gray-400 transition-all"
        >
          {isPending ? "Greeting..." : "Greet"}
        </button>

        {state.message && (
          <p className="mt-4 text-green-600 text-center font-medium">
            {state.message}
          </p>
        )}
      </form>
    </div>
  );
};

export default Greeter;
```

Dans le navigateur, tu verrais ton bouton de formulaire passer de `Greet` à `Greeting...` pendant que l'action `isPending` - et la salutation afficherait `Good morning, {name}`, `Good afternoon, {name}`, ou `Good evening, {name}`, selon l'heure de soumission du formulaire.

Tu te souviens que nous avons mentionné que tu peux aussi utiliser le hook `useActionState` hors d'un formulaire ?

Dans cet exemple, nous récupérerons cinq utilisateurs depuis JSONPlaceholder avec un clic de bouton :

```js
"use server";

export async function getUsers() {
  const res = await fetch(
    "https://jsonplaceholder.typicode.com/users?_start=0&_limit=5/"
  );
  return await res.json();
}
```

Voici l'UI stylisée :

```jsx
"use client";

import { useActionState } from "react";
import { getUsers } from "./actions/getUsers";

export default function FetchUsers() {
  const [users, fetchAction, isPending] = useActionState(getUsers, []);

  return (
    <div className="p-6 max-w-lg mx-auto">
      <button
        onClick={fetchAction}
        disabled={isPending}
        className="px-4 py-2 cursor-pointer bg-green-500 text-white rounded-lg hover:bg-green-600 disabled:bg-gray-400 font-bold"
      >
        {isPending ? "Fetching Users..." : "Fetch Users"}
      </button>

      <ul className="mt-4 space-y-2">
        {users.map((user) => (
          <li key={user.id} className="p-3 bg-gray-100 rounded-lg">
            <p className="font-semibold">{user.name}</p>
            <p className="text-sm text-gray-600">{user.email}</p>
          </li>
        ))}
      </ul>
    </div>
  );
}
```

Dans le navigateur, tu verrais que le texte du bouton n'est jamais mis à jour en `Fetching Users...` après le clic.

Cela arrive car React traite la récupération de données et le rendu comme une priorité plus haute que le state `isPending`, ce qui bloque `isPending` dans le processus et lance une erreur.

Pour corriger ce problème, tu dois envelopper l'action dans `startTransition` :

```jsx
"use client";

// import startTransition from React
import { useActionState, startTransition } from "react";
import { getUsers } from "./actions/getUsers";

export default function FetchUsers() {
  const [users, fetchAction, isPending] = useActionState(getUsers, []);

  return (
    <div className="p-6 max-w-lg mx-auto">
      <button
        {/* wrap fetchAction in startTransition */}
        onClick={() => startTransition(() => fetchAction())}
        disabled={isPending}
        className="px-4 py-2 bg-green-500 font-bold cursor-pointer text-white rounded-lg hover:bg-green-600 disabled:bg-gray-400"
      >
        {isPending ? 'Fetching Users...' : 'Fetch Users'}
      </button>

      <ul className="mt-4 space-y-2">
        {users.map((user) => (
          <li key={user.id} className="p-3 bg-gray-100 rounded-lg">
            <p className="font-semibold">{user.name}</p>
            <p className="text-sm text-gray-600">{user.email}</p>
          </li>
        ))}
      </ul>
    </div>
  );
}
```

Si tu te demandes ce qu'est `startTransition`, c'est une fonction qui dit à React qu'une mise à jour de state est de faible priorité et peut être interrompue. Cela garde l'UI réactive pendant les mises à jour asynchrones comme les server actions.

## --text--

Quel est le but du hook `useActionState` en React ?

## --answers--

Il gère le state selon le résultat d'une action, y compris les soumissions de formulaire, les clics de bouton et d'autres mises à jour liées aux événements.

---

Il ne met à jour le state que quand un formulaire est soumis et ne prend pas en charge d'autres types d'actions comme les clics de bouton ou les gestionnaires d'événements personnalisés.

### --feedback--

Il fonctionne avec les actions, pas seulement les formulaires.

---

Il gère le state global sur plusieurs composants, ce qui en fait un remplacement des bibliothèques de state comme Redux ou Zustand.

Il remplace entièrement le hook `useState` en fournissant une façon intégrée de gérer le state local et global sans dépendances supplémentaires.

Pourquoi ne peux-tu pas utiliser le hook `useActionState` dans un server component ?

## --answers--

Parce que les server components ne prennent pas en charge la gestion du state, ce qui rend `useActionState` incompatible.

---

Parce que `useActionState` nécessite une connexion à une base de données, qui n'est disponible que dans les client components.
