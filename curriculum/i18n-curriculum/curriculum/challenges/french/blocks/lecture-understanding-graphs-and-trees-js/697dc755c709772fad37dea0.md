# --description--

Une **file de priorité** est un type abstrait de données (TAD) qui fonctionne de façon similaire à une file ou une pile, mais avec une différence clé.

Comme tu le sais peut-être déjà, les files standard suivent une approche FIFO (premier entré, premier sorti), où le premier élément ajouté à la file est le premier à en être retiré.

Les piles suivent une approche LIFO (dernier entré, premier sorti), où le dernier élément ajouté à la pile est le premier à en être retiré.

Les files et les piles ne considèrent que l'ordre d'insertion des éléments.

Cependant, les files de priorité prennent en compte la « priorité » des éléments. La priorité sert à déterminer quel élément doit être retiré ensuite.

Habituellement, l'élément avec la plus haute priorité est retiré en premier, mais certaines implémentations peuvent aussi choisir de retirer d'abord l'élément avec la plus basse priorité. Cela dépendra des exigences de ton programme.

Les files de priorité sont très utiles pour des applications pratiques comme trouver le plus court chemin entre deux emplacements, planifier des tâches dans les systèmes d'exploitation, simuler le trafic, compresser des données, et gérer des réseaux.

En pratique, les files de priorité sont couramment implémentées avec une structure de données de type tas.

Un **tas** est une structure de données arborescente avec une propriété très spécifique appelée la **propriété de tas**. Cette propriété détermine la relation entre chaque nœud et ses enfants, selon le type de tas.

Il y a deux types principaux de tas :

* Max-heap

* Min-heap

Dans un **max-heap**, la valeur de chaque nœud est supérieure ou égale à la valeur de ses enfants.

Dans cet exemple, tu peux voir une structure d'arbre avec les nœuds 8, 7, 5, 2 et 1. Note que le nœud 7 est supérieur au nœud 2 et au nœud 1, suivant la propriété de tas. C'est aussi vrai pour tous les autres nœuds.

<img src="https://cdn.freecodecamp.org/curriculum/lecture-transcripts/how-do-priority-queues-and-heaps-work-1.png" alt="Une structure d'arbre max-heap montrant des nœuds avec la valeur 8 à la racine, 7 et 5 comme enfants de 8, et 2 et 1 comme enfants de 7, illustrant que chaque nœud parent est supérieur à ses enfants.">

En revanche, dans un **min-heap**, la valeur de chaque nœud est inférieure ou égale à la valeur de ses enfants.

Dans cet exemple, nous avons des nœuds avec les valeurs 4, 7, 9, 12 et 15. Par exemple, le nœud 7 est inférieur au nœud 12 et au nœud 15, suivant la propriété de tas. C'est aussi vrai pour tous les autres nœuds.

<img src="https://cdn.freecodecamp.org/curriculum/lecture-transcripts/how-do-priority-queues-and-heaps-work-2.png" alt="Une structure d'arbre min-heap montrant des nœuds avec la valeur 4 à la racine, 7 et 9 comme enfants de 4, et 12 et 15 comme enfants de 7, illustrant que chaque nœud parent est inférieur à ses enfants.">

La propriété de tas est essentielle car elle garantit que l'élément maximum (ou minimum) (selon le type de tas) reste toujours au sommet, ce qui rend son retrait très facile.

En pratique, les tas sont typiquement implémentés comme des tableaux pour accéder efficacement aux nœuds parents et enfants.

Utiliser des tableaux simplifie la logique pour accéder à ces valeurs ou « nœuds » parce qu'en coulisses, si le tas maintient la structure d'un arbre binaire complet, l'implémentation en tableau ne nécessite que de simples opérations mathématiques basées sur leurs indices pour trouver où les éléments sont situés en mémoire.

JavaScript n'a pas de module de tas intégré, mais tu peux implémenter un min-heap avec un tableau.

Voici une implémentation basique de min-heap en JavaScript :

```js
class MinHeap {
  constructor(compare = (a, b) => a - b) {
    this.data = [];
    this.compare = compare;
  }

  peek() {
    return this.data[0];
  }

  push(value) {
    this.data.push(value);
    this.#bubbleUp(this.data.length - 1);
  }

  pop() {
    if (this.data.length === 0) return undefined;

    const top = this.data[0];
    const last = this.data.pop();

    if (this.data.length > 0) {
      this.data[0] = last;
      this.#bubbleDown(0);
    }

    return top;
  }

  pushPop(value) {
    if (this.data.length === 0) return value;

    if (this.compare(this.data[0], value) < 0) {
      const top = this.data[0];
      this.data[0] = value;
      this.#bubbleDown(0);
      return top;
    }

    return value;
  }

  heapify(arr) {
    this.data = arr.slice();
    for (let i = Math.floor(this.data.length / 2) - 1; i >= 0; i--) {
      this.#bubbleDown(i);
    }
  }

  #bubbleUp(i) {
    while (i > 0) {
      const p = Math.floor((i - 1) / 2);
      if (this.compare(this.data[i], this.data[p]) >= 0) break;
      [this.data[i], this.data[p]] = [this.data[p], this.data[i]];
      i = p;
    }
  }

  #bubbleDown(i) {
    const n = this.data.length;

    while (true) {
      let smallest = i;
      const l = 2 * i + 1;
      const r = 2 * i + 2;

      if (l < n && this.compare(this.data[l], this.data[smallest]) < 0) smallest = l;
      if (r < n && this.compare(this.data[r], this.data[smallest]) < 0) smallest = r;

      if (smallest === i) break;

      [this.data[i], this.data[smallest]] = [this.data[smallest], this.data[i]];
      i = smallest;
    }
  }
}
````

Pour utiliser ce tas, tu peux créer un tas vide. Ce sera la structure de données sous-jacente du tas :

```js
const myHeap = new MinHeap();
```

Pour ajouter des éléments au tas, tu appellerais `push()`. Cela ajoutera automatiquement l'élément là où il doit être, pour préserver la propriété de tas :

```js
myHeap.push(9);
```

Pour obtenir l'élément avec la plus haute priorité (dans ce cas, la plus petite valeur), tu appellerais `pop()` :

```js
myHeap.pop();
```

`pushPop()` combine les deux opérations en un seul appel.

C'est plus efficace que de les appeler séparément en séquence, surtout quand le tas est grand, car il n'effectue qu'une seule opération de réordonnancement :

```js
myHeap.pushPop(15);
```

Si tu as déjà un tableau et que tu veux le transformer en tas, tu pourrais appeler `heapify()` :

```js
myHeap.heapify([9, 2, 7, 1]);
```

Mais actuellement, nous trions les éléments par leurs valeurs, n'est-ce pas ?

Et si nous voulions les trier par leur « priorité » à la place ?

Tu pourrais le faire en stockant des tableaux avec cette structure : `[priority, element]`.

En JavaScript, les tableaux ne sont pas automatiquement comparés élément par élément pour l'ordonnancement, donc tu passes une fonction de comparaison au tas qui compare d'abord les priorités.

Note bien que, dans ce cas, les valeurs plus basses représenteront des priorités plus élevées. Cela signifie qu'un élément avec une priorité de 1 aura une priorité **plus haute** qu'un élément avec une priorité de 3 :

```js
const myHeap = new MinHeap((a, b) => a[0] - b[0]);

myHeap.push([3, "A"]);
myHeap.push([2, "B"]);
myHeap.push([1, "C"]);
```

Si tu as besoin que les éléments avec la même priorité soient retirés dans l'ordre où ils ont été insérés, tu pourrais envisager d'inclure un compteur unique comme deuxième élément de ton item pour départager, comme ceci `[priority, counter, element]`.

Par exemple, tu peux comparer d'abord par priorité, puis par le compteur :

```js
let counter = 0;
const myHeap = new MinHeap((a, b) => (a[0] - b[0]) || (a[1] - b[1]));

myHeap.push([3, counter++, "A"]);
myHeap.push([2, counter++, "B"]);
myHeap.push([2, counter++, "C"]);
```

Parlons maintenant de l'efficacité des tas.

Les complexités temporelles moyennes et dans le pire des cas pour l'insertion et l'extraction de la valeur minimum ou maximum d'un tas (selon le type de tas) sont logarithmiques, `O(log n)`, car le nombre d'échanges requis est généralement proportionnel à la hauteur du tas, qui est log(n).

La complexité temporelle moyenne et dans le pire des cas pour l'opération « peek » est un temps constant, O(1). Le peek consiste à obtenir la valeur minimum ou maximum (selon le type de tas) sans la retirer.

L'opération « heapify », où le tas est construit à partir d'une liste non triée, a une complexité temporelle linéaire, O(n), en moyenne et dans le pire des cas.

De même, la recherche et la suppression d'un élément arbitraire ont toutes deux des complexités temporelles moyennes et dans le pire des cas linéaires de O(n), car elles nécessitent potentiellement de parcourir tout le tas.

Et de combien d'espace ont-ils besoin ?

La complexité spatiale du tas est linéaire, O(n), où `n` est le nombre d'éléments qu'il contient. Il n'a besoin que de stocker les éléments et un petit surcoût supplémentaire pour l'objet tableau lui-même.

Les files de priorité et les tas sont très importants en informatique. Ils te permettent de trouver et d'utiliser rapidement les éléments les plus importants d'une liste. Cette efficacité est cruciale pour de nombreux programmes informatiques qui effectuent des tâches critiques du monde réel, comme trouver l'itinéraire le plus rapide sur une carte.
