# --description--

Les graphes sont des structures de données très puissantes formées d'un ensemble de nœuds, aussi appelés sommets, et d'arêtes qui les relient.

Il y a deux façons courantes d'implémenter des graphes dans ton code :

* Matrices d'adjacence

* Listes d'adjacence

Examinons-les plus en détail, et passons en revue leurs avantages et leurs limitations.

## Matrices d'adjacence

Nous commencerons par les matrices d'adjacence.

Une matrice d'adjacence est un tableau à deux dimensions dans lequel les lignes et les colonnes représentent les sommets du graphe.

Les valeurs dans la matrice représentent les arêtes ou connexions entre les nœuds.

Par exemple, si tu as une matrice stockée dans une variable nommée `matrix`, la valeur stockée à `matrix[i][j]`, où `i` est la ligne et `j` est la colonne, représente l'arête ou la connexion entre le nœud `i` et le nœud `j`.

Les valeurs peuvent avoir différentes significations selon que le graphe est pondéré ou non pondéré :

* Si le graphe est non pondéré, une valeur de `1` signifie qu'il y a une arête reliant ces nœuds, tandis qu'une valeur de `0` signifie qu'il n'y a pas d'arête entre eux.

* Si le graphe est pondéré, la valeur représenterait le poids de l'arête qui relie les nœuds.

L'un des grands avantages d'utiliser une matrice d'adjacence est que vérifier s'il y a une arête entre deux nœuds prend un temps constant `O(1)`. C'est parce que le programme n'a besoin que de trouver cette valeur particulière dans le tableau 2D.

Cependant, cette efficacité pour trouver les arêtes a un compromis. Les matrices d'adjacence ont un grand besoin d'espace quadratique `O(V²)`, où `V` est le nombre de nœuds dans le graphe.

C'est inefficace pour les graphes creux, qui sont des graphes qui n'ont que peu d'arêtes. Pourquoi ? Parce que si le graphe est creux, tu stockeras beaucoup de 0 dans la matrice pour représenter l'absence d'arêtes entre les nœuds, et ces 0 occuperont quand même de l'espace en mémoire.

Les matrices d'adjacence sont aussi inefficaces pour trouver les voisins d'un nœud, car le programme doit parcourir toute la ligne ou la colonne pour trouver les 0 et les 1 qui représentent les arêtes. Dans le pire des cas, ce processus peut prendre un temps `O(V)`, où `V` est le nombre de nœuds dans le graphe.

Voyons un exemple de matrice d'adjacence pour ce graphe particulier :

<img src="https://cdn.freecodecamp.org/curriculum/lecture-transcripts/how-do-matrices-and-adjacency-lists-work-1.png" alt="Un graphe avec quatre nœuds étiquetés A, B, C et D. Le nœud A est relié à B, C et D. Le nœud B est relié à A et D. Le nœud C est relié à A. Le nœud D est relié à A et B.">

Dans la matrice d'adjacence :

* Chaque ligne représente un nœud. La première ligne représente le nœud A, la deuxième ligne représente le nœud B, et ainsi de suite.

* Chaque colonne représente aussi un nœud.

* Chaque valeur dans la matrice représente s'il y a une arête entre chaque paire de nœuds. Une valeur de 0 signifie qu'il n'y a pas d'arête reliant ces nœuds, tandis qu'une valeur de 1 signifie qu'il y en a une.

Les valeurs sur la diagonale représentent si chaque nœud a une boucle sur lui-même, une arête qui relie le nœud à lui-même. Dans notre exemple, ce sont toutes des 0 parce que le graphe n'a aucune boucle sur lui-même.

Voici une représentation visuelle de la matrice d'adjacence pour te montrer comment les lignes et les colonnes représentent les nœuds correspondants.

Par exemple, la première ligne est `[0, 1, 1, 1]` parce que le nœud A a des arêtes le reliant aux nœuds B, C et D :

```markdown
#      A  B  C  D
# A   [0, 1, 1, 1],
# B   [1, 0, 0, 1],
# C   [1, 0, 0, 0],
# D   [1, 1, 0, 0]
```

Et voici la même matrice d'adjacence, mais implémentée en code JavaScript :

```javascript
const adjacencyMatrix = [
  [0, 1, 1, 1], // The neighbors of A are B, C, and D
  [1, 0, 0, 1], // The neighbors of B are A and D
  [1, 0, 0, 0], // The only neighbor of C is A
  [1, 1, 0, 0]  // The neighbors of D are A and B
];
```

## Listes d'adjacence

Une autre façon courante de représenter des graphes est d'utiliser des listes d'adjacence.

Une liste d'adjacence est un tableau ou un objet (ou une `Map`) qui stocke tous les voisins de chaque nœud.

Il y a deux façons courantes d'implémenter des listes d'adjacence :

* Sous forme de tableau, où chaque indice représente un nœud et le tableau stocké à cet indice contient ses voisins.
* Sous forme d'objet (ou `Map`), où chaque clé représente un nœud et la valeur associée à cette clé (un tableau) contient ses voisins.

Les listes d'adjacence sont plus efficaces que les matrices d'adjacence en termes de besoins en espace. Elles ont une complexité spatiale `O(V + E)`, où `V` est le nombre de sommets (nœuds) et `E` est le nombre d'arêtes.

Elles sont aussi efficaces pour trouver tous les nœuds voisins, puisque cette opération ne nécessite que d'accéder à la liste associée au nœud.

Cependant, il y a aussi un compromis.

Les listes d'adjacence sont moins efficaces que les matrices d'adjacence pour déterminer s'il y a une arête entre deux nœuds.

Le processus de recherche prend typiquement un temps `O(deg(v))` (où `deg(v)` est le nombre de voisins du nœud que tu vérifies), et dans le pire des cas il peut être `O(V)` si un nœud est connecté à tous les autres nœuds du graphe.

Voici un exemple de liste d'adjacence pour ce graphe :

<img src="https://cdn.freecodecamp.org/curriculum/lecture-transcripts/how-do-matrices-and-adjacency-lists-work-1.png" alt="Un graphe avec quatre nœuds étiquetés A, B, C et D. Le nœud A est relié à B, C et D. Le nœud B est relié à A et D. Le nœud C est relié à A. Le nœud D est relié à A et B. C'est la même image qu'auparavant.">

Cette liste d'adjacence est implémentée comme un objet. Chaque clé de l'objet représente un nœud, et la valeur associée à cette clé est un tableau avec tous les voisins du nœud correspondant :

```javascript
const adjacencyList = {
  A: ["B", "C", "D"],
  B: ["A", "D"],
  C: ["A"],
  D: ["A", "B"]
};
```

Alternativement, nous pourrions l'implémenter comme un tableau 2D, où chaque indice représente un nœud. Par exemple, l'indice 0 représente le nœud A, l'indice 1 représente le nœud B, et ainsi de suite :

```javascript
const adjacencyList = [
  ["B", "C", "D"], // Neighbors of A (index 0)
  ["A", "D"],      // Neighbors of B (index 1)
  ["A"],           // Neighbors of C (index 2)
  ["A", "B"]       // Neighbors of D (index 3)
];
```

Remarque que même si ce tableau 2D peut sembler similaire à la matrice d'adjacence, ils sont assez différents.

* La matrice d'adjacence stocke des 0, des 1, ou d'autres valeurs qui représentent les arêtes ou les poids des arêtes dans le graphe.

* La liste d'adjacence stocke la liste réelle de tous les voisins de chaque nœud.

C'est une différence très importante que tu devrais connaître.

Les matrices d'adjacence et les listes d'adjacence sont toutes deux très importantes pour implémenter des graphes. Le choix entre elles dépend de la taille du graphe et de la façon dont tu as besoin d'utiliser les données. Les matrices d'adjacence sont utiles pour les graphes denses avec beaucoup d'arêtes, tandis que les listes d'adjacence sont généralement le choix privilégié pour les scénarios du monde réel, où les graphes creux sont plus courants.
