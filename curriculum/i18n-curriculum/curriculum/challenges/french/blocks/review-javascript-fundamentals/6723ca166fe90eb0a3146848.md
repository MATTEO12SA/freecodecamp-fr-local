## Constructeur String et méthode `toString()`

- **Définition** : un objet chaîne est utilisé pour représenter une séquence de caractères. Les objets chaîne sont créés à l'aide de la fonction constructeur `String`, qui enveloppe la valeur primitive dans un objet.

:::interactive_editor

```js
const greetingObject = new String("Hello, world!");

console.log(typeof greetingObject); // "object"
```

:::

- **Méthode `toString()`** : cette méthode convertit une valeur en sa représentation sous forme de chaîne. C'est une méthode que tu peux utiliser pour les nombres, les booléens, les tableaux et les objets.

:::interactive_editor

```js
const num = 10;
console.log(num.toString()); // "10"

const arr = [1, 2, 3];
console.log(arr.toString()); // "1,2,3"
```

:::

Cette méthode accepte une base optionnelle, qui est un nombre de 2 à 36. Cette base représente le système de numération, comme la base 2 pour le binaire ou la base 8 pour l'octal. Si la base n'est pas spécifiée, elle utilise par défaut la base 10, qui est le décimal.


:::interactive_editor

```js
const num = 10;
console.log(num.toString(2)); // "1010"(binary)
```

:::

## Constructeur Number

- **Définition** : le constructeur `Number` est utilisé pour créer un objet nombre. L'objet nombre contient quelques propriétés et méthodes utiles comme `isNaN` et `toFixed`. La plupart du temps, tu utiliseras le constructeur `Number` pour convertir d'autres types de données en type nombre.

:::interactive_editor

```js
const myNum = new Number("34");
console.log(typeof myNum); // "object"

const num = Number('100');
console.log(num); // 100

console.log(typeof num); // number
```

:::

## Bonnes pratiques pour nommer les variables et les fonctions

- **camelCase** : par convention, les développeurs JavaScript utilisent le camelCase pour nommer les variables et les fonctions. Le camelCase consiste à écrire le premier mot entièrement en minuscules et à commencer chaque mot suivant par une majuscule. Ex. `isLoading`.

- **Nommer les booléens** : pour les variables booléennes, il est courant d'utiliser des préfixes tels que « is », « has » ou « can ».

```js
let isLoading = true;
let hasPermission = false;
let canEdit = true;
```

- **Nommer les fonctions** : pour les fonctions, le nom doit indiquer clairement ce que fait la fonction. Pour les fonctions qui renvoient un booléen (souvent appelées prédicats), tu peux utiliser les mêmes préfixes « is », « has » ou « can ». Pour les fonctions qui récupèrent des données, il est courant de commencer par le mot « get ». Pour les fonctions qui définissent des données, il est courant de commencer par le mot « set ». Pour les fonctions gestionnaires d'événements, tu peux utiliser le préfixe « handle » ou le suffixe « Handler ».

```js
function getUserData() { /* ... */ }

function isValidEmail(email) { /* ... */ }

function getProductDetails(productId) { /* ... */ }

function setUserPreferences(preferences) { /* ... */ }

function handleClick() { /* ... */ }
```

- **Nommer les variables dans les boucles** : pour nommer les variables d'itération dans les boucles, il est courant d'utiliser des lettres simples comme `i`, `j` ou `k`.

```js
for (let i = 0; i < array.length; i++) { /* ... */ }
```

## Travailler avec les tableaux clairsemés

- **Définition** : il est possible d'avoir des tableaux avec des emplacements vides. Les emplacements vides sont définis comme des emplacements ne contenant rien. C'est différent des emplacements de tableau ayant la valeur `undefined`. Ces types de tableaux sont connus sous le nom de tableaux clairsemés.

:::interactive_editor

```js
const sparseArray = [1, , , 4];
console.log(sparseArray.length); // 4
```

:::

## Linters et formateurs

- **Linters** : un linter est un outil d'analyse statique de code qui signale les erreurs de programmation, les bugs, les erreurs de style et les constructions suspectes. Un exemple de linter courant serait ESLint.
- **Formateurs** : les formateurs sont des outils qui formatent automatiquement ton code pour qu'il respecte un guide de style spécifique. Un exemple de formateur courant serait Prettier.

## Gestion de la mémoire

- **Définition** : la gestion de la mémoire est le processus de contrôle de la mémoire, en l'allouant lorsque c'est nécessaire et en la libérant lorsqu'elle n'est plus utile. JavaScript utilise une gestion automatique de la mémoire. Cela signifie que JavaScript (plus précisément, le moteur JavaScript de ton navigateur web) s'occupe de l'allocation et de la libération de la mémoire pour toi. Tu n'as pas à libérer explicitement la mémoire dans ton code. Ce processus automatique est souvent appelé « garbage collection » (ramasse-miettes).

## Fermetures

- **Définition** : une fermeture est une fonction qui a accès aux variables de sa portée lexicale extérieure (englobante), même après que la fonction extérieure a renvoyé.

:::interactive_editor

```js
function outerFunction(x) {
  let y = 10;
  function innerFunction() {
    console.log(x + y);
  }
  return innerFunction;
}

let closure = outerFunction(5);
closure(); // 15
```

:::

## Mot-clé `var` et hissage

- **Définition** : `var` était la façon originale de déclarer des variables avant 2015. Mais `var` posait certains problèmes en termes de portée, de redéclaration, etc. C'est pourquoi la programmation JavaScript moderne utilise `let` et `const` à la place.
- **Redéclarer des variables avec `var`** : si tu essaies de redéclarer une variable avec `let`, tu obtiens une `SyntaxError`. Mais avec `var`, tu es autorisé à redéclarer une variable.

```js
// Uncaught SyntaxError: Identifier 'num' has already been declared
let num = 19;
let num = 18;

var myNum = 5;
var myNum = 10; // This is allowed and doesn't throw an error

console.log(myNum) // 10
```

- **`var` et la portée** : les variables déclarées avec `var` à l'intérieur d'un bloc (comme une instruction `if` ou une boucle `for`) restent accessibles en dehors de ce bloc.

:::interactive_editor

```js
if (true) {
  var num = 5;
}
console.log(num); // 5
```

:::

- **Hissage** : c'est le comportement par défaut de JavaScript qui consiste à déplacer les déclarations en haut de leur portée respective pendant la phase de compilation, avant l'exécution du code. Lorsque tu déclares une variable avec le mot-clé `var`, JavaScript hisse la déclaration en haut de sa portée.

:::interactive_editor

```js
console.log(num); // undefined
var num = 5;
console.log(num); // 5
```

:::

Lorsque tu déclares une fonction avec la syntaxe de déclaration de fonction, le nom de la fonction et le corps de la fonction sont hissés. Cela signifie que tu peux appeler une fonction avant de l'avoir déclarée dans ton code.

:::interactive_editor

```js
sayHello(); // "Hello, World!"

function sayHello() {
  console.log("Hello, World!");
}
```

:::

Les déclarations de variables faites avec `let` ou `const` sont hissées, mais elles ne sont pas initialisées, et tu ne peux pas y accéder avant la déclaration réelle dans ton code. Ce comportement est souvent appelé la « zone morte temporelle » (temporal dead zone).

:::interactive_editor

```js
console.log(num); // Throws a ReferenceError
let num = 10;
```

:::

## Travailler avec les imports, exports et modules

- **Module** : c'est une unité de code autonome qui encapsule des fonctions, des classes ou des variables liées. Pour créer un module, tu écris ton code JavaScript dans un fichier séparé.
- **Exports** : toutes les variables, fonctions ou classes que tu veux rendre disponibles aux autres parties de ton application doivent être explicitement exportées avec le mot-clé `export`. Il existe deux types d'export : l'export nommé et l'export par défaut.
- **Imports** : pour utiliser les éléments exportés dans une autre partie de ton application, tu dois les importer avec le mot-clé `import`. Les types peuvent être l'import nommé, l'import par défaut et l'import d'espace de noms.

```js
// Within a file called math.js, we export the following functions:

// Named export
export function add(num1, num2) {
  return num1 + num2;
}

// Default export
export default function subtract(num1, num2) {
  return num1 - num2;
}

// Within another file, we can import the functions from math.js.

// Named import - This line imports the add function.
// The name of the function must exactly match the one exported from math.js.
import { add } from './math.js';

// Default import - This line imports the subtract function.
// The name of the function can be anything.
import subtractFunc from './math.js';

// Namespace import - This line imports everything from the file.
import * as Math from './math.js';

console.log(add(5, 3)); // 8
console.log(subtractFunc(5, 3)); // 2
console.log(Math.add(5, 3)); // 8
console.log(Math.subtract(5, 3)); // 2
```
