# --interactive--

En JavaScript, il existe plusieurs façons de vérifier si un objet possède une propriété précise. Comprendre ces méthodes est important pour travailler efficacement avec les objets, surtout lorsque tu traites des données provenant de sources externes ou lorsque tu dois t'assurer que certaines propriétés existent avant de les utiliser.

Nous allons explorer quelques approches courantes : la méthode `hasOwnProperty()`, la méthode `Object.hasOwn()`, l'opérateur `in`, et la vérification par rapport à `undefined`.

Commençons par la méthode `hasOwnProperty()`. Cette méthode retourne un booléen indiquant si l'objet possède la propriété spécifiée comme propriété propre. Voici un exemple :

:::interactive_editor

```js
const person = {
  name: "Alice",
  age: 30
};

console.log(person.hasOwnProperty("name")); // true
console.log(person.hasOwnProperty("job")); // false
```

:::

Dans cet exemple, nous avons un objet appelé `person` avec deux propriétés : `name` et `age`. Pour vérifier si `name` est une propriété de l'objet `person`, nous utilisons la méthode `hasOwnProperty()`. Comme `name` est une propriété, elle retournera `true`. Mais lorsque nous utilisons `hasOwnProperty()` pour vérifier si `job` est une propriété, elle retournera `false` car elle n'existe pas dans l'objet.

`Object.hasOwn()` est la façon moderne et recommandée de vérifier si un objet possède une propriété comme propriété propre (non héritée). Vois-la comme une version améliorée et plus sûre de `hasOwnProperty()`. La syntaxe est `Object.hasOwn(object, propertyName)` — tu passes l'objet comme premier argument et le nom de la propriété comme second.

Voici un exemple de base :

:::interactive_editor

```js
const person = {
  name: "Alice",
  age: 30
};

console.log(Object.hasOwn(person, "name")); // true
console.log(Object.hasOwn(person, "job")); // false
```

:::

Dans cet exemple, `Object.hasOwn(person, "name")` retourne `true` car `name` existe directement sur l'objet `person`. `Object.hasOwn(person, "job")` retourne `false` car `job` n'a jamais été ajouté à l'objet.

Une chose très importante à comprendre est que `Object.hasOwn()` vérifie uniquement si la propriété **existe** — elle ne se soucie pas de la valeur de la propriété. Cela signifie qu'elle retourne quand même `true` même lorsque la valeur est `0`, `false`, `null` ou `undefined` :

:::interactive_editor

```js
const user = {
  username: "coder123",
  score: 0,
  isActive: false,
  nickname: null
};

// Object.hasOwn() correctly reports these all exist
console.log(Object.hasOwn(user, "score"));    // true  (value is 0, but property exists)
console.log(Object.hasOwn(user, "isActive")); // true  (value is false, but property exists)
console.log(Object.hasOwn(user, "nickname")); // true  (value is null, but property exists)
console.log(Object.hasOwn(user, "email"));   // false (property was never added)

// Danger! Using if() directly gives wrong results for falsy values
if (user.score) {
  console.log("Has score"); // This will NOT print even though score exists!
}

// Safe! Object.hasOwn() gives correct result
if (Object.hasOwn(user, "score")) {
  console.log("Has score:", user.score); // Has score: 0
}
```

:::

Une autre façon de vérifier l'existence d'une propriété dans un objet est d'utiliser l'opérateur `in`. Comme `hasOwnProperty()`, l'opérateur `in` retournera `true` si la propriété existe sur l'objet. Voici comment tu peux l'utiliser :

:::interactive_editor

```js
const person = {
  name: "Bob",
  age: 25
};
console.log("name" in person);  // true
```

:::

Dans cet exemple, `"name" in person` retourne `true` car `name` est une propriété de `person`.

La troisième méthode consiste à vérifier si une propriété est `undefined`. Cette approche peut être utile, mais elle a quelques limites. Voici un exemple :

:::interactive_editor

```js
const car = {
  brand: "Toyota",
  model: "Corolla",
  year: 2020
};

console.log(car.brand !== undefined); // true
console.log(car.color !== undefined); // false
```

:::

Dans ce code, nous vérifions si `car.brand` et `car.color` ne sont pas `undefined`. Cela fonctionne parce qu'accéder à une propriété inexistante sur un objet retourne `undefined`. Cependant, cette méthode peut donner des faux négatifs si une propriété a explicitement la valeur `undefined`.

En pratique, le choix entre ces méthodes dépend souvent des besoins spécifiques de ton code. Comprendre les différences entre elles t'aidera à faire le bon choix dans différents scénarios.
