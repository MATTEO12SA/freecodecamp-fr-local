# --interactive--

En JavaScript, comprendre la différence entre les types de données primitifs et non primitifs est important pour écrire un code efficace et sans bug.

Ces deux catégories de types de données se comportent différemment en termes de stockage en mémoire et de manipulation dans tes programmes.

Les types de données primitifs sont la forme la plus simple de données en JavaScript. Ils incluent number, bigint, string, boolean, `null`, `undefined` et symbol. Ces types sont appelés « primitifs » parce qu'ils représentent des valeurs uniques et ne sont pas des objets.

Lorsque tu travailles avec des types de données primitifs, tu manipules directement leurs valeurs. Par exemple, lorsque tu crées une variable avec une valeur primitive, cette valeur est stockée directement dans la variable.

Les valeurs primitives sont immuables, ce qui signifie qu'une fois créées, leur valeur ne peut pas être modifiée. Cependant, tu peux réaffecter une nouvelle valeur à la variable. Voici un exemple de travail avec des types de données primitifs :

:::interactive_editor

```js
let num1 = 5;
let num2 = num1;
num1 = 10;

console.log(num2); // 5
```

:::

Dans cet exemple, nous affectons une valeur primitive (`5`) de `num1` à `num2`. Cela crée une copie indépendante de la valeur. Par conséquent, toute modification apportée à la variable d'origine (`num1`) n'affecte pas la copie (`num2`).

Les types de données non primitifs, en revanche, sont plus complexes. En JavaScript, ce sont les objets, qui incluent les objets classiques, les tableaux et les fonctions. Contrairement aux primitifs, les types non primitifs peuvent contenir plusieurs valeurs sous forme de propriétés ou d'éléments.

Lorsque tu crées une variable avec une valeur non primitive, ce qui est stocké dans la variable est en réalité une référence vers l'emplacement en mémoire où l'objet est stocké, pas l'objet lui-même. Cela entraîne quelques différences importantes de comportement. Voici un exemple avec des types non primitifs :

:::interactive_editor

```js
const originalPerson = { name: "John", age: 30 };
const copiedPerson = originalPerson;

originalPerson.age = 31;

console.log(copiedPerson.age); // 31
```

:::

Dans cet exemple, nous avons un objet appelé `originalPerson` avec deux propriétés `name` et `age`. Nous affectons ensuite l'objet `originalPerson` à une variable appelée `copiedPerson`.

Ensuite, nous mettons à jour la valeur `age` de l'objet `originalPerson`. Lorsque nous affichons la propriété `age` de l'objet `copiedPerson`, elle montre la valeur mise à jour.

Mais pourquoi cela se produit-il ? Cela arrive parce que `originalPerson` et `copiedPerson` font tous deux référence au même objet en mémoire.

En JavaScript, lorsque tu affectes un objet à une autre variable, tu copies la référence vers l'objet, pas l'objet lui-même. C'est ce qu'on appelle la copie superficielle par référence. Par conséquent, toute modification apportée à l'objet via une référence se répercute sur toutes les références vers cet objet.

Au fur et à mesure que tu continueras à travailler avec JavaScript, tu rencontreras de nombreuses situations où comprendre la différence entre les types primitifs et non primitifs est important. C'est un concept fondamental qui sous-tend de nombreux aspects du langage et qui est essentiel pour écrire un code efficace et correct.
