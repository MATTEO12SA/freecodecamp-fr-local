# --description--

Dans une leçon précédente, tu as appris ce que sont les dépendances. Ici, tu en apprendras davantage et les points à considérer quand tu choisis un paquet externe pour ton projet.

Une dépendance est un autre morceau de code dont ton projet a besoin pour fonctionner. Ce sont généralement des paquets externes que d'autres développeurs ont créés et partagés dans le registre npm.

Utiliser des dépendances te fait gagner beaucoup de temps. Au lieu de tout construire toi-même, tu peux installer un paquet qui résout déjà un problème courant — des choses comme créer un serveur web, gérer le routage, récupérer des données, gérer l'authentification, et plus encore.

Dans ton fichier `package.json`, tous les paquets dont ton projet dépend sont listés sous la clé `dependencies` :

```json
{
  "name": "package-dependencies",
  "version": "1.0.0",
  "description": "a demo on how package dependencies work",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "keywords": [
    "Node",
    "NPM"
  ],
  "author": "Kolade Chris",
  "license": "ISC",
  "dependencies": {
    "chalk": "^5.6.2",
    "lodash": "^4.17.21"
  }
}
```

Dans l'exemple de fichier `package.json` ci-dessus, `chalk` et `lodash` sont listés comme dépendances du projet. Cela signifie que le projet s'appuie sur ces paquets pour fonctionner. S'ils ne sont pas installés—et listés dans le fichier `package.json`—toute fonctionnalité qui les utilise cassera.

Il existe aussi une autre catégorie de dépendances appelée `devDependencies`. Ce sont des paquets dont tu as besoin uniquement pendant la construction ou les tests de ton projet, pas quand il tourne en production. Des exemples courants incluent :

* Nodemon pour redémarrer automatiquement le projet quand il y a des mises à jour

* Jest ou Mocha pour les tests

* ESLint pour le linting du code

Comme tu t'y attendrais, les `devDependencies` apparaissent sous la section `devDependencies` du fichier `package.json` :

```json
{
  "name": "package-dependencies",
  "version": "1.0.0",
  "description": "a demo on how package dependencies work",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "keywords": [
    "Node",
    "NPM"
  ],
  "author": "Kolade Chris",
  "license": "ISC",
  "dependencies": {
    "chalk": "^5.6.2",
    "lodash": "^4.17.21"
  },
  "devDependencies": {
    "jest": "^30.2.0",
    "nodemon": "^3.1.10"
  }
}
```

Quand tu choisis quels paquets utiliser dans ton projet, il y a quelques points importants à garder à l'esprit.

La sécurité doit toujours venir en premier. Même un seul paquet non sûr peut créer des problèmes pour tout ton projet. Tu dois aussi considérer les performances, car un paquet volumineux ou mal optimisé peut ralentir ton projet.

Il est aussi utile de choisir des paquets populaires et bien pris en charge. Les paquets populaires ont généralement des communautés actives, une bonne documentation et des mises à jour fréquentes. Une façon facile de vérifier la popularité est de regarder le nombre de téléchargements hebdomadaires sur npm. Par exemple, le paquet `chalk` obtient plus de 300 000 téléchargements chaque semaine :

<img src="https://cdn.freecodecamp.org/curriculum/lecture-transcripts/what-are-package-dependencies-and-what-are-some-considerations-for-choosing-an-external-package-1.webp" alt="capture d'écran npm des statistiques du paquet chalk">

La maintenance est importante aussi. Les paquets bien maintenus sont mis à jour régulièrement et fonctionnent mieux avec les nouvelles versions des autres logiciels.

Enfin, ne néglige pas la documentation. Des docs claires et complètes facilitent beaucoup la compréhension de l'usage d'un paquet et te font gagner beaucoup de temps quand tu l'intègres dans ton projet.
