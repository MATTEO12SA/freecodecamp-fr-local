# --description--

npm a besoin d'un moyen de stocker des détails importants sur ton projet – des choses comme les paquets qu'il utilise, la version de ces paquets, et les commandes qu'il peut exécuter. Il le fait avec le fichier `package.json`.

Pense au fichier `package.json` comme à un fichier de configuration npm pour le projet. C'est un simple fichier JSON qui décrit ton projet avec des paires clé-valeur pour suivre des choses comme :

* le nom et la version du projet

* l'auteur

* le fichier principal qui doit être exécuté en premier

* la licence

* le dépôt de code, les mots-clés et les descriptions

* toutes les dépendances dont le projet a besoin

Voici à quoi pourrait ressembler un fichier `package.json` :

```json
{
  "name": "my-app",
  "version": "1.0.0",
  "description": "A simple NPM project",
  "main": "index.js",
  "scripts": {
    "start": "node index.js",
    "test": "echo \"Running tests...\""
  },
  "repository": {
    "type": "git",
    "url": "git+https://github.com/username/project.git"
  },
  "keywords": ["fCC", "js"],
  "author": "Kolade Chris",
  "license": "ISC",
  "dependencies": {
    "react": "^19.2.1"
  },
  "devDependencies": {
    "cypress": "^15.7.1"
  }
}
```

Le champ `main` est souvent défini sur `index.js`, et indique à Node.js quel fichier exécuter en premier.

Le champ `license` sert à préciser les conditions légales sous lesquelles d'autres personnes peuvent utiliser, modifier et distribuer le code de ton paquet. Il existe de nombreuses licences comme `MIT`, `ISC` ou `GPL`, qui ont toutes des conditions et permissions différentes. La valeur par défaut est `ISC`, la licence Internet Systems Consortium, une licence open source très permissive.

À mesure que ton projet grandit et que tu installes des paquets, npm les ajoute sous l'une de ces deux sections :

* `dependencies`, qui sont les paquets dont ton app a besoin pour tourner en production

* `devDependencies`, qui sont les paquets dont tu as besoin uniquement pendant le développement

Par exemple, si ton projet utilise React pour son UI, cela va dans `dependencies` car c'est requis pour que ton projet fonctionne une fois déployé. Un outil comme Cypress, utilisé uniquement pour les tests end-to-end avant le déploiement en production, appartient à `devDependencies`.

Il y a quelques façons faciles de créer un fichier `package.json`. La plus courante est d'exécuter la commande suivante :

```bash
npm init
```

Tu dois l'exécuter dans le dossier racine de ton projet. Cette commande démarre un processus de configuration interactif où npm te pose une série de questions. Tes réponses servent à remplir des champs comme le nom du projet, la version, la description, les scripts, les mots-clés, l'auteur et la licence.

Si tu préfères sauter les questions et créer un fichier `package.json` avec des valeurs par défaut, tu peux exécuter :

```bash
npm init -y
```

ou

```bash
npm init --yes
```

Cela crée instantanément un fichier `package.json` pour toi avec des valeurs par défaut dans de nombreux champs.

Il est généralement préférable d'utiliser `npm init` sans le drapeau `-y` ou `--yes` pour parcourir chaque champ et personnaliser les informations de ton projet. Si tu ne réponds pas à une question, npm utilise simplement une valeur par défaut. Par exemple, si tu laisses la question de la licence vide, npm la définira sur `ISC` par défaut.

Tu remarqueras peut-être que `dependencies` et `devDependencies` ne sont pas encore listés. C'est parce que ces sections ne sont ajoutées qu'après l'installation de ton premier paquet.

Tu remarqueras aussi que le champ `repository` est manquant. Même si npm a posé la question pendant `npm init`, il ne le remplit pas automatiquement ensuite. Par exemple, quand tu exécutes des commandes comme `git remote add origin` ou `git push`, npm ne mettra pas à jour le champ repository pour toi — tu dois l'ajouter manuellement si tu veux qu'il soit inclus.
