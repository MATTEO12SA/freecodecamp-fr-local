# --description--

Quand tu installes des dépendances avec npm, surtout dans un projet existant, npm regarde ton fichier `package.json` pour voir quels paquets ton projet a besoin.

Chaque dépendance dans `package.json` inclut un numéro de version comme ceci :

```bash
"lodash": "^4.17.21"
```

Comme tu l'as appris plus tôt, le **caret (^)** permet à npm d'installer des versions mineures et de patch plus récentes comme `4.18.0` ou `4.17.22`. Cette flexibilité est utile, mais elle peut aussi entraîner des problèmes.

Si deux développeurs exécutent `npm install` à des moments différents, npm pourrait installer des versions légèrement différentes du même paquet. Même de petites différences peuvent causer des bugs ou un comportement inattendu.

Le fichier `package-lock.json` résout cela. Il est créé automatiquement la première fois que tu exécutes `npm install`, et il verrouille les versions exactes de chaque dépendance installée—y compris toutes les dépendances enfants, qui sont des dépendances de dépendances.

Cela garantit que tout le monde travaillant sur le projet obtient les mêmes versions de paquets à chaque fois.

Voici un simple fichier `package.json` avec `lodash` comme dépendance :

```bash
{
  "name": "package-lock-json",
  "version": "1.0.0",
  "description": "",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "keywords": [],
  "author": "",
  "license": "ISC",
  "type": "commonjs",
  "dependencies": {
    "lodash": "^4.17.21"
  }
}
```

Et voici la section correspondante du `package-lock.json` :

```bash
"node_modules/lodash": {
  "version": "4.17.21",
  "resolved": "https://registry.npmjs.org/lodash/-/lodash-4.17.21.tgz",
  "integrity": "sha512-v2kDEe57..."
}
```

Remarque la différence :

* Dans `package.json`, `lodash` est listé comme `^4.17.21` — une règle flexible.

* Dans `package-lock.json`, `lodash` est épinglé à la version `4.17.21`.

Peu importe quand quelqu'un exécute `npm install`, il obtiendra cette version exacte.

Ainsi, peu importe quand quelqu'un exécute `npm install`, il obtiendra exactement la même version de Lodash à chaque fois.

Note que cela s'applique aussi aux dépendances enfants, qui sont les dépendances de toute dépendance que tu utilises pour ton projet.

Tu peux voir qu'en plus d'Express lui-même, il y a d'autres paquets comme `accepts`, `mime-types` et `negotiator`. Ce sont des dépendances enfants, des paquets dont Express dépend en interne pour fonctionner.

Remarque aussi que, bien que les `dependencies` dans `node_modules/express` utilisent des caractères caret pour les plages, si tu trouves l'entrée de chaque dépendance enfant comme `node_modules/etags`, elles sont épinglées à une version spécifique.

En résumé, le fichier `package-lock.json` garde tout le monde sur la même longueur d'onde et assure la cohérence entre machines de développeurs, serveurs CI, déploiements et autres environnements.

Il est important de toujours committer ton fichier `package-lock.json` avec Git pour que ton équipe partage la même configuration. Aussi, ne modifie pas manuellement le fichier `package-lock.json`—npm le mettra à jour automatiquement quand les dépendances changent.
