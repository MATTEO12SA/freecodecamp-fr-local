# --description--

La programmation dynamique est une technique algorithmique qui résout des problèmes complexes en les décomposant en sous-problèmes plus simples et en stockant les résultats pour éviter les calculs redondants. Cette approche transforme des problèmes qui prendraient normalement un temps exponentiel en problèmes pouvant être résolus en temps polynomial.

## Principes fondamentaux de la programmation dynamique

La programmation dynamique fonctionne lorsque deux conditions clés sont présentes dans un problème.

- **Sous-problèmes qui se chevauchent** : Les mêmes petits problèmes apparaissent plusieurs fois lors de la résolution du problème plus large. Au lieu de recalculer ces sous-problèmes à plusieurs reprises, on stocke leurs solutions.

- **Sous-structure optimale** : La solution optimale du problème contient des solutions optimales de ses sous-problèmes. Cela signifie qu'on peut construire la meilleure solution en combinant les meilleures solutions des parties plus petites.

Examinons ces concepts à l'aide du problème classique de « montée d'escalier ».

## Le problème de la récursion naïve

Considère le problème de montée d'escalier : tu montes un escalier de `n` marches et tu peux monter soit 1, soit 2 marches à la fois. Combien de façons distinctes as-tu d'atteindre le sommet ?

```js
function climbStairsRecursive(n) {
  // Base cases: 1 way for 1 step, 2 ways for 2 steps
  if (n <= 2) {
    return n;
  }

  // Recursive rule: to reach step n, you can come from step (n-1) or step (n-2)
  return climbStairsRecursive(n - 1) + climbStairsRecursive(n - 2);
}
```

Cette implémentation a une complexité temporelle exponentielle à cause d'énormes calculs redondants. Lors du calcul de `climbStairsRecursive(5)`, voici ce qui se passe :

- `climbStairsRecursive(5)` appelle `climbStairsRecursive(4)` et `climbStairsRecursive(3)`

- `climbStairsRecursive(4)` appelle `climbStairsRecursive(3)` et `climbStairsRecursive(2)`

- Or `climbStairsRecursive(3)` est calculé **deux fois**

- `climbStairsRecursive(3)` appelle `climbStairsRecursive(2)` et `climbStairsRecursive(1)`

- `climbStairsRecursive(2)` est calculé **3 fois au total**

Pour seulement `n=5`, on fait 9 appels de fonction alors qu'on n'a besoin que de 5 calculs uniques. À mesure que `n` augmente, cette redondance explose exponentiellement — `climbStairsRecursive(30)` nécessiterait plus de quelques millions d'appels de fonction ! La complexité temporelle devient `O(2^n)`, ce qui la rend inefficace et impraticable pour de plus grandes valeurs de `n`.

## Solutions de programmation dynamique

La programmation dynamique élimine ce calcul redondant grâce à deux approches principales :

### Mémoïsation (approche top-down)

La mémoïsation stocke les résultats d'appels de fonctions coûteux et renvoie le résultat mis en cache lorsque les mêmes entrées se représentent :

```js
function climbStairsMemo(n, memo = {}) {
  // If already calculated, return cached value
  if (memo[n] !== undefined) {
    return memo[n];
  }

  // Base cases: 1 way for 1 step, 2 ways for 2 steps
  if (n <= 2) {
    return n;
  }

  // Calculate once and store in memo for future use
  memo[n] =
    climbStairsMemo(n - 1, memo) +
    climbStairsMemo(n - 2, memo);

  return memo[n];
}
```

La mémoïsation est bien plus efficace car chaque valeur unique de `1` à `n` est calculée exactement une fois. Lorsque nous avons à nouveau besoin de `climbStairsMemo(3)`, au lieu de le recalculer (ce qui déclencherait d'autres appels récursifs), nous le recherchons simplement dans notre dictionnaire memo en temps `O(1)`.

Suivons l'exécution de `climbStairsMemo(5)` avec l'approche top-down pour voir comment la mémoïsation élimine le travail redondant :

```md
Call: climbStairsMemo(5)
  memo = {} (empty)

  Call: climbStairsMemo(4)
    memo = {} (empty)

    Call: climbStairsMemo(3)
      memo = {} (empty)

      Call: climbStairsMemo(2) → returns 2 (base case)
      Call: climbStairsMemo(1) → returns 1 (base case)

      Result: 2 + 1 = 3
      memo = {3: 3} (stored!)

    Call: climbStairsMemo(2) → returns 2 (base case)

    Result: 3 + 2 = 5
    memo = {3: 3, 4: 5} (stored!)

  Call: climbStairsMemo(3) → returns 3 (FROM MEMO - no recursion!)

  Result: 5 + 3 = 8
  memo = {3: 3, 4: 5, 5: 8}
```

**Comparaison d'efficacité**

- **Récursion naïve** : Fait 9 appels de fonction avec des calculs répétés

- **Mémoïsation** : Ne fait que 5 calculs uniques, puis réutilise les résultats stockés

- **Complexité temporelle** : Réduite de `O(2^n)` à `O(n)` puisque nous ne faisons que `n` calculs uniques

- **Complexité spatiale** : `O(n)` pour le stockage memo et la pile d'appels

- **Impact réel** : `climbStairsMemo(30)` passe de millions d'appels de fonction à environ 30 calculs uniques !

### Tabulation (approche bottom-up)

La tabulation construit la solution depuis la base, en remplissant une table avec les solutions des sous-problèmes :

```js
function climbStairsTabulation(n) {
  if (n <= 2) {
    return n;
  }

  // Create an array to store solutions from 0 to n
  const dp = new Array(n + 1).fill(0);

  // Base cases
  dp[1] = 1; // 1 way to reach step 1
  dp[2] = 2; // 2 ways to reach step 2

  // Build up the solution iteratively
  for (let i = 3; i <= n; i++) {
    // Ways to reach step i = ways to reach (i-1) + ways to reach (i-2)
    dp[i] = dp[i - 1] + dp[i - 2];
  }

  return dp[n];
}
```

La tabulation élimine entièrement la récursion en construisant la solution de façon itérative, des plus petits sous-problèmes jusqu'à la cible.

Voyons l'approche bottom-up en action pour voir comment on construit la solution de façon systématique. Voici la construction itérative pour `climbStairsTabulation(5)` :

```md
Initial state:
dp = [0, 1, 2, 0, 0, 0]
     [0, 1, 2, 3, 4, 5] ← indices (step numbers)

Step by step construction:

i = 3:
  dp[3] = dp[2] + dp[1] = 2 + 1 = 3
  dp = [0, 1, 2, 3, 0, 0]

i = 4:
  dp[4] = dp[3] + dp[2] = 3 + 2 = 5
  dp = [0, 1, 2, 3, 5, 0]

i = 5:
  dp[5] = dp[4] + dp[3] = 5 + 3 = 8
  dp = [0, 1, 2, 3, 5, 8]

Final result: dp[5] = 8
```

**Avantages clés de la tabulation**

- **Pas de surcoût de récursion** : Contrairement à la mémoïsation, il n'y a pas de pile d'appels récursifs.

- **Exécution prévisible** : On calcule les valeurs dans un ordre prédéterminé (1, 2, 3, 4, 5...).

- **Favorable au cache** : L'accès séquentiel au tableau optimise l'utilisation de la mémoire.

- **Facile à optimiser** : On peut réduire la complexité spatiale à `O(1)` car on n'a besoin que des deux dernières valeurs.

```js
function climbStairsOptimized(n) {
  if (n <= 2) {
    return n;
  }

  // Store only the last two results to save space
  let prev2 = 1; // ways to reach step 1
  let prev1 = 2; // ways to reach step 2

  for (let i = 3; i <= n; i++) {
    const current = prev1 + prev2;

    // Shift values forward
    prev2 = prev1;
    prev1 = current;
  }

  return prev1;
}
```

**Comparaison d'efficacité**

- **Récursion naïve** : 9 appels de fonction pour `n=5`, croissance exponentielle.

- **Tabulation** : 3 additions simples pour `n=5`, croissance linéaire.

- **Complexité temporelle** : `O(n)` au lieu de `O(2^n)`.

- **Complexité spatiale** : `O(n)` pour le tableau, ou `O(1)` avec optimisation.

- **Performance prévisible** : Aucun risque de débordement de pile pour de grandes entrées.

Les deux approches réduisent la complexité temporelle d'exponentielle `O(2^n)` à linéaire `O(n)`, une amélioration spectaculaire qui fait la différence entre résoudre le problème en millisecondes et attendre des années pour de plus grandes entrées.

## Applications concrètes

La programmation dynamique a des applications très répandues en informatique et au-delà :

- **Optimisation d'itinéraires** : Les systèmes GPS utilisent des algorithmes de programmation dynamique pour trouver les plus courts chemins entre des lieux.

- **Traitement de texte** : Les correcteurs orthographiques et les fonctionnalités d'autocomplétion s'appuient souvent sur la programmation dynamique pour calculer les distances d'édition entre les mots.

- **Modélisation financière** : Les stratégies d'investissement et l'optimisation de portefeuilles emploient fréquemment des techniques de programmation dynamique.

- **Allocation de ressources** : Le problème du sac à dos et ses variantes apparaissent dans la planification, la budgétisation et la gestion des ressources.

## Exemple pratique : le problème du rendu de monnaie

Le problème du rendu de monnaie est un défi de code classique qui, résolu avec la programmation dynamique, illustre les deux principes clés de la PD : sous-structure optimale et sous-problèmes qui se chevauchent.

Le problème du rendu de monnaie demande : « Quel est le nombre minimum de pièces nécessaires pour atteindre un montant cible ? »

Voici une solution utilisant la programmation dynamique :

```js
function minCoins(amount, coins) {
  // Create dp array from 0 to amount, filled with Infinity
  const dp = new Array(amount + 1).fill(Infinity);

  // Base case: 0 coins needed to make amount 0
  dp[0] = 0;

  // Build up from 1 to target amount
  for (let i = 1; i <= amount; i++) {
    // Try each coin denomination
    for (let coin of coins) {
      // Only use coin if it is not larger than current amount
      if (coin <= i) {
        // Choose the minimum: current value OR solution for remaining amount + 1 coin
        dp[i] = Math.min(dp[i], dp[i - coin] + 1);
      }
    }
  }

  // Return result if possible, -1 if impossible (infinity)
  return dp[amount] === Infinity ? -1 : dp[amount];
}

/*
 Example usage:
coins = [1, 3, 4], amount = 6

dp[0] = 0
dp[1] = dp[0] + 1 = 1
dp[2] = dp[1] + 1 = 2
dp[3] = min(dp[2]+1, dp[0]+1) = min(2+1, 0+1) = 1
dp[4] = min(dp[3]+1, dp[1]+1, dp[0]+1) = min(1+1, 1+1, 0+1) = 1
dp[5] = min(dp[4]+1, dp[2]+1, dp[1]+1) = min(1+1, 2+1, 1+1) = 2
dp[6] = min(dp[5]+1, dp[3]+1, dp[2]+1) = min(2+1, 1+1, 2+1) = 2

Result: 2 coins (3 + 3)
*/
```

Et voici comment l'algorithme de rendu de monnaie en programmation dynamique fonctionne étape par étape pour `coins = [1, 3, 4]`, `amount = 6` :

```md
Initial state:
dp = [0, ∞, ∞, ∞, ∞, ∞, ∞]
     [0, 1, 2, 3, 4, 5, 6] ← amounts

Building up the solution:

For amount = 1:
  Try coin 1: dp[1] = min(∞, dp[0] + 1) = min(∞, 0 + 1) = 1
  dp = [0, 1, ∞, ∞, ∞, ∞, ∞]

For amount = 2:
  Try coin 1: dp[2] = min(∞, dp[1] + 1) = min(∞, 1 + 1) = 2
  dp = [0, 1, 2, ∞, ∞, ∞, ∞]

For amount = 3:
  Try coin 1: dp[3] = min(∞, dp[2] + 1) = min(∞, 2 + 1) = 3
  Try coin 3: dp[3] = min(3, dp[0] + 1) = min(3, 0 + 1) = 1
  dp = [0, 1, 2, 1, ∞, ∞, ∞]

For amount = 4:
  Try coin 1: dp[4] = min(∞, dp[3] + 1) = min(∞, 1 + 1) = 2
  Try coin 3: dp[4] = min(2, dp[1] + 1) = min(2, 1 + 1) = 2
  Try coin 4: dp[4] = min(2, dp[0] + 1) = min(2, 0 + 1) = 1
  dp = [0, 1, 2, 1, 1, ∞, ∞]

For amount = 5:
  Try coin 1: dp[5] = min(∞, dp[4] + 1) = min(∞, 1 + 1) = 2
  Try coin 3: dp[5] = min(2, dp[2] + 1) = min(2, 2 + 1) = 2
  Try coin 4: dp[5] = min(2, dp[1] + 1) = min(2, 1 + 1) = 2
  dp = [0, 1, 2, 1, 1, 2, ∞]

For amount = 6:
  Try coin 1: dp[6] = min(∞, dp[5] + 1) = min(∞, 2 + 1) = 3
  Try coin 3: dp[6] = min(3, dp[3] + 1) = min(3, 1 + 1) = 2
  Try coin 4: dp[6] = min(2, dp[2] + 1) = min(2, 2 + 1) = 2
  dp = [0, 1, 2, 1, 1, 2, 2]

Final result: dp[6] = 2 (achieved with coins 3 + 3)
```

Cette solution illustre les deux principes clés de la programmation dynamique. Elle a des sous-problèmes qui se chevauchent car trouver le minimum de pièces pour le montant 6 nécessite de connaître les solutions pour les montants 5, 3 et 2. Ces mêmes sous-problèmes apparaissent lors du calcul d'autres montants. Elle a une sous-structure optimale car la solution optimale pour tout montant intègre les solutions optimales pour des montants plus petits. Si on sait que le minimum de pièces pour le montant 3 est 1, alors une façon de faire le montant 6 est d'utiliser cette solution plus une pièce supplémentaire de valeur 3.

Sans PD, il faudrait essayer chaque combinaison possible de pièces — un nombre exponentiel de possibilités. Avec la PD, on construit la solution de façon systématique :

- **Complexité temporelle** : `O(amount × number of coins)` au lieu d'exponentielle.

- **Complexité spatiale** : `O(amount)` pour le tableau `dp`.

- **Pas de travail redondant** : Chaque sous-problème (trouver le minimum de pièces pour chaque montant) est résolu exactement une fois.

- **Résultats réutilisables** : Une fois qu'on connaît le minimum de pièces pour le montant 3, on utilise cette connaissance pour tous les montants plus grands qui peuvent en bénéficier.

## Quand utiliser la programmation dynamique

La programmation dynamique est efficace lorsque :

- Le problème peut être décomposé en sous-problèmes qui se chevauchent.

- Le problème présente une sous-structure optimale.

- Une solution récursive naïve entraînerait des calculs répétés.

- Tu as besoin d'optimiser la complexité temporelle au prix de la complexité spatiale.

Les motifs courants de programmation dynamique incluent les problèmes d'optimisation (trouver des valeurs minimum/maximum), les problèmes de comptage (nombre de façons d'accomplir quelque chose) et les problèmes de décision qui peuvent être décomposés en décisions plus petites.

La programmation dynamique transforme des problèmes complexes en problèmes gérables en stockant et réutilisant systématiquement les solutions des sous-problèmes. Comprendre cette technique ouvre la porte à la résolution efficace d'un large éventail de défis computationnels.
