# --description--

Quand tu conçois tes applications, tu auras souvent une série de petites fonctions responsables d'une seule chose. C'est ce qu'on appelle le « principe de responsabilité unique ». Quand tu as une série de petites fonctions, il est préférable de les tester pour s'assurer que tout fonctionne comme prévu. Dans cette leçon, on verra comment créer un test unitaire avec le framework de test populaire Jest.

Dans cet exemple, on va créer une fonction responsable de renvoyer une chaîne nouvellement formatée :

```js
export function getFormattedWord(str) {
  if (!str) return '';
  return str.charAt(0).toUpperCase() + str.slice(1);
}
```

Cette fonction `getFormattedWord` a un paramètre appelé `str` et vérifie d'abord si `str` est vide. Si oui, une chaîne vide est renvoyée. Sinon, une nouvelle chaîne est renvoyée où la première lettre est en majuscule. On exporte cette fonction pour pouvoir l'utiliser dans un fichier de test.

Dans un fichier séparé `getFormattedWord.test.js`, on peut écrire des tests pour vérifier que la fonction fait ce qu'elle est censée faire.

En haut du fichier `getFormattedWord.test.js`, on doit d'abord importer la fonction comme ceci :

```js
import { getFormattedWord } from "./getFormattedWord.js";
```

Ensuite, on doit installer le paquet Jest avec `npm i jest`. Puis on peut ajouter un test pour vérifier qu'un mot en minuscules, `hello`, est correctement formaté en `Hello`, qui commence par un `H` majuscule :

```js
test('capitalizes the first letter of a word', () => {
  expect(getFormattedWord('hello')).toBe('Hello');
});
```

La fonction `expect` sert à tester une valeur. Elle est combinée avec un matcher, une fonction qui vérifie si la valeur se comporte comme prévu. Dans ce cas, le matcher est `toBe()`. Jest a une variété de matchers pour t'aider à tester la vérité, les chaînes, les nombres, et plus encore.

Une façon d'exécuter tes tests est d'ajouter un script npm à ton fichier `package.json`. Voici un exemple de script pour le framework Jest :

```js
"scripts": {
  "test": "jest"
},
```

Ensuite, lance simplement `npm run test` dans ton terminal pour exécuter tes tests. Si tes tests passent, tu devrais voir quelque chose comme ceci dans le terminal :

```sh
PASS ./getFormattedWord.test.js
  ✓ capitalizes the first letter of a word (1 ms)

Test Suites: 1 passed, 1 total
Tests:       1 passed, 1 total
Snapshots:   0 total
Time:        0.103 s, estimated 1 s
Ran all test suites.
```

Pour voir à quoi ressemble un test qui échoue, on peut intentionnellement casser le test en mettant à jour la fonction comme suit :

```js
export function getFormattedWord(str) {
  if (!str) return '';
  return "This is incorrect";
}
```

Maintenant, quand tu lances la commande `npm run test`, il y aura un message d'erreur car le test attendait un résultat différent :

```sh
FAIL ./getFormattedWord.test.js
  ✕ capitalizes the first letter of a word (1 ms)

  ● capitalizes the first letter of a word

  expect(received).toBe(expected) // Object.is equality

  Expected: "Hello"
  Received: "This is incorrect"

    2 |
    3 | test('capitalizes the first letter of a word', () => {
    4 |   expect(getFormattedWord('hello')).toBe('Hello');
                                            ^
    5 | });
    6 |

    at Object.toBe (getFormattedWord.test.js:4:37)

Test Suites: 1 failed, 1 total
Tests:       1 failed, 1 total
Snapshots:   0 total
Time:        0.121 s, estimated 1 s
Ran all test suites.
```

On peut maintenant remettre notre fonction à l'original ici :

```js
export function getFormattedWord(str) {
  if (!str) return '';
  return str.charAt(0).toUpperCase() + str.slice(1);
}
```

Ajoute un autre test pour vérifier les cas où aucun argument n'est fourni à `getFormattedWord` :

```js
test("returns an empty string when no argument is provided", () => {
  expect(getFormattedWord()).toBe("");
});
```

Il y a d'autres tests que tu peux ajouter pour rendre les choses plus robustes, mais ces premiers tests sont une bonne introduction aux tests unitaires.

Pour tester des applications JavaScript, des frameworks courants incluent Jest, Mocha et Vitest.

Les tests unitaires sont importants car ils t'aideront à attraper plus de bugs dans tes programmes, et à s'assurer que tout fonctionne comme prévu. Ils peuvent aussi servir de documentation pour ton application, car ils sont censés représenter le comportement attendu de ton code.
