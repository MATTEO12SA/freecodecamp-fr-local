# --description--

Il y a deux approches de tests dont tu devrais être conscient en développement logiciel. Ces approches sont le TDD (Test-Driven Development) et le BDD (Behavior-Driven Development).

Regardons d'abord le TDD. Le Test-Driven Development est une méthodologie qui met l'accent sur l'écriture des tests avant de construire les fonctionnalités d'une application.

Voici le processus typique du TDD :

1. Écrire un test

2. S'assurer qu'il échoue

3. Écrire le code pour ce test

4. S'assurer que le test passe cette fois

5. Faire les éventuels refactorings nécessaires du code

Répéter les étapes 1 à 5.

Écrire les tests avant de construire les fonctionnalités donne un retour en temps réel aux développeurs pendant le développement. Cela aide aussi à attraper les bugs plus tôt dans la phase de développement.

Même si certaines équipes logicielles choisissent de suivre l'approche TDD, le TDD est un sujet polarisant dans l'industrie. Tu trouveras plein d'articles et de vidéos qui défendent ou critiquent le TDD. Quoi que tu penses de cette approche, il est important d'en être conscient car tu pourrais la rencontrer dans des scénarios réels.

La deuxième approche de tests qu'on regardera est le Behavior-Driven Development (BDD). Le BDD consiste à aligner une série de tests sur les objectifs métier. Ces tests doivent être écrits dans un langage compréhensible par les personnes techniques et non techniques.

Quand on teste des comportements spécifiques dans une application logicielle, le BDD utilise couramment le langage Gherkin, utilisé en entreprise pour décrire des comportements et des scénarios. Le langage Gherkin utilise des instructions Given, When et Then pour décrire les scénarios.

Voici un exemple :

**Scenario :** Créer un nouvel article de blog

**Given** l'utilisateur est connecté à son compte et se trouve sur la page « Create New Post »,

**When** l'utilisateur saisit un titre et un contenu pour l'article et clique sur le bouton « Publish »,

**Then** l'article de blog devrait être enregistré et affiché sur la page d'accueil avec le bon titre, contenu et horodatage.

Tu veux d'abord définir un scénario. Des exemples de scénarios incluent quand un utilisateur se connecte à une application ou passe une commande sur un site. Dans cet exemple, le scénario concerne un utilisateur qui crée un nouvel article de blog sur un site.

Après avoir défini le scénario, tu devrais commencer par une instruction Given. Cela donne le contexte de où se trouve l'utilisateur avant d'effectuer une action. L'instruction When représente l'action prise par l'utilisateur.

Enfin, l'instruction Then représente le résultat souhaité de l'action précédente de l'utilisateur. Une fois tous tes scénarios définis, tu peux écrire des tests pour chacun.

Des exemples de frameworks de test BDD incluent Cucumber, JBehave et SpecFlow.
