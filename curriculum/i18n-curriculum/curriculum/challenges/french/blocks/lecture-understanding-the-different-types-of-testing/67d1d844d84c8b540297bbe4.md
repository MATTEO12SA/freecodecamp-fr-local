# --description--

Jusqu'ici, tu as construit plein de petits projets dans des langages comme HTML, CSS, JavaScript, et plus encore. Mais comment savoir si tes projets fonctionnent correctement ?

Une option est de faire ce qu'on appelle des tests manuels. Un testeur parcourt chaque partie de l'application et teste toutes les fonctionnalités pour s'assurer qu'elles marchent correctement. Si des bugs sont découverts, le testeur les signale à l'équipe logicielle pour qu'ils soient corrigés.

Même s'il est important de tester manuellement tes applications, ce n'est souvent pas suffisant. Les applications du monde réel impliquent de nombreux composants et services, et peuvent être complexes. Se fier uniquement aux tests manuels laissera beaucoup de bugs sous la surface, ce qui peut nuire à l'utilisabilité et à la maintenabilité d'une application.

C'est là qu'interviennent les tests automatisés. Tu peux écrire un code de test séparé pour vérifier si ton application se comporte comme prévu, sans avoir à cliquer manuellement partout. Les tests manuels et automatisés peuvent être regroupés en différents types, selon ce qu'ils testent.

Dans les prochaines leçons, on couvrira les différents types de tests utilisés dans l'industrie : tests unitaires, tests de bout en bout, tests fonctionnels, et plus encore.

Écrire des tests pour tes applications aidera à s'assurer que ton code fait ce qu'il est censé faire. Il est important de commencer à te familiariser avec les bases des tests, car ce sera quelque chose dont tu auras besoin dans un poste de développeur.
