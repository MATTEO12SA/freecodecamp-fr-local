# --description--

Dans les leçons précédentes, tu as appris à tester de petites unités de code via les tests unitaires. Eh bien, les tests unitaires font partie des tests fonctionnels. Les tests fonctionnels vérifient si les fonctionnalités de l'application marchent comme prévu.

Dans cette leçon, on regardera les différences entre tests fonctionnels et non fonctionnels.

L'objectif des tests fonctionnels est de tester le système dans son ensemble face à plusieurs scénarios pour s'assurer qu'il fonctionne comme prévu. Un exemple de test fonctionnel serait le smoke testing. Le smoke testing consiste à faire une vérification préliminaire du système pour des problèmes basiques ou critiques avant des tests plus poussés.

En contraste, les tests non fonctionnels se concentrent sur des aspects comme la performance et la fiabilité.

Un vrai scénario de test fonctionnel serait une connexion utilisateur. Un utilisateur devrait pouvoir se connecter à l'application avec son nom d'utilisateur et son mot de passe. En cas de succès, il devrait pouvoir accéder aux informations de son compte. S'il y a un problème, cette erreur doit être gérée correctement. Quand tu écris des tests, tu dois prendre en compte tous les types de scénarios de succès et d'échec.

Un exemple de test non fonctionnel serait de tester la performance de ton application sous différentes conditions réseau. Dans une prochaine leçon, tu en apprendras plus sur les tests de performance.

Les raisons pour lesquelles les tests fonctionnels sont si importants : tu veux identifier les bugs tôt dans ton application. Tu veux aussi t'assurer que ton application répond aux exigences définies au début de la phase de planification. Enfin, tu veux t'assurer que tes utilisateurs ont une bonne expérience. Les utilisateurs ne devraient pas peiner à utiliser ton application ni être bloqués par des fonctionnalités cassées et des pannes système.
