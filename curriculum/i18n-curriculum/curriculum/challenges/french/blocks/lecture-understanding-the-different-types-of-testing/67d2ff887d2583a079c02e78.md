# --description--

Le web est un endroit puissant rempli d'informations et d'activités. Mais ce peut aussi être un endroit dangereux si tu n'es pas prudent. Il y a de nombreux hackers et cybercriminels qui cherchent de nouvelles façons de pirater des sites et de compromettre des données.

Tu as probablement entendu parler de quelques fuites de données très médiatisées qui ont touché des entreprises milliardaires comme Meta et Microsoft. Quand tu travailles sur des applications web, tu devras faire des tests de sécurité approfondis pour aider à identifier les vulnérabilités et les faiblesses.

Voici quelques principes à connaître quand tu fais des audits et des tests de sécurité :

- Confidentialité : cela protège contre la divulgation d'informations sensibles à des destinataires non prévus.

- Intégrité : cela implique d'empêcher des utilisateurs malveillants de modifier les informations utilisateur.

- Authentification : cela implique de vérifier l'identité de l'utilisateur pour s'assurer qu'il est autorisé à utiliser le système.

- Autorisation : c'est le processus qui détermine quelles actions les utilisateurs authentifiés peuvent effectuer, ou quelles parties du système ils peuvent accéder.

- Disponibilité : cela garantit que les informations et services sont disponibles pour les utilisateurs autorisés quand ils en ont besoin.

- Non-répudiation : cela garantit que l'émetteur et le destinataire ont une preuve de livraison et une vérification de l'identité de l'émetteur. Cela protège contre le déni d'avoir envoyé l'information.

Maintenant qu'on comprend le raisonnement derrière les tests de sécurité, regardons quelques menaces de sécurité courantes :

- Cross-site Scripting (XSS) : tu as appris cela dans une leçon précédente. Pour rappel, les attaques XSS surviennent quand un attaquant injecte des scripts malveillants dans une page web vue par d'autres utilisateurs. Ces scripts peuvent alors s'exécuter dans le contexte du navigateur de la victime, potentiellement voler des cookies et des données de session, ou effectuer d'autres actions malveillantes sans le savoir ni le consentement de l'utilisateur.

- Injection SQL : SQL est un langage pour gérer et stocker des informations dans une base de données relationnelle. L'injection SQL permet à des utilisateurs malveillants d'injecter du code malveillant dans une base de données. Tu en apprendras plus sur SQL, les bases relationnelles et l'injection SQL dans un futur module.

- Attaque par déni de service (DoS) : c'est quand des utilisateurs malveillants inondent un site d'un grand nombre de requêtes ou de trafic, ce qui ralentit le serveur et peut le faire planter, rendant le site indisponible.

Il y a bien d'autres types de menaces de sécurité, mais aussi de nombreux outils pour aider à protéger tes applications web et les rendre plus sécurisées. Voici les grandes catégories dans lesquelles tombent les outils de tests de sécurité :

- Static application security testing : ces outils évaluent le code source d'une application pour identifier des vulnérabilités de sécurité.

- Dynamic application security testing (DAST) : ces outils s'interfacent avec le front-end de l'application pour découvrir des faiblesses de sécurité potentielles. Contrairement au SAST, les outils DAST n'ont pas accès au code source.

Un autre type de test de sécurité est le test de pénétration (ou pentest). Cela consiste à créer des cyberattaques simulées sur l'application pour identifier des vulnérabilités dans le système. Les entreprises de taille moyenne à grande peuvent avoir une équipe de professionnels de la cybersécurité dédiés qui réalisent des pentests régulièrement dans le cadre de leurs audits de sécurité.

Le monde de la cybersécurité est très vaste et détaillé. Mais chaque développeur devrait comprendre quelques menaces courantes contre les applications web et des façons de s'en protéger.
