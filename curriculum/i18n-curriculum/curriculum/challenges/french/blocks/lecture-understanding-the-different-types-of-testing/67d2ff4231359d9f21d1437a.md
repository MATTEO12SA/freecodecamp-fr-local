# --description--

Les tests de bout en bout, ou E2E, testent des scénarios réels du point de vue de l'utilisateur. Des exemples de scénarios E2E incluent tester le processus d'inscription et de connexion, ou tester le checkout d'un site e-commerce.

Pour mieux comprendre comment fonctionnent les tests de bout en bout, regardons un exemple réel issu du dépôt freeCodeCamp. Cet exemple utilise Playwright, un framework E2E populaire développé par Microsoft.

Dans le dépôt freeCodeCamp, il y a un répertoire appelé `e2e` qui contient des tests pour les dons, les certifications, les examens, et plus encore. Dans ce répertoire, il y a un fichier `donate-page-donor.spec.ts` avec des tests pour la page supporter du donateur authentifié.

La première étape est de naviguer vers la page de dons en tant qu'utilisateur démo qui est déjà supporter :

```js
test.beforeEach(async ({ page }) => {
  execSync("node ./tools/scripts/seed/seed-demo-user --set-true isDonating");
  await page.goto("/donate");
});
```

Comme il y a plusieurs tests dans ce fichier, le hook `beforeEach` s'exécutera avant chacun des tests.

Une fois sur la page de dons, l'utilisateur verra un message de remerciement avec des suggestions pour soutenir freeCodeCamp davantage. Voici juste quelques tests qui vérifient une partie du texte trouvé sur la page de dons :

```js
test("should render the donate page correctly", async ({ page }) => {
  await expect(
    page.getByText("Thank you for your continued support")
  ).toBeVisible();

  await expect(
    page.getByText(
      "Your contributions are crucial in creating resources that empower millions of people to learn new skills and support their families."
    )
  ).toBeVisible();

  ...
});
```

Il y a aussi des tests pour vérifier que le donateur a un lien supporter dans la barre de menu, ainsi qu'une bordure stylisée spéciale autour de son avatar pour indiquer qu'il est supporter :

```js
test("The menu should have a supporters link", async ({ page }) => {
  const menuButton = page.getByTestId("header-menu-button");
  const menu = page.getByTestId("header-menu");

  await expect(menuButton).toBeVisible();
  await menuButton.click();

  await expect(menu).toBeVisible();

  await expect(page.getByRole("link", { name: "Supporters" })).toBeVisible();
});

test("The Avatar should have a special border for donors", async ({ page }) => {
  const container = page.locator(".avatar-container");
  await expect(container).toHaveClass("avatar-container gold-border");
});
```

En ayant ce type de tests détaillés, tu peux augmenter la couverture de tests de ton application au-delà des seuls tests unitaires. Les tests de bout en bout aident aussi à s'assurer que ton application se comporte correctement et de façon prévisible pour les utilisateurs. D'autres outils E2E incluent Cypress, Selenium et Puppeteer.

Même si les tests de bout en bout sont importants, ils sont coûteux car longs à mettre en place, concevoir et maintenir. Les tests E2E sont excellents pour les parcours utilisateur critiques, tandis que les tests unitaires sont excellents pour tester de petites unités dans l'application.
