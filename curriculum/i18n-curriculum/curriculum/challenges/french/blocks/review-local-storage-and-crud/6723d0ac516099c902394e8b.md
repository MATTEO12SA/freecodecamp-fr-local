## Stockage persistant

- **Définition** : Le stockage persistant désigne une façon de sauvegarder des données de sorte qu'elles restent disponibles même après une coupure d'alimentation ou un redémarrage de l'appareil.

## Create, Read, Update, Delete (CRUD)

- **Create** : Cela désigne le processus de création de nouvelles données. Par exemple, dans une application web, cela peut être lorsqu'un utilisateur ajoute un nouvel article à un blog.
- **Read** : C'est l'opération où les données sont récupérées depuis une base de données. Par exemple, lorsque tu visites un article de blog ou que tu consultes ton profil sur un site, tu effectues une opération de lecture pour récupérer et afficher des données stockées dans la base de données.
- **Update** : Cela consiste à modifier des données existantes dans la base de données. Un exemple serait la modification d'un article de blog ou la mise à jour des informations de ton profil.
- **Delete** : C'est l'opération qui retire des données d'une base de données. Par exemple, lorsque tu supprimes un article de blog ou un compte, tu effectues une opération de suppression.

## Méthodes HTTP

- **Définition** : HTTP signifie Hypertext Transfer Protocol et c'est le fondement de la communication de données sur le web. Il existe des méthodes HTTP qui définissent les actions pouvant être effectuées sur des ressources via le web. Les méthodes courantes sont GET, POST, PUT, PATCH, DELETE.
- **Méthode `GET`** : Elle est utilisée pour récupérer des données depuis un serveur.
- **Méthode `POST`** : Elle est utilisée pour envoyer des données à un serveur qui crée une nouvelle ressource.
- **Méthode `PUT`** : Elle est utilisée pour mettre à jour une ressource en la remplaçant entièrement.
- **Méthode `PATCH`** : Elle est utilisée pour mettre à jour partiellement une ressource.
- **Méthode `DELETE`** : Elle est utilisée pour supprimer des enregistrements d'une base de données.

## Propriétés `localStorage` et `sessionStorage`

- **Web Storage API** : Cette API fournit un mécanisme permettant aux navigateurs de stocker des paires clé-valeur directement dans le navigateur, ce qui permet aux développeurs de stocker des informations utilisables à travers différents rechargements de page et sessions. Les deux composants principaux de la Web Storage API sont les propriétés `localStorage` et `sessionStorage`.
- **Propriété `localStorage`** : `localStorage` est la partie de la Web Storage API qui permet aux données de persister même après la fermeture de la fenêtre du navigateur ou le rafraîchissement de la page. Ces données restent disponibles jusqu'à ce qu'elles soient explicitement retirées par l'application ou l'utilisateur.
- **Méthode `localStorage.setItem()`** : Cette méthode est utilisée pour stocker une paire clé-valeur dans `localStorage`.

```js
localStorage.setItem('username', 'Jessica');
```

- **Méthode `localStorage.getItem()`** : Cette méthode est utilisée pour récupérer la valeur d'une clé donnée depuis `localStorage`.

```js
localStorage.setItem('username', 'codingRules');

let username = localStorage.getItem('username');
console.log(username); // codingRules
```

- **Méthode `localStorage.removeItem()`** : Cette méthode est utilisée pour retirer un élément spécifique de `localStorage` à l'aide de sa clé.

```js
localStorage.removeItem('username');
```

- **Méthode `localStorage.clear()`** : Cette méthode est utilisée pour effacer toutes les données stockées dans `localStorage`.

```js
localStorage.clear();
```

- **Propriété `sessionStorage`** : Stocke des données qui ne durent que pour la session en cours et sont effacées lorsque l'onglet ou la fenêtre du navigateur est fermé.
- **Méthode `sessionStorage.setItem()`** : Cette méthode est utilisée pour stocker une paire clé-valeur dans `sessionStorage`.

```js
sessionStorage.setItem('cart', '3 items');
```

- **Méthode `sessionStorage.getItem()`** : Cette méthode est utilisée pour récupérer la valeur d'une clé donnée depuis `sessionStorage`.

```js
sessionStorage.setItem('cart', '3 items');

let cart = sessionStorage.getItem('cart');
console.log(cart); // '3 items'
```

- **Méthode `sessionStorage.removeItem()`** : Cette méthode est utilisée pour retirer un élément spécifique de `sessionStorage` à l'aide de sa clé.

```js
sessionStorage.removeItem('cart');
```

- **Méthode `sessionStorage.clear()`** : Cette méthode est utilisée pour effacer toutes les données stockées dans `sessionStorage`.

```js
sessionStorage.clear();
```

## Travailler avec les cookies

- **Définition** : Les cookies, aussi appelés cookies web ou cookies de navigateur, sont de petits morceaux de données qu'un serveur envoie au navigateur web d'un utilisateur. Ces cookies sont stockés sur l'appareil de l'utilisateur et renvoyés au serveur avec les requêtes suivantes. Les cookies sont essentiels pour aider les applications web à maintenir un état et à se souvenir des informations utilisateur, ce qui est particulièrement important car HTTP est un protocole sans état.
- **Cookies de session** : Ces cookies ne durent que le temps de la session de l'utilisateur sur le site. Une fois que l'utilisateur ferme le navigateur ou l'onglet, le cookie de session est supprimé. Ces cookies sont généralement utilisés pour des tâches comme garder un utilisateur connecté pendant sa visite.
- **Cookies sécurisés (Secure)** : Ces cookies ne sont envoyés que via HTTPS, ce qui garantit qu'ils ne peuvent pas être interceptés par un attaquant en transit.
- **Cookies HttpOnly** : Ces cookies ne peuvent pas être consultés ni modifiés par du JavaScript s'exécutant dans le navigateur, ce qui les rend plus sûrs face aux attaques de type cross-site scripting (XSS).
- **En-tête Set-Cookie** : Lorsque tu visites un site web, le serveur peut envoyer un en-tête Set-Cookie dans la réponse HTTP. Cet en-tête indique à ton navigateur d'enregistrer un cookie avec des informations spécifiques. Par exemple, il peut stocker un ID unique qui aide le site à te reconnaître lors de ta prochaine visite.
Tu peux définir manuellement un cookie en JavaScript avec `document.cookie` :

```js
document.cookie = "organization=freeCodeCamp; expires=Fri, 31 Dec 2021 23:59:59 GMT; path=/";
```

Pour supprimer un cookie, tu peux définir sa date d'expiration à une date passée.

```js
document.cookie = "username=; expires=Thu, 01 Jan 1970 00:00:00 GMT; path=/";
```

## Cache API

- **Définition** : La mise en cache est le processus qui consiste à stocker des copies de fichiers dans un emplacement de stockage temporaire, afin qu'elles puissent être consultées plus rapidement. La Cache API est utilisée pour stocker des requêtes et des réponses réseau, ce qui permet aux applications web de fonctionner plus efficacement et même hors ligne. Elle fait partie de la Service Worker API plus large et est cruciale pour créer des Progressive Web Apps (PWAs) capables de fonctionner dans des conditions réseau peu fiables ou lentes.
La Cache API est un mécanisme de stockage qui stocke des objets Request et Response. Lorsqu'une requête est faite à un serveur, l'application peut stocker la réponse et la récupérer plus tard depuis le cache au lieu de faire une nouvelle requête réseau. Cela réduit les temps de chargement, économise la bande passante et améliore l'expérience utilisateur globale.
- **Cache Storage** : Ceci est utilisé pour stocker des paires clé-valeur de requêtes HTTP et de leurs réponses correspondantes. Cela permet une récupération efficace des ressources précédemment demandées, réduisant le besoin de les récupérer depuis le réseau lors des visites suivantes et améliorant les performances.
- **Cache-Control** : Les développeurs peuvent définir combien de temps une ressource en cache doit être conservée, et si elle doit être revalidée ou servie directement depuis le cache.
- **Support hors ligne** : En utilisant la Cache API, tu peux créer des applications web offline-first. Par exemple, une PWA peut servir des assets en cache lorsque l'utilisateur est déconnecté du réseau.

## Patterns négatifs et stockage côté client

- **Suivi excessif** : Cela désigne la pratique qui consiste à collecter et stocker une quantité excessive de données utilisateur dans le stockage côté client (comme les cookies, le local storage ou le session storage) sans consentement clair et éclairé, ni besoin légitime. Cela implique souvent de suivre le comportement, les préférences et les interactions de l'utilisateur sur plusieurs sites ou sessions, ce qui peut porter atteinte à la vie privée de l'utilisateur.
- **Empreinte du navigateur (Browser Fingerprinting)** : Une technique utilisée pour suivre et identifier des utilisateurs individuels à partir de caractéristiques uniques de leur appareil et de leur navigateur, plutôt qu'en s'appuyant sur des cookies ou d'autres méthodes de suivi traditionnelles. Contrairement aux cookies, qui sont stockés localement sur l'appareil de l'utilisateur, le fingerprinting consiste à collecter un ensemble d'informations pouvant servir à créer une « empreinte » distinctive de la session de navigateur d'un utilisateur.
- **Stocker des mots de passe dans LocalStorage** : Cela peut sembler un pattern négatif plus évident, mais stocker des données sensibles comme des mots de passe dans le local storage représente un risque de sécurité. Le Local Storage n'est pas chiffré et peut être consulté facilement. Tu ne dois donc jamais y stocker de données sensibles d'aucune sorte.

## IndexedDB

- **Définition** : IndexedDB est utilisé pour stocker des données structurées dans le navigateur. Elle est intégrée aux navigateurs web modernes, ce qui permet aux applications web de stocker et de récupérer efficacement des objets JavaScript.

## Cache / Service Workers

- **Définition** : Un Service Worker est un script qui s'exécute en arrière-plan, séparément de ta page web. Il peut intercepter les requêtes réseau, accéder au cache et faire fonctionner l'application web hors ligne. C'est un composant clé des Progressive Web Apps.
