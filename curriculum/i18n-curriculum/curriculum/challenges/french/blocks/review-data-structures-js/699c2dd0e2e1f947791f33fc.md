## Algorithmes et notation Big O

- **Algorithmes** : Un ensemble d'instructions non ambiguës pour résoudre un problème ou accomplir une tâche. Les algorithmes doivent se terminer en un nombre fini d'étapes et chaque étape doit être précise et non ambiguë.

- **Notation Big O** : Décrit les performances dans le pire des cas, ou le taux de croissance, d'un algorithme lorsque la taille de l'entrée augmente. Elle se concentre sur la façon dont l'utilisation des ressources croît avec la taille de l'entrée, en ignorant les facteurs constants et les termes d'ordre inférieur.

### Complexités temporelles courantes

- **O(1) - Temps constant** : L'algorithme prend le même temps quelle que soit la taille de l'entrée.

:::interactive_editor

```js
function checkEvenOrOdd(number) {
  if (number % 2 === 0) {
    return "Even";
  } else {
    return "Odd";
  }
}

console.log(checkEvenOrOdd(4)) // "Even"
console.log(checkEvenOrOdd(5)) // "Odd"
```

:::

- **O(log n) - Temps logarithmique** : Le temps augmente lentement à mesure que l'entrée grandit. Courant dans les algorithmes qui réduisent de façon répétée la taille du problème d'une fraction (comme la recherche binaire).

- **O(n) - Temps linéaire** : Le temps d'exécution augmente proportionnellement à la taille de l'entrée.

```js
for (const grade of grades) { // grades is an array
  console.log(grade);
}
```

- **O(n log n) - Temps log-linéaire** : Complexité temporelle courante des algorithmes de tri efficaces comme le tri fusion et le tri rapide.

- **O(n²) - Temps quadratique** : Le temps d'exécution augmente de façon quadratique. Souvent observé dans les boucles imbriquées.

:::interactive_editor

```js
const n = 3;

for (let i = 0; i < n; i++) {
  for (let j = 0; j < n; j++) {
    console.log("Hello, World!");
  }
}
```

:::

### Complexité spatiale

- **O(1) - Espace constant** : L'algorithme utilise la même quantité de mémoire quelle que soit la taille de l'entrée.
- **O(n) - Espace linéaire** : L'utilisation de la mémoire croît proportionnellement à la taille de l'entrée.
- **O(n²) - Espace quadratique** : L'utilisation de la mémoire croît de façon quadratique avec la taille de l'entrée.

## Techniques de résolution de problèmes

- **Comprendre le problème** : Lis l'énoncé du problème plusieurs fois. Identifie l'entrée, la sortie attendue, et comment transformer l'entrée en sortie.

- **Pseudocode** : Description de haut niveau de la logique d'un algorithme, indépendante du langage. Utilise le langage courant mélangé à des constructions de programmation comme `IF`, `ELSE`, `FOR`, `WHILE`.

```md
GET original_string
SET reversed_string = ""
FOR EACH character IN original_string:
  ADD character TO THE BEGINNING OF reversed_string
DISPLAY reversed_string
```

- **Cas limites** : Entrées spécifiques et valides qui se situent aux frontières de ce qu'un algorithme doit gérer. Considère et teste toujours les cas limites.

## Tableaux

- **Tableaux statiques** : Ont une taille fixe déterminée à l'initialisation. Les éléments sont stockés dans des emplacements mémoire adjacents. La taille ne peut pas être modifiée pendant l'exécution du programme.

- **Tableaux dynamiques** : Peuvent grandir ou rétrécir automatiquement pendant l'exécution du programme. Gèrent le redimensionnement en copiant automatiquement vers de plus grands tableaux quand c'est nécessaire.

### Implémentation des tableaux dynamiques en JavaScript

:::interactive_editor

```js
let numbers = [3, 4, 5, 6];
// Access elements
console.log(numbers[0])  // 3

// Update elements
numbers[2] = 16
console.log([...numbers]);  // [3, 4, 16, 6]

// Add elements
numbers.push(7)
console.log([...numbers]);  // [3, 4, 16, 6, 7]

// Add at a specific index
numbers.splice(3, 0, 15);
console.log([...numbers]);  // [3, 4, 16, 15, 6, 7]

// Remove elements
numbers.splice(2, 1);  // Remove at specific index
console.log([...numbers]);  // [3, 4, 15, 6, 7]

numbers.pop()   // Remove last element
console.log([...numbers]); // [3, 4, 15, 6]
```

:::

### Complexités temporelles pour les tableaux dynamiques

- **Accès** : O(1)
- **Insertion à la fin** : O(1) en moyenne, O(n) quand un redimensionnement est nécessaire
- **Insertion au milieu** : O(n)
- **Suppression** : O(n) au milieu, O(1) à la fin

## Piles

- **Piles** : Structure de données Dernier entré, premier sorti (LIFO). Les éléments sont ajoutés et retirés uniquement par le sommet.

- **Opération Push** : Ajouter un élément au sommet de la pile. Complexité temporelle : O(1).

- **Opération Pop** : Retirer un élément du sommet de la pile. Complexité temporelle : O(1).

:::interactive_editor

```js
// Using JavaScript array as a stack

let stack = [];

// Push operations
stack.push(1);
stack.push(2);
stack.push(3);
console.log([...stack]);  // [1, 2, 3]

// Pop operations
let topElement = stack.pop();
console.log(topElement);  // 3
console.log([...stack]);  // [1, 2]
```

:::

## Files

- **Files** : Structure de données Premier entré, premier sorti (FIFO). Les éléments sont ajoutés à l'arrière et retirés à l'avant.

- **Opération Enqueue** : Ajouter un élément à l'arrière de la file. Complexité temporelle : O(1).

- **Opération Dequeue** : Retirer un élément de l'avant de la file. Complexité temporelle : O(1).

:::interactive_editor

```js
// Using JavaScript array as a queue
let queue = [];

// Enqueue operations
queue.push(1);
queue.push(2);
queue.push(3);
console.log([...queue]);  // [1, 2, 3]

// Dequeue operations
let firstElement = queue.shift();
console.log(firstElement);  // 1
console.log([...queue]);  // [2, 3]
```

:::

## Listes chaînées

- **Listes chaînées** : Structure de données linéaire où chaque nœud contient des données et une référence vers le nœud suivant. Les nœuds sont reliés comme une chaîne.

### Listes simplement chaînées

- **Structure** : Chaque nœud a des données et une référence vers le nœud suivant.
- **Parcours** : Tu ne peux te déplacer que vers l'avant, de la tête à la queue.
- **Nœud de tête** : Premier nœud de la liste, généralement le seul nœud directement accessible.
- **Nœud de queue** : Dernier nœud de la liste, pointe vers `null`.

### Opérations et complexités temporelles

- **Insertion au début** : O(1)
- **Insertion à la fin** : O(n) - doit parcourir jusqu'à la fin
- **Insertion au milieu** : O(n) - doit parcourir jusqu'à la position
- **Suppression au début** : O(1)
- **Suppression à la fin** : O(n) - doit parcourir pour trouver le nœud précédent
- **Suppression au milieu** : O(n) - doit parcourir pour trouver le nœud

### Listes doublement chaînées

- **Structure** : Chaque nœud a des données et deux références : le nœud suivant et le nœud précédent.
- **Parcours** : Tu peux te déplacer dans les deux directions.
- **Mémoire** : Nécessite plus de mémoire que les listes simplement chaînées à cause de la référence supplémentaire.

## Quand utiliser chaque structure de données

- **Tableaux (tableaux dynamiques)** : Quand tu as besoin d'un accès ordonné et indexé et que tu ne connais pas la taille à l'avance
- **Piles** : Pour les opérations LIFO (fonctionnalité d'annulation, évaluation d'expressions, retour arrière)
- **Files** : Pour les opérations FIFO (ordonnancement de tâches, parcours en largeur)
- **Listes chaînées** : Quand des insertions/suppressions fréquentes au début, une taille inconnue, et qu'aucun accès aléatoire n'est nécessaire
