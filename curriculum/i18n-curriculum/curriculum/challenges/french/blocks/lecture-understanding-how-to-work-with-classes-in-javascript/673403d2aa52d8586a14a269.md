# --interactive--

En programmation, l'héritage te permet de définir des classes qui héritent des propriétés et méthodes d'autres classes.

Par exemple, une `Car` est un type de `Vehicle`, donc tu pourrais définir une classe `Vehicle` avec les propriétés et méthodes les plus générales communes à tous les types de véhicules, puis définir une classe `Car` qui hérite des propriétés et méthodes de la classe `Vehicle`.

Cette relation « est un » est caractéristique de l'héritage. Dans cet exemple, `Car` est une forme plus spécialisée de `Vehicle`.

Il y a deux concepts principaux que tu dois connaître pour commencer à travailler avec l'héritage : la classe parente et la classe enfant.

Une classe parente est une classe qui agit comme un plan pour d'autres classes. Elle définit des propriétés et méthodes qui sont héritées par d'autres classes.

Une classe enfant est une classe qui hérite des propriétés et méthodes d'une autre classe. Les classes enfants peuvent aussi étendre les fonctionnalités de leurs classes parentes en ajoutant de nouvelles propriétés et méthodes.

Dans notre exemple précédent, `Vehicle` serait la classe parente de la classe `Car`, tandis que la classe `Car` serait la classe enfant de `Vehicle`.

Une classe parente peut avoir plusieurs classes enfants.

En JavaScript, on utilise le mot-clé `extends` pour implémenter l'héritage. Ce mot-clé indique qu'une classe est la classe enfant d'une autre classe.

Dans cet exemple, où l'on n'a que les premières lignes des définitions de classes, tu peux voir que la classe `Car` étend la classe `Vehicle`, donc `Car` hérite de `Vehicle`.

```js
class Vehicle {
  // Implementation of Vehicle...
}

class Car extends Vehicle {
  // Implementation of Car...
}
```

Disons que la classe `Vehicle` a deux propriétés : `brand` et `year`. Tu peux le voir dans le code mis à jour.

`Car` a une méthode appelée `honk`. Cependant, remarque que la classe `Car` n'a pas son propre constructeur. Voyons si elle hérite bien des propriétés.

```js
class Vehicle {
  constructor(brand, year) {
    this.brand = brand;
    this.year = year;
  }
}

class Car extends Vehicle {
  honk() {
    console.log("Honk! Honk!");
  }
}
```

Pour définir une instance de `Car`, tu devras passer deux arguments : `brand` et `year`. Dans ce cas, la marque est `freeCodeCamp Motors` et l'année est `2019`.

```js
let myCar = new Car("freeCodeCamp Motors", 2019);
```

Si tu essaies d'accéder à ces propriétés et d'appeler la méthode avec la notation point :

```js
console.log(myCar.brand);
console.log(myCar.year);
myCar.honk();
```

Voici l'exemple complet :

En effet, la sortie est correcte, donc ces propriétés et cette méthode sont définies dans l'instance `Car`, et tu viens de t'éviter beaucoup de répétition de code en héritant de ces propriétés de la classe `Vehicle`.

Dans cet exemple, la classe enfant n'avait aucune propriété supplémentaire. C'est pourquoi la classe n'avait pas de constructeur, seulement une méthode.

Si tu as besoin d'ajouter des propriétés supplémentaires, tu devras définir un constructeur.

Voyons un exemple.


```js
class Vehicle {
  constructor(brand, year) {
    this.brand = brand;
    this.year = year;
  }
}

class Car extends Vehicle {
  constructor(brand, year, numDoors) {
    super(brand, year);
    this.numDoors = numDoors;
  }
}
```

Cette fois, on ajoutera une propriété `numDoors` à la sous-classe `Car`.

Tu peux voir que cette classe a maintenant un constructeur dans le code mis à jour. Dans le constructeur, il y a un appel à `super()`, en passant les arguments `brand` et `year`.

`super()` invoque le constructeur de la superclasse, donc en utilisant `super(brand, year)` tu définiras essentiellement les propriétés de la superclasse dans la sous-classe. C'est une autre terminologie que tu peux utiliser : la superclasse est la classe parente et la sous-classe est la classe enfant.

Ensuite, la ligne `this.numDoors = numDoors` définit une nouvelle propriété qui appartient exclusivement à la classe `Car`, le nombre de portes (`numDoors`).

C'est une façon d'étendre la classe `Vehicle`, en ajoutant une propriété exclusive aux instances de `Car`.

C'est un exemple d'extensibilité, l'un des avantages fondamentaux de l'héritage.

Maintenant, si tu crées une instance de la classe `Car`, tu verras qu'elle a les trois propriétés : `brand`, `year` et `numDoors`. Tu devras aussi passer les arguments nécessaires lorsque tu créeras l'instance.

```js
let myCar = new Car("freeCodeCamp Motors", 2019, 4);
```

Si tu affiches les valeurs de ces propriétés avec `console.log()` :

```js
console.log(myCar.brand);
console.log(myCar.year);
console.log(myCar.numDoors);
```

Voici l'exemple complet :

:::interactive_editor

```js
class Vehicle {

    this.brand = brand;
    this.year = year;
  }

  }

```

:::

Les principaux avantages de l'héritage sont la réutilisabilité du code, la modularité, l'extensibilité et une meilleure structure du code.

En mettant en place une hiérarchie, tu peux réutiliser du code déjà écrit pour une classe parente dans la classe enfant, en évitant la répétition.

L'héritage favorise aussi la modularité en décomposant des systèmes complexes en composants plus simples dans la hiérarchie.

De plus, pouvoir étendre les fonctionnalités de la classe parente facilite l'adaptation aux exigences changeantes et l'ajout de nouvelles fonctionnalités plus tard dans le processus de développement.

Enfin, la structure hiérarchique peut rendre ton code plus facile à comprendre et à maintenir.

Voilà les fondamentaux de l'héritage. En comprenant comment fonctionne l'héritage, tu peux concevoir des programmes orientés objet bien structurés, maintenables et extensibles.
