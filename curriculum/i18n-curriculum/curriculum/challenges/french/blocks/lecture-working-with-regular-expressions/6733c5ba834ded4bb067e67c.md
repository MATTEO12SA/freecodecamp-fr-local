# --interactive--

Les modificateurs, souvent appelés « flags » (drapeaux), modifient le comportement d'une expression régulière. Rappelons notre exemple d'une leçon précédente :

:::interactive_editor

```js
const regex = /freeCodeCamp/;
console.log(regex.test("freeCodeCamp")); // true
console.log(regex.test("freeCodeCamp is great")); // true
console.log(regex.test("I love freeCodeCamp")); // true
console.log(regex.test("freecodecamp")); // false
console.log(regex.test("FREECODECAMP")); // false
console.log(regex.test("free")); // false
console.log(regex.test("code")); // false
console.log(regex.test("camp")); // false
```

:::

Si tu te souviens, les chaînes `freeCodeCamp` entièrement en minuscules et entièrement en majuscules n'ont pas réussi à correspondre au motif. C'est parce que, par défaut, les expressions régulières sont sensibles à la casse.

Mais et si nous pouvions dire à l'expression régulière d'ignorer la casse ? Eh bien, il y a un modificateur pour cela. Le flag `i` fait qu'une regex ignore la casse. Comment l'utiliser ? Les flags vont après la barre oblique fermante d'une expression régulière :

```js
const regex = /freeCodeCamp/i;
```

Remarque le changement de l'expression régulière à la première ligne. Maintenant, on peut vérifier comment cela change les choses :

:::interactive_editor

```js
const regex = /freeCodeCamp/i;

console.log(regex.test("freeCodeCamp")); // true
console.log(regex.test("freeCodeCamp is great")); // true
console.log(regex.test("I love freeCodeCamp")); // true
console.log(regex.test("freecodecamp")); // true
console.log(regex.test("FREECODECAMP")); // true
console.log(regex.test("free")); // false
console.log(regex.test("code")); // false
console.log(regex.test("camp")); // false
```

:::

Parce que notre expression régulière est maintenant insensible à la casse, les chaînes entièrement en minuscules et entièrement en majuscules ont « réussi » le test. Cela peut aussi fonctionner pour une chaîne avec un mélange aléatoire de majuscules et de minuscules :

:::interactive_editor

```js
const regex = /freeCodeCamp/i;

console.log(regex.test("dO yOu LoVe fReEcOdEcAmP?")); // true
```

:::

Il y a plusieurs autres flags que tu peux utiliser. Le flag `g`, ou modificateur global, permet à ton expression régulière de correspondre à un motif plus d'une fois.

Voyons comment cela affecte notre code. Tu remarqueras que nous avons gardé le flag `i` – une expression régulière peut utiliser plusieurs flags (autant que nécessaire) pour obtenir le comportement souhaité :

```js
const regex = /freeCodeCamp/gi;
```

Attends une seconde… qu'est-ce que c'est ? Il semblerait que le modificateur global fasse échouer certaines de nos chaînes qui devraient réussir :

:::interactive_editor

```js
const regex = /freeCodeCamp/gi;

console.log(regex.test("freeCodeCamp")); // true
console.log(regex.test("freeCodeCamp is great")); // false
console.log(regex.test("I love freeCodeCamp")); // true
console.log(regex.test("freecodecamp")); // false
console.log(regex.test("FREECODECAMP")); // true
console.log(regex.test("free")); // false
console.log(regex.test("code")); // false
console.log(regex.test("camp")); // false
```

:::

Pourquoi ? Eh bien, le modificateur global rend ton expression régulière à état (stateful). Cela signifie qu'elle garde la trace de l'endroit où elle a précédemment fait correspondre un motif. Donc quand elle correspond à la première chaîne `freeCodeCamp`, elle se souvient qu'elle a trouvé une correspondance commençant à l'indice `0`.

Nous la testons ensuite contre `freeCodeCamp is great`, mais cela ne commence pas à l'indice `0`. L'expression régulière « sait » qu'elle a déjà trouvé une correspondance à l'indice `0`, donc même si c'est une chaîne différente, elle repart de l'indice de fin de la correspondance.

`freeCodeCamp` fait `12` caractères de long, donc une correspondance à `0` se termine à l'indice `11`. La recherche reprendra à l'indice `12`. Et comme `is great` ne correspond pas à `freeCodeCamp`, elle renvoie `false`.

Ensuite, parce qu'elle échoue à trouver une correspondance, elle « perd » son état et recommence la correspondance suivante à `0`.

Si nous inversons nos logs pour qu'une chaîne avec la correspondance à `0` soit immédiatement suivie d'une chaîne qui a une correspondance après l'indice `11` :

:::interactive_editor

```js
const regex = /freeCodeCamp/gi;

console.log(regex.test("freeCodeCamp")); // true
console.log(regex.test("I loooooooove freeCodeCamp")); // true
```

:::

Quand une expression régulière est globale, elle obtient une nouvelle propriété appelée `lastIndex`. En reprenant notre code précédent, voyons comment cette propriété fonctionne :

:::interactive_editor

```js
const regex = /freeCodeCamp/gi;

console.log(regex.lastIndex); // 0
console.log(regex.test("freeCodeCamp")); // true
console.log(regex.lastIndex); // 12
console.log(regex.test("freeCodeCamp is great")); // false
console.log(regex.lastIndex); // 0
console.log(regex.test("I love freeCodeCamp")); // true
console.log(regex.lastIndex); // 19
console.log(regex.test("freecodecamp")); // false
console.log(regex.lastIndex); // 0
console.log(regex.test("FREECODECAMP")); // true
console.log(regex.lastIndex); // 12
console.log(regex.test("free")); // false
console.log(regex.lastIndex); // 0
console.log(regex.test("code")); // false
console.log(regex.lastIndex); // 0
console.log(regex.test("camp")); // false
```

:::

En regardant cet exemple, tu peux voir comment l'état de l'expression régulière change à chaque appel de test en utilisant `lastIndex` pour suivre ses correspondances précédentes.

Le flag global est parfait quand tu as besoin d'obtenir plusieurs correspondances depuis une seule chaîne. Mais si tu testes plusieurs chaînes avec la même expression régulière, il vaut mieux laisser le flag `g` de côté.

Avant d'apprendre le prochain flag, tu dois apprendre les ancres. L'ancre caret (`^`), au début de l'expression régulière, dit « correspondre au début de la chaîne » :

```js
const start = /^freecodecamp/i;
```

L'ancre dollar (`$`), à la fin de l'expression régulière, dit « correspondre à la fin de la chaîne » :

```js
const end = /freecodecamp$/i;
```

Prends un moment pour comparer les sorties à droite :

:::interactive_editor

```js
const start = /^freecodecamp/i;
const end = /freecodecamp$/i;
console.log(start.test("freecodecamp")); // true
console.log(end.test("freecodecamp")); // true
console.log(start.test("freecodecamp is great")); // true
console.log(end.test("freecodecamp is great")); // false
console.log(start.test("i love freecodecamp")); // false
console.log(end.test("i love freecodecamp")); // true
console.log(start.test("have met freecodecamp's founder")); // false
console.log(end.test("have met freecodecamp's founder")); // false
```

:::

Tu vois comment l'ancre de début ne correspond qu'au début de la chaîne, et l'ancre de fin uniquement à la fin de la chaîne ? Mais qu'en est-il de la correspondance sur plusieurs lignes ? Regardons cela :

:::interactive_editor

```js
const start = /^freecodecamp/i;
const end = /freecodecamp$/i;
const string = `I really love
freecodecamp
it's my favorite`;
console.log(start.test(string)); // false
console.log(end.test(string)); // false
```

:::

Même si `freecodecamp` est là sur sa propre ligne, les deux tests échouent. C'est parce que, par défaut, les ancres cherchent le début et la fin de la chaîne entière.

Mais tu peux faire gérer plusieurs lignes à une regex avec le flag `m`, ou le modificateur multi-ligne. Ajoutons-le à nos expressions régulières pour voir ce que l'on obtient :

:::interactive_editor

```js
const start = /^freecodecamp/im;
const end = /freecodecamp$/im;
const string = `I really love
freecodecamp
it's my favorite`;
console.log(start.test(string)); // true
console.log(end.test(string)); // true
```

:::

Maintenant elles correspondent toutes les deux ! Parce que `freecodecamp` est entièrement sur sa propre ligne, l'ancre de début correspond au début de cette ligne, et l'ancre de fin correspond à la fin de cette ligne.

Enfin, tu as le flag `d`, ou modificateur d'indices. Souviens-toi que le flag `i` sert à l'insensibilité à la casse, donc le modificateur d'indices avait besoin d'un flag différent.

Le flag `d` étend les informations que tu obtiens dans un objet de correspondance. Ajoutons-le à notre expression régulière :

```js
const regex = /freecodecamp/di;
const string = "we love freecodecamp isn't freecodecamp great?";
console.log(string.match(regex));
```

Et le résultat est :

```js
// [
//   'freecodecamp',
//   index: 8,
//   input: "we love freecodecamp isn't freecodecamp great?",
//   groups: undefined,
//   indices: [
//     0: [8, 20],
//     groups: undefined
//   ]
// ]
```

Notre objet de correspondance obtient une nouvelle propriété `indices` ! Cette propriété est un tableau de deux nombres, le premier étant l'indice dans la chaîne d'origine où la correspondance commence, et le second étant l'indice après la fin de la correspondance. Ce tableau a aussi une propriété `groups` supplémentaire, qui sert aussi aux groupes de capture nommés.

Il y a quelques autres flags que tu dois savoir disponibles, mais qui sont moins courants dans le code typique.

Le premier est le modificateur unicode, ou flag `u`. Il étend les fonctionnalités d'une expression régulière pour lui permettre de correspondre à des caractères unicode spéciaux.

Tu en apprendras plus sur les classes de caractères dans une leçon future, mais le flag `u` te donne accès à des classes spéciales comme `Extended_Pictographic` pour correspondre à la plupart des emoji :

:::interactive_editor

```js
const regex = /🍎/u;

const str = "I have an apple 🍎";
console.log(regex.test(str)); // true
```

:::

Il y a aussi un flag `v`, qui étend encore davantage les fonctionnalités de la correspondance unicode.

Le deuxième est le modificateur sticky, ou flag `y`. Le modificateur sticky se comporte de façon très similaire au modificateur global, mais avec quelques exceptions.

La plus importante est qu'une expression régulière globale partira de `lastIndex` et cherchera dans tout le reste de la chaîne une autre correspondance, mais une expression régulière sticky renverra `null` et réinitialisera `lastIndex` à `0` s'il n'y a pas immédiatement une correspondance au précédent `lastIndex`.

Et le dernier est le modificateur single-line, ou flag `s`. Souviens-toi que le modificateur multi-ligne permet aux ancres de début et de fin de correspondre au début et à la fin d'une ligne, au lieu de la chaîne entière.

Le modificateur single-line permet à un caractère joker, représenté par un point (`.`) en regex, de correspondre aux sauts de ligne – traitant efficacement la chaîne comme une seule ligne de texte.

Il y a pas mal de ces modificateurs, mais les flags `i` et `g` sont ceux que tu utiliseras le plus fréquemment, et les plus importants à retenir.
