# --description--

Apprenons comment faire correspondre ou remplacer toutes les occurrences d'un motif dans une chaîne.

Tu as déjà appris les méthodes `replace()` et `match()`, ainsi que le modificateur global `g`. Tu peux maintenant combiner ces connaissances pour gérer tous les motifs dans une chaîne. Rappelons notre code de correspondance d'origine :

```js
const regex = /freeCodeCamp/;
const match = "freeCodeCamp".match(regex);
console.log(match);
```

Et notre objet de correspondance résultant :

```js
// [
//   'freeCodeCamp',
//   index: 0,
//   input: 'freeCodeCamp',
//   groups: undefined
// ]
```

Mais et si nous avons une chaîne avec plusieurs occurrences de `freecodecamp` à faire correspondre ? Regardons comment `match()` se comporte dans ce cas. On ajoutera aussi notre ancien exemple `replace()`, juste pour comparer :

```js
const regex = /freecodecamp/;
const str = "freecodecamp is the best we love freecodecamp";
const matched = str.match(regex);
const replaced = str.replace(regex, "freeCodeCamp");
console.log(matched);
console.log(replaced);
```

Et le résultat est celui-ci :

```js
// [
//   'freecodecamp',
//   index: 0,
//   input: 'freecodecamp is the best we love freecodecamp',
//   groups: undefined
// ]
// freeCodeCamp is the best we love freecodecamp
```

Oh non ! `match()` n'a renvoyé que la première correspondance, et `replace()` n'a remplacé que la première correspondance. C'est parce que, par défaut, `match()` et `replace()` n'opèrent que sur la première occurrence du motif.

Heureusement, tu peux éviter cela en utilisant le modificateur global sur ton expression régulière. Ajoutons-le à la nôtre :

```js
const regex = /freecodecamp/g;
const str = "freecodecamp is the best we love freecodecamp";
const matched = str.match(regex);
const replaced = str.replace(regex, "freeCodeCamp");
console.log(matched);
console.log(replaced);
```

Et confirmons le résultat :

```js
// [ 'freecodecamp', 'freecodecamp' ]
// freeCodeCamp is the best we love freeCodeCamp
```

Ça a marché ! Notre appel replace a remplacé toutes les chaînes `freecodecamp` en minuscules, et notre méthode `match()` a trouvé les deux.

Ce qui est intéressant ici, c'est que lorsque tu utilises le modificateur global avec `match()`, tu perds les informations supplémentaires sur les groupes de capture et les indices de chaîne qui se trouveraient dans le tableau de correspondance.

Heureusement, la mise à jour ECMAScript de 2019 nous a apporté deux nouvelles méthodes : `matchAll()` et `replaceAll()`. Comme leurs homologues au singulier, ces méthodes acceptent une chaîne ou une expression régulière, et `replaceAll()` accepte aussi un second argument comme chaîne de remplacement.

Mais contrairement aux méthodes précédentes, `replaceAll()` et `matchAll()` lèveront une erreur si tu leur donnes une expression régulière sans le modificateur global. Mettons à jour notre code pour utiliser ces nouvelles méthodes :

```js
const pattern = "freecodecamp";
const str = "freecodecamp is the best we love freecodecamp";
const matched = str.matchAll(pattern);
const replaced = str.replaceAll(pattern, "freeCodeCamp");
console.log(matched);
console.log(replaced);
```

Et notre résultat :

```js
// {}
// freeCodeCamp is the best we love freeCodeCamp
```

Bonne nouvelle ! Notre `replaceAll()` a fonctionné exactement comme on le voulait – il a remplacé toutes les occurrences de `freecodecamp` en minuscules par la version correctement en camelCase.

Mais qu'est-ce que cet objet vide ? Eh bien, `matchAll()` renvoie un type spécial d'objet appelé `Iterator`, que la console freeCodeCamp n'est pas préparée à gérer.

Si on regarde dans la console du navigateur, l'`Iterator` a une méthode `next()`, que l'on peut appeler pour obtenir la valeur suivante :

```js
// RegExpStringIterator {  }
//  <prototype>: RegExp String Iterator {
//    next: ƒ next(),
//    Symbol(Symbol.toStringTag): "RegExp String Iterator"
//    <prototype>: Object { ... }
//  }
```

Allons-y et appelons `matched.next()`, et affichons le résultat :

```js
// {
//   "done": false,
//   "value": [
//     0: "freecodecamp"
//     groups: undefined
//     index: 0
//     input: "freecodecamp is the best we love freecodecamp"
//   ]
// }
```

Voilà notre tableau de correspondance ! `next()` nous donne un objet avec deux valeurs : `done`, qui est `false` quand il reste des éléments disponibles dans l'itérateur, et `value` qui est la valeur que l'on vient de parcourir. Donc, si on l'appelle encore une fois :

```js
const regex = /freecodecamp/g;
const str = "freecodecamp is the best we love freecodecamp";
const matched = str.matchAll(regex);
const replaced = str.replaceAll(regex, "freeCodeCamp");
console.log(matched);
console.log(replaced);
console.log(matched.next());
console.log(matched.next());
```

```js
// {
//   "done": false,
//   "value": Array [ "freecodecamp"]
// }
//
// {
//   "done": false,
//   "value": Array [ "freecodecamp"]
// }
```

Attends, pourquoi dit-il que `done` est encore `false` ? Il ne devrait y avoir que deux correspondances dans le tableau, non ? Appelons-le une troisième fois et voyons ce que l'on obtient :

```js
// {
//   "done": false,
//   "value": Array [ "freecodecamp"]
// }
//
// {
//   "done": false,
//   "value": Array [ "freecodecamp"]
// }
//
// {
//   "done": true,
//   "value": undefined
// }
```

`done` est enfin `true`, mais pourquoi cette valeur est-elle `undefined` ? Eh bien, il s'avère que l'itérateur de `matchAll()` est paresseux (lazy). Il ne trouve pas toutes tes correspondances d'un coup. Il ne trouve une correspondance que lorsque tu le lui demandes en appelant `next()`.

Tant qu'il trouve une correspondance, il n'est pas `done`. Une fois qu'il échoue à trouver une correspondance et ramène `undefined`, il est `done`. Cela peut sembler peu pratique, mais cela peut être très utile quand ton expression régulière est coûteuse en calcul.

Si ton exemple l'est moins, comme le nôtre, tu peux ignorer cette fonctionnalité et extraire toutes les correspondances d'un coup en le convertissant en tableau. Cela s'obtient en appelant `Array.from()` et en passant ton itérateur comme argument.

Mettons à jour notre code pour utiliser cela – on va aussi nettoyer nos appels `replaceAll` puisque l'on sait que ça marche :

```js
const regex = /freecodecamp/g;
const str = "freecodecamp is the best we love freecodecamp";
const matched = str.matchAll(regex);
console.log(Array.from(matched));
```

Et on obtient enfin notre tableau de correspondances :

```js
// [
//   'freecodecamp',
//   index: 0,
//   input: 'freecodecamp is the best we love freecodecamp',
//   groups: undefined
// ]
//
// [
//   'freecodecamp',
//   index: 33,
//   input: 'freecodecamp is the best we love freecodecamp',
//   groups: undefined
// ]
```

Ces méthodes puissantes peuvent t'aider à manipuler et extraire des données depuis des chaînes sans sacrifier les performances ni la lisibilité.
