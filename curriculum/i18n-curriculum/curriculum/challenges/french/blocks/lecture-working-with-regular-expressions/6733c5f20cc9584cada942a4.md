# --interactive--

Un groupe de capture te permet de « capturer » une portion de la chaîne correspondante pour l'utiliser comme tu en as besoin. Les groupes de capture sont définis par des parenthèses contenant le motif à capturer, sans caractères avant comme un lookahead.

Capturons le `code` de notre expression régulière `freeCodeCamp`. Pour cela, on enfermera `code` entre parenthèses et on le définira comme un groupe de capture :

```js
const regex = /free(code)camp/i;
```

Pour confirmer le comportement, on peut le tester contre une chaîne `freecodecamp` :

:::interactive_editor

```js
const regex = /free(code)camp/i;
console.log(regex.test("freecodecamp")); // true
```

:::

Mais cela n'utilise pas réellement notre groupe capturé. Au lieu de cela, regardons le résultat de l'utilisation de `match` :

```js
const regex = /free(code)camp/i;
console.log("freecodecamp".match(regex));
// [
//   'freecodecamp',
//   'code', <--
//   index: 0,
//   input: 'freecodecamp',
//   groups: undefined
// ]
```

Ici on peut voir que notre tableau `match` a un second élément, qui est la portion de la chaîne capturée par notre groupe de capture.

Remarque que le groupe de capture correspond au motif exact `code`, alors qu'une classe de caractères correspondrait à un seul caractère de la liste `c`, `o`, `d`, et `e`.

Mais comment l'utiliser concrètement ? Eh bien, les groupes de capture sont souvent utilisés lors du remplacement du contenu d'une chaîne. Mettons en place du code pour cela. On va transformer `freecodecamp` en `paidcodeworld` :

:::interactive_editor

```js
const regex = /free(code)camp/i;
console.log("freecodecamp".replace(regex, "paidcodeworld"));
```

:::

Cela fonctionne tout seul, mais et si on ne savait pas combien de `o` il y avait dans `code` ? S'il nous faut un quantificateur pour un ou plusieurs `o` :

:::interactive_editor

```js
const regex = /free(co+de)camp/i;
console.log("freecoooooooodecamp".replace(regex, "paidcodeworld"));
```

:::

On obtient `paidcodeworld` comme résultat. On veut préserver le nombre de `o`, donc on doit réutiliser ce qui a été capturé par l'expression régulière.

C'est là qu'intervient une backreference. Au lieu de coder en dur la portion `code` de notre chaîne de remplacement, on peut référencer directement le groupe capturé.

Dans un appel `replace`, tu obtiens une backreference en utilisant un signe dollar (`$`) suivi du numéro du groupe de capture à utiliser. Dans notre cas, ce serait `$1`, puisque `code` est capturé dans le premier groupe de capture :

:::interactive_editor

```js
const regex = /free(co+de)camp/i;
console.log("freecoooooooodecamp".replace(regex, "paid$1world")); // paidcoooooooodeworld
```

:::

On a maintenant réussi à préserver un nombre inconnu de caractères `o` en convertissant `freecodecamp` en `paidcodeworld`. Mais les backreferences ne sont pas limitées à l'appel replace. Tu peux en fait les utiliser directement dans une expression régulière.

Cela te permettrait de faire correspondre un motif précédemment capturé plus loin dans l'expression régulière.

Disons que l'on veut faire correspondre `freecodecamp` deux fois, avec le même nombre de `o`, mais n'importe où dans la chaîne.

D'abord, on doit les séparer avec notre caractère joker, et autoriser n'importe quel nombre de caractères à correspondre à ce joker :

```js
const regex = /free(co+de)camp.*free(co+de)camp/i;
```

Cette expression actuelle ne garantira cependant pas que le nombre de caractères `o` soit le même. Pour y arriver, on doit remplacer le second groupe de capture par une référence au premier.

À l'intérieur d'une expression régulière, une backreference est notée avec une barre oblique inversée suivie du numéro du groupe de capture :

:::interactive_editor

```js
const regex = /free(co+de)camp.*free\1camp/i;
console.log(regex.test("freecooooodecamp is great i love freecooooodecamp")); // true
console.log(regex.test("freecooooodecamp is great i love freecodecamp")); // false
```

:::

Et avec cela, on peut voir qu'une chaîne avec le bon nombre de `o` correspond, tandis qu'une chaîne avec deux nombres différents de `o` ne correspond pas.

Cette syntaxe est géniale, mais peut rapidement devenir confuse quand tu références plusieurs groupes de capture. Heureusement, au lieu d'utiliser des numéros, tu peux donner des noms à tes groupes.

Pour définir un groupe de capture nommé, tu ajoutes un point d'interrogation (`?`) suivi du nom enfermé entre signes inférieur et supérieur au début du groupe. Nommons notre groupe de capture `code` :

```js
const regex = /free(?<code>co+de)camp.*free\1camp/i;
```

Maintenant on peut mettre à jour notre backreference dans l'expression régulière pour se référer à ce groupe. Une backreference nommée commence par une barre oblique inversée suivie de la lettre `k` en JavaScript. Ensuite tu ajoutes le nom, à nouveau enfermé entre signes inférieur (`<`) et supérieur (`>`). Regardons cela :

```js
const regex = /free(?<code>co+de)camp.*free\k<code>camp/i;
```

Maintenant si on vérifie notre appel `test()`, on peut voir que l'on réussit toujours :

:::interactive_editor

```js
const regex = /free(?<code>co+de)camp.*free\k<code>camp/i;
console.log(regex.test("freecooooodecamp is freecooooodecamp")); // true
```

:::

Pour utiliser notre groupe de capture nommé dans un appel `replace()`, on insérerait un signe dollar dans la chaîne, suivi du nom enfermé entre signes inférieur et supérieur :

:::interactive_editor

```js
const regex = /free(?<code>co+de)camp/i;
console.log("freecooooodecamp".replace(regex, "paid$<code>camp")); // paidcooooodecamp
```

:::

Enfin, parfois tu veux créer un groupe de caractères, mais tu n'as pas besoin du résultat capturé.

Disons que l'on veut faire correspondre soit `freecodecamp` soit `freecandycamp`. Tu pourrais créer deux motifs séparés par une assertion OR :

```js
const regex = /freecodecamp|freecandycamp/i;
```

Mais cela peut devenir assez long pour des expressions régulières à plus grande échelle. Au lieu de cela, tu peux créer un groupe non capturant autour des caractères que tu dois mettre en OR :

```js
const regex = /free(?:code|candy)camp/i;
```

Un groupe non capturant ne stocke pas la correspondance `code|candy` séparément en mémoire. Mais il peut être utile pour créer des motifs alternatifs sans sacrifier la lisibilité ni les performances.
