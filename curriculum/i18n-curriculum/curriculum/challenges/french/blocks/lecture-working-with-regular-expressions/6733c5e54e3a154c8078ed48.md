# --interactive--

Apprenons les quantificateurs dans les expressions régulières.

Considère un scénario où tu veux faire correspondre un code d'identification à quatre chiffres. Tu sais que tu peux utiliser la classe de caractères `\d`, donc tu pourrais l'écrire quatre fois. Et pour éviter tout caractère parasite, tu inclurais les ancres de début et de fin :

```js
const regex = /^\d\d\d\d$/;
```

Et cela fonctionne – cela correspondra à quatre caractères numériques. Mais plutôt que d'avoir à écrire la même classe plusieurs fois, tu peux lui donner un quantificateur.

Les quantificateurs sont définis par des accolades contenant un ou deux nombres. Utilisons un quantificateur dans notre motif :

```js
const regex = /^\d{4}$/;
```

Remarque que notre quantificateur ne contient que le nombre `4`. Cette syntaxe signifie « faire correspondre le caractère précédent exactement quatre fois ». Voyons comment cela se comporte :

:::interactive_editor

```js
const regex = /^\d{4}$/;
console.log(regex.test("123")); // false
console.log(regex.test("1234")); // true
console.log(regex.test("12345")); // false
console.log(regex.test("123456")); // false
console.log(regex.test("1234567")); // false
```

:::

Le motif ne correspond qu'à la chaîne avec exactement quatre chiffres, parce que nous avons utilisé les ancres et que notre quantificateur n'autorise qu'exactement quatre chiffres. Mais peut-être que le code d'identification n'a besoin que d'un minimum de quatre chiffres.

Pour autoriser quatre chiffres ou plus, ajoute une virgule après le nombre dans ton quantificateur :

```js
const regex = /^\d{4,}$/;
```

Maintenant, notre syntaxe permet au motif de correspondre à quatre chiffres ou plus. Testons-le :

:::interactive_editor

```js
const regex = /^\d{4,}$/;
console.log(regex.test("123")); // false
console.log(regex.test("1234")); // true
console.log(regex.test("12345")); // true
console.log(regex.test("123456")); // true
console.log(regex.test("1234567")); // true
```

:::

Un identifiant à sept chiffres est plutôt long. Ces identifiants devraient avoir un maximum de 6 chiffres, et un minimum de 4 chiffres. Pour y arriver, tu peux ajouter un second nombre à ton quantificateur après la virgule :

```js
const regex = /^\d{4,6}$/;
```

Et maintenant notre motif ne correspond plus à l'identifiant à sept chiffres, parce qu'il est supérieur à notre maximum de six chiffres.

:::interactive_editor

```js
const regex = /^\d{4,6}$/;
console.log(regex.test("123")); // false
console.log(regex.test("1234")); // true
console.log(regex.test("12345")); // true
console.log(regex.test("123456")); // true
console.log(regex.test("1234567")); // false
```

:::

Note que tu ne peux pas utiliser cette syntaxe pour définir un maximum seul – tu dois toujours définir un minimum. Mais si tu définis le minimum à `1`, tu peux effectivement obtenir le même résultat.

Nous avons reçu des exigences mises à jour de nos utilisateurs. Les identifiants peuvent maintenant optionnellement commencer par une lettre. On connaît déjà la classe de caractères pour cela, alors ajoutons-la à notre expression régulière :

```js
const regex = /^[a-zA-Z]\d{4,6}$/;
```

Mais maintenant on impose la présence d'une lettre. Comment la rendre optionnelle ?

Tu pourrais utiliser la syntaxe de quantificateur avec `0` comme minimum et `1` comme maximum :

```js
const regex = /^[a-zA-Z]{0,1}\d{4,6}$/;
```

Mais il y a en fait un quantificateur abrégé spécial pour un seul caractère optionnel – le point d'interrogation (`?`). Remplaçons notre quantificateur par le point d'interrogation :

```js
const regex = /^[a-zA-Z]?\d{4,6}$/;
```

On devrait valider le résultat :

:::interactive_editor

```js
const regex = /^[a-zA-Z]?\d{4,6}$/;
console.log(regex.test("123")); // false
console.log(regex.test("a1234")); // true
console.log(regex.test("12345")); // true
console.log(regex.test("az12345")); // false
console.log(regex.test("X123456")); // true
console.log(regex.test("1234567")); // false
```

:::

Notre motif autorise maintenant une seule lettre optionnelle, suivie de quatre à six chiffres.

Malheureusement, on vient de réaliser qu'on a mal lu les exigences. On doit autoriser n'importe quel nombre de lettres avant les chiffres. On peut utiliser notre quantificateur avec un minimum de `0` et sans maximum défini :

```js
const regex = /^[a-zA-Z]{0,}\d{4,6}$/;
```

Mais notre motif redevient long. Heureusement, il y a une autre abréviation pour « faire correspondre le caractère précédent zéro fois ou plus » – le symbole astérisque (`*`). Remplaçons notre quantificateur par celui-ci dans le motif, et testons-le :

:::interactive_editor

```js
const regex = /^[a-zA-Z]*\d{4,6}$/;
console.log(regex.test("123")); // false
console.log(regex.test("a1234")); // true
console.log(regex.test("12345")); // true
console.log(regex.test("az12345")); // true
console.log(regex.test("X123456")); // true
console.log(regex.test("1234567")); // false
```

:::

Maintenant on fait correspondre avec succès n'importe quel identifiant avec zéro lettre ou plus suivi de quatre à six chiffres. Mais il s'avère que cela fait planter notre système – on doit en fait exiger au moins une lettre.

Encore une fois, on pourrait utiliser un quantificateur avec un minimum de un et sans maximum défini, ou on pourrait utiliser encore une autre syntaxe spéciale – le symbole plus (`+`) :

:::interactive_editor

```js
const regex = /^[a-zA-Z]+\d{4,6}$/;
console.log(regex.test("123")); // false
console.log(regex.test("a1234")); // true
console.log(regex.test("12345")); // false
console.log(regex.test("az12345")); // true
console.log(regex.test("X123456")); // true
console.log(regex.test("1234567")); // false
```

:::

Maintenant les identifiants qui ne commencent pas par au moins une lettre échouent, quel que soit le nombre de chiffres.

Tu peux utiliser les quantificateurs pour grandement améliorer la brièveté et la lisibilité de tes expressions régulières.
