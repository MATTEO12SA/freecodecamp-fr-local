# --description--

Déboguer tes programmes JavaScript va au-delà de l'utilisation d'instructions `console.log()` dans ton code. Il existe des techniques plus avancées qui rendent le débogage facile une fois que tu t'y es habitué. Passons en revue ces techniques plus avancées pour que tu sois ravi de déboguer ton programme JavaScript quand tu rencontreras des erreurs.

Le premier concept que nous allons examiner est l'utilisation des points d'arrêt. Les points d'arrêt te permettent de mettre en pause l'exécution de ton code à une ligne précise de ton choix. Après la pause, tu peux inspecter les variables, évaluer des expressions et examiner la pile d'appels.

Pour ajouter un point d'arrêt à n'importe quelle ligne de ton code dans le navigateur Chrome, ouvre les outils de développement et va dans l'onglet Sources, ouvre le fichier JavaScript que tu veux déboguer, et clique sur un numéro de ligne pour définir un point d'arrêt.

Une fois que l'exécution atteint le point d'arrêt et s'arrête, tu peux avancer pas à pas dans le code en utilisant les icônes en haut à droite. Tu peux aussi ajouter un point d'arrêt conditionnel en faisant un clic droit sur une ligne et en sélectionnant "Add conditional breakpoint…"

Passons maintenant aux expressions de surveillance. Les expressions de surveillance te permettent de suivre les valeurs de variables ou d'expressions pendant que le code s'exécute, même si elles sont hors de la portée actuelle.

Pour ajouter une expression de surveillance, va dans l'onglet Sources des outils de développement, cherche le panneau de surveillance à droite et clique sur l'icône plus (`+`) pour l'ajouter.

Le prochain concept que nous allons examiner est le profilage. Le profilage t'aide à identifier les goulots d'étranglement de performance en te permettant de capturer des captures d'écran et d'enregistrer l'utilisation du processeur, les appels de fonction et le temps d'exécution.

Pour le faire sur ton code, ouvre l'onglet Performance, clique sur enregistrer, et effectue l'action que tu veux profiler. Une fois que tu as terminé cette action, arrête l'enregistrement pour analyser les résultats.

Cela peut être utile si ton application rame pendant certaines opérations. Avec le profileur, tu peux voir quelle fonction ou quelle autre donnée dans le code consomme le plus de ressources.

Passons maintenant à l'inspection des requêtes réseau. Inspecter les requêtes réseau peut t'aider à déboguer des problèmes liés aux requêtes API comme des erreurs de paramètres, d'adresse ou de serveur.

Pour utiliser l'onglet Network pour le débogage, ouvre les outils de développement et va dans l'onglet Network, puis clique sur les requêtes individuelles pour voir des détails comme les en-têtes, les réponses et les charges utiles.

Pour la dernière partie de cette leçon, nous nous concentrerons sur `console.table` et `console.dir`.

`console.table()` affiche des données tabulaires sous forme de tableau dans la console. Elle prend un argument obligatoire, qui doit être un tableau ou un objet, et un argument optionnel pour spécifier quelles propriétés ou colonnes afficher.

`console.dir()` de son côté te permet d'afficher une liste interactive des propriétés d'un objet JavaScript spécifié. Elle produit une liste hiérarchique qui peut être développée pour voir toutes les propriétés imbriquées.

Maintenant que tu disposes d'une boîte à outils élargie de techniques de débogage, mets ces nouvelles compétences à l'épreuve dans tes prochains projets JavaScript. En appliquant ces stratégies, tu pourras identifier et résoudre les problèmes plus efficacement, ce qui mènera à un code plus propre et plus fiable.
