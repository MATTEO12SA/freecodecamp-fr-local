# --description--

Apprenons le JavaScript asynchrone. Les événements asynchrones se produisent à des moments différents, indépendamment les uns des autres.

En développement logiciel, « asynchrone » désigne des tâches qui s'exécutent en arrière-plan, indépendamment du flux principal du programme. Le grand avantage des processus asynchrones est qu'ils ne bloquent pas l'exécution du programme principal.

C'est particulièrement utile pour les tâches longues, comme récupérer des données d'un serveur distant, traiter de gros fichiers, gérer les saisies utilisateur, et effectuer des calculs complexes. C'est ce qu'on appelle la programmation asynchrone.

Cette approche contraste avec la technique synchrone traditionnelle avec laquelle tu as travaillé jusqu'ici. Quand tu écris plusieurs lignes de code, tu peux généralement prédire ce qui se passera et quand. La première ligne s'exécute, puis la deuxième, et ainsi de suite dans l'ordre où tu les écris.

Dans cet exemple, la première ligne où tu définis la variable s'exécute d'abord, puis la deuxième, et enfin la troisième où la chaîne est affichée dans la console :

```js
const topic = "JavaScript";
const learning = `I'm learning ${topic}!`;
console.log(learning);
```

Tout est séquentiel et prévisible. Chaque ligne se termine avant que la suivante ne commence. Ce type de programme JavaScript est dit monothread (single-threaded).

Le concept de threads est très important. Un thread est une unité d'exécution au sein d'un processus. C'est comme un flux de contrôle distinct dans le programme.

En programmation synchrone, les threads s'exécutent séquentiellement, l'un après l'autre. Si un thread est bloqué, par exemple en attendant une saisie utilisateur, tout le processus est bloqué jusqu'à la fin du thread.

En programmation asynchrone, les threads peuvent s'exécuter en concurrence, plusieurs à la fois. Ainsi, le programme peut continuer plusieurs tâches simultanément sans rendre le programme principal non réactif, même si l'un des threads est bloqué.

La programmation asynchrone implique souvent des callbacks, des promesses, ou async/await pour gérer les opérations non bloquantes.

Comme tu l'as appris dans les leçons précédentes, un callback est une fonction que tu passes à une autre pour qu'elle soit appelée plus tard. Les gestionnaires d'événements sont un type particulier de callback que tu as déjà utilisé. Ils étaient le moyen le plus courant d'implémenter des fonctions asynchrones en JavaScript. Cependant, si la fonction callback prend aussi d'autres callbacks, le code et la logique peuvent vite devenir très compliqués.

Actuellement, la technique la plus utilisée pour la programmation asynchrone en JavaScript est la promesse. Une `Promise` est un objet qui représente l'achèvement éventuel (ou l'échec) d'un processus asynchrone et sa valeur.

La valeur d'une promesse n'est pas connue à sa création. Elle n'est connue que lorsque le processus asynchrone est terminé. Par exemple, récupérer des données d'une API distante pour ton application web peut prendre du temps. Pendant ce temps, tu veux que tes utilisateurs aient une bonne expérience, n'est-ce pas ?

Pour cela, tu pourrais créer une promesse afin de garder l'interface utilisateur active et interactive pendant que le processus asynchrone tourne. Quand le processus est terminé, la promesse contiendra les données renvoyées par l'API, pour que l'application puisse les traiter ou les afficher correctement dès qu'elles sont disponibles.

La programmation asynchrone est un outil puissant pour créer des applications JavaScript efficaces. En comprenant les différences entre programmation synchrone et asynchrone, tu peux choisir la bonne approche pour ton application et écrire un code plus efficace.
