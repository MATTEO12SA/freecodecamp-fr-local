# --interactive--

Dans les leçons précédentes, tu as appris la programmation asynchrone qui permet à d'autre code de s'exécuter pendant qu'on attend des tâches longues, comme récupérer des données d'un serveur, lire un fichier, etc.

`async`/`await`, construit sur les promesses, facilite l'écriture et la lecture du code asynchrone. Quand tu mets le mot-clé `async` avant une fonction, cela signifie que cette fonction renverra toujours une `Promise`. Le mot-clé `await`, qui te permet d'attendre qu'une `Promise` se résolve avant de passer à la ligne suivante, ne peut être utilisé que dans des fonctions asynchrones ou au niveau supérieur des modules. Voici un exemple pour illustrer comment `async`/`await` fonctionne :

:::interactive_editor

```js
async function delayedGreeting(name) {
  console.log("A Messenger entered the chat...");
  await new Promise(resolve => setTimeout(resolve, 2000));
  console.log(`Hello, ${name}!`);
}

delayedGreeting("Alice");
console.log("First Printed Message!");
```

:::

Dans ce code, on définit une fonction `async` appelée `delayedGreeting`. À l'intérieur, on utilise `await` pour mettre en pause l'exécution pendant 2 secondes. Après le délai, elle affiche une salutation.

Quand on appelle cette fonction, tu verras `First Printed Message!` apparaître avant la salutation. C'est parce que la fonction est asynchrone — elle ne bloque pas le reste du code.

Un des plus grands avantages de `async`/`await` est la gestion des erreurs. Avec les promesses, on devait souvent utiliser la méthode `.catch()`. Avec `async`/`await`, on peut utiliser des blocs `try`/`catch`. Voici un exemple :

```js
async function fetchUserData() {
  try {
    let response = await fetch(`https://api.example.com/users`);
    let userData = await response.json();
    console.log(userData);
  } catch (error) {
    console.log("Error fetching user data:", error);
  }
}

fetchUserData();
```

Dans cet exemple, on utilise `async`/`await` pour récupérer des données utilisateur depuis une API. Le mot-clé `await` est utilisé deux fois : une fois pour attendre la fin de l'opération fetch, et encore pour attendre la fin de l'analyse JSON. Si une erreur survient pendant ce processus, elle sera attrapée dans le bloc `catch`.
