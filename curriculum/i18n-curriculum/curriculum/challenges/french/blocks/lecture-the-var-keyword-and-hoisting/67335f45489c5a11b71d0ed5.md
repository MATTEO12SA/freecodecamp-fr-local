# --interactive--

Le hoisting est un comportement en JavaScript qui perturbe souvent les débutants, mais le comprendre peut t'aider à éviter des bugs subtils dans ton code. En termes simples, le hoisting est le comportement par défaut de JavaScript qui consiste à déplacer les déclarations en haut de leurs portées respectives pendant la phase de compilation, avant l'exécution du code.

Pour comprendre le hoisting, il est important de savoir que JavaScript s'exécute en deux phases : la phase de compilation et la phase d'exécution. Pendant la phase de compilation, le moteur JavaScript parcourt ton code et réserve de l'espace mémoire pour les variables et les fonctions. C'est là qu'intervient le hoisting.

Commençons par le hoisting des variables : lorsque tu déclares une variable en utilisant le mot-clé `var`, JavaScript remonte la déclaration en haut de sa portée. Cependant, il est crucial de noter que seule la déclaration est hoistée, pas l'initialisation. Cela signifie que tu peux utiliser une variable dans ton code avant de l'avoir déclarée, mais sa valeur sera `undefined` jusqu'à ce que tu lui assignes réellement une valeur.

:::interactive_editor

```js
console.log(x); // undefined
var x = 5;
console.log(x); // 5
```

:::

Dans ce code, même si nous utilisons `x` avant de le déclarer, nous n'obtenons pas d'erreur, mais plutôt `undefined`. C'est parce que JavaScript remonte la déclaration `var x` en haut de sa portée, mais pas l'initialisation `x = 5`. C'est comme si le code était réécrit ainsi :

:::interactive_editor

```js
var x;
console.log(x); // undefined
x = 5;
console.log(x); // 5
```

:::

Le hoisting des fonctions fonctionne un peu différemment. Lorsque tu déclares une fonction en utilisant la syntaxe de déclaration `function`, le nom de la fonction et le corps de la fonction sont tous deux hoistés. Cela signifie que tu peux appeler une fonction avant de l'avoir déclarée dans ton code. Voici un exemple de hoisting de fonction :

:::interactive_editor

```js
sayHello(); // "Hello, World!"

function sayHello(){
  console.log("Hello, World!");
}
```

:::

Dans ce cas, nous pouvons appeler `sayHello()` avant sa déclaration, car l'intégralité de la fonction est hoistée en haut de sa portée.

Il est important de noter que le hoisting fonctionne différemment avec les déclarations `let` et `const` introduites dans ES6.

```js
console.log(y); // Throws a ReferenceError
let y = 10;
```

Ces déclarations sont hoistées, mais elles ne sont pas initialisées et tu ne peux pas y accéder avant la déclaration réelle dans ton code. On appelle cela la zone morte temporelle.

Comprendre le hoisting peut t'aider à écrire un code plus propre et plus prévisible. Cependant, s'appuyer sur le hoisting peut rendre ton code plus difficile à lire et à maintenir. En bonne pratique, il est recommandé de déclarer tes variables en haut de leur portée et tes fonctions avant de les utiliser, indépendamment du hoisting. Cela rend le comportement de ton code plus explicite et plus facile à comprendre pour les autres, y compris ton futur toi.
