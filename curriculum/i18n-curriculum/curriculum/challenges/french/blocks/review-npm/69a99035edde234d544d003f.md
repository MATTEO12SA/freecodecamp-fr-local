## Qu'est-ce que npm ?

- **Définition** : npm est un registre en ligne de logiciels open source, fonctionnant comme un « app store » pour le code.
- **Signification officielle** : npm ne signifie pas officiellement « Node Package Manager » ; c'est une abréviation backronymique récursive pour « npm is not an acronym ».
- **Trois parties liées** :

  - **Site web (npmjs.com)** : Pour chercher des paquets dans le registre.
  - **Registre** : Une grande base de données publique stockant tous les paquets.
  - **CLI (Command Line Interface)** : Un outil installé avec Node.js pour gérer les dépendances du projet.

- **Alternatives** : Bien que npm soit le plus largement utilisé, des alternatives populaires incluent **Yarn**, **PNPM** et **Bun**.

## Le fichier package.json

- **Objectif** : Un fichier de configuration qui stocke les métadonnées, dépendances et scripts d'un projet Node.js.
- **Champs clés** :

  - `name` et `version` : Identifient le projet.
  - `main` : Spécifie le fichier point d'entrée, souvent `index.js`.
  - `license` : Définit les conditions légales (par défaut `ISC`).
  - `dependencies` : Paquets requis pour faire tourner l'app en production.
  - `devDependencies` : Outils nécessaires uniquement pendant le développement, comme les frameworks de test.


- **Création** :

  - `npm init` : Démarre un processus de configuration interactif.
  - `npm init -y` : Installe un `package.json` avec des valeurs par défaut instantanément.

## Versionnage sémantique (SemVer)

- **Format** : `MAJOR.MINOR.PATCH`.
- **Règles** :

  - **MAJOR** : Breaking changes qui peuvent affecter le code existant.
  - **MINOR** : Nouvelles fonctionnalités rétrocompatibles.
  - **PATCH** : Petites corrections de bugs et améliorations.

- **Symboles de plage** :

  - `^` (Caret) : Autorise les mises à jour mineures et de patch (ex. : `^1.2.3` autorise `1.x.x`).
  - `~` (Tilde) : Autorise uniquement les mises à jour de patch (ex. : `~1.2.3` autorise `1.2.x`).
  - `*` (Astérisque) : Correspond à n'importe quelle version ; utilisé principalement pour les tests.

## Gestion des dépendances

- **Installation** :

  - `npm install <name>` : Ajoute une dépendance de production.
  - `npm install <name> -D` : Ajoute une dépendance de développement.
  - `npm install <name>@<version>` : Installe une version spécifique.

- **Node Modules et verrous** :

  - `node_modules/` : Contient le code réel des paquets installés.
  - `package-lock.json` : Verrouille les versions exactes de toutes les dépendances et « dépendances enfants » pour assurer la cohérence entre environnements.

- **Suppression** : `npm uninstall <name>` retire le paquet et met à jour `package.json`.
- **Maintenance** :

  - `npm outdated` : Identifie quels paquets ont de nouvelles versions disponibles.
  - `npm update` : Met à jour les paquets dans la plage SemVer autorisée.

## Scripts npm

- **Fonction** : Commandes personnalisées définies dans la section `scripts` de `package.json` pour automatiser des tâches.
- **Exécution** : Lancer via `npm run <script_name>`.
- Des abréviations existent pour `start`, `test`, `stop` et `restart` (ex. : `npm start`).
- **Exécution séquentielle** :
- `&&` : Exécute la seconde commande uniquement si la première réussit.
- `;` : Exécute les commandes l'une après l'autre, succès ou non.
- **Exécution concurrente** : Utilise l'opérateur `&` pour lancer des processus en arrière-plan.
- **Arguments** : Passe des arguments aux scripts avec le séparateur `--` (ex. : `npm start -- 8000`).

## Publier sur le registre npm

- **Accès au registre** : Une base de données de paquets publics et privés.
- **Étapes de publication** :

1. Crée un compte gratuit sur `npmjs.com`.
2. Connecte-toi via le terminal avec `npm login`.
3. Assure-toi qu'un `name` unique et une `version` valide sont dans `package.json`.
4. Crée un `README.md` et un `.npmignore` (pour exclure les fichiers sensibles).
5. Exécute `npm publish` (ou `npm publish --access public` pour les paquets scoped).

- **Scopes** : Utilisés pour éviter les conflits de noms en publiant sous `@username/package-name`.

## Systèmes de modules dans Node.js

### CommonJS (CJS)

- **Système par défaut** : La façon originale dont Node.js gère les modules ; charge de façon synchrone.
- **Syntaxe** :
- **Import** : `const module = require('./path')`.
- **Export** : `module.exports = { functionName }`.
- **Identification** : Utilisé pour les fichiers `.cjs` ou `.js` quand aucun `type` n'est spécifié dans `package.json`.

### Modules ES (ESM)

- **Format standardisé** : Standard JavaScript moderne ; charge de façon asynchrone pour plus d'efficacité.
- **Syntaxe** :

  - **Export** : `export { name }` ou `export default function`.
  - **Import** : `import { name } from './path.mjs'`.
  - **Identification** : Utilisé pour les fichiers `.mjs` ou `.js` quand `package.json` contient `"type": "module"`.
