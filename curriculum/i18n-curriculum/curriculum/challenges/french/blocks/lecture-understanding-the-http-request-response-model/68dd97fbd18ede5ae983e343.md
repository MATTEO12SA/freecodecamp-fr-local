# --description--

Les sites web et les apps ont besoin de collecter des données et de les traiter, ou de générer quelque chose dont l'utilisateur a besoin comme des résultats de recherche. Donc, tout comme le texte, les formulaires sont aussi une partie fondamentale du web.

Avec les formulaires, les utilisateurs peuvent s'inscrire et se connecter à un site, envoyer des messages, et chercher des éléments. Par exemple, tu accèdes à la page de résultats de recherche Google en saisissant ta requête dans le formulaire le plus populaire du web, le champ de recherche Google.

Regardons ce qui compose un formulaire, comme les champs de saisie, l'attribut `action`, les méthodes de formulaire, et surtout, ce qui se passe quand tu soumets un formulaire.

Les formulaires sont intégrés dans une page web avec l'élément `form`, mais pour faire apparaître des champs, tu as aussi besoin des éléments `input`, selon tes besoins. Certains de ces éléments d'entrée sont texte, e-mail, mot de passe, sélection, fichier, entrées cachées, et plus encore.

Pour utiliser ces champs de saisie, tu dois les envelopper avec l'élément `form`. Chacun des champs a besoin d'un attribut `name` pour que le serveur sache quelles données correspondent à chaque champ.

Voici un exemple :

```html
<form>
   <input type="text" name="username" />
   <input type="email" name="email" />
   <input type="file" name="profilePicture" />
   <input type="radio" name="gender" />
   <input type="checkbox" name="subscribe" />
   <input type="hidden" name="userId" />
</form>
```

Les champs de saisie doivent aussi être validés pour s'assurer que l'utilisateur saisit les bonnes informations.

Cette validation peut se faire à la fois côté client et côté serveur. HTML te permet de faire une validation basique côté client avec les attributs `required` et `pattern`. Même ainsi, tu devrais aussi valider côté serveur pour plus de sécurité, car la validation HTML est surtout pour l'expérience utilisateur et le feedback immédiat.

L'attribut `required` spécifie que le champ de saisie doit être rempli, tandis que l'attribut `pattern` te permet d'entrer des expressions régulières qui forcent l'utilisateur à saisir l'information de la façon dont tu en as besoin.

Voici un exemple de cela pour un champ de nom d'utilisateur :

```html
<input type="text" name="username" required pattern="[A-Za-z0-9]{3,}" />
```

Après la validation des champs de saisie, la soumission devrait avoir lieu. Alors que se passe-t-il quand le formulaire est soumis ?

D'abord, pour que la soumission se produise, le formulaire a besoin d'un attribut `action` qui spécifie où le navigateur doit envoyer les valeurs des champs de saisie et d'un attribut `method` qui spécifie comment les données du formulaire sont soumises. Plus d'informations sur l'attribut `method` plus tard.

Voici à quoi pourrait ressembler un attribut action :

```html
<form action="/register">
	<!-- input fields -->
</form>
```

L'attribut `method` peut être soit `GET`, `POST`, `PUT`, `PATCH`, soit `DELETE` :

* `GET` récupère quelque chose du serveur, par exemple, des résultats de recherche.

* `POST` envoie quelque chose au serveur, par exemple, des informations de connexion ou d'inscription saisies via les champs de saisie.

* `PUT` modifie quelque chose sur le serveur.

* `PATCH` modifie partiellement quelque chose sur le serveur.

* `DELETE` supprime quelque chose du serveur.

Note que HTML ne prend pas en charge directement les méthodes `PUT`, `PATCH` et `DELETE`, mais il existe des solutions de contournement. Si tu travailles avec du JavaScript vanilla, tu peux utiliser la Fetch API pour spécifier la méthode, et dans Node.js et Express, tu peux utiliser le paquet `method-override`.

Voici à quoi pourrait ressembler un formulaire faisant une requête `GET` :

```html
<form action="/search" method="GET">
   <input type="text" name="q">
   <button type="submit">Search</button>
</form>
```

Et voici à quoi pourrait ressembler un formulaire faisant une requête `POST` :

```html
<form action="/submit" method="POST">
   <input type="text" name="username" required pattern="[A-Za-z0-9]{3,}" />
   <input type="password" name="password" />
   <button type="submit">Submit</button>
</form>
```

Après la requête `GET` ou `POST`, le serveur vérifie la validation côté serveur et soit traite, soit rejette les valeurs d'entrée.

Si la validation réussit, le serveur envoie les informations demandées ou renvoie une erreur si la validation échoue.

Si la validation réussit, la réponse du serveur pourrait être une redirection en cas d'authentification ou de recherche, ou un message de succès confirmant l'action.

Voici un récapitulatif de ce qui se passe quand un formulaire est soumis :

* L'utilisateur remplit les champs du formulaire.

* Le navigateur vérifie la validation côté client (s'il y en a) et continue si la validation réussit.

* Le navigateur envoie les données du formulaire au serveur selon les attributs action et method.

* Le serveur reçoit les données et les traite (stockage dans une base de données, inscription d'un utilisateur, connexion d'un utilisateur, envoi d'une requête de recherche, et ainsi de suite).

* S'il y a une validation côté serveur, le serveur revérifie les données avant de les traiter.

* Le serveur répond avec un message de succès, une erreur, ou redirige l'utilisateur selon l'état de validation (succès ou échec).

* L'utilisateur voit un feedback basé sur la réponse du serveur.
