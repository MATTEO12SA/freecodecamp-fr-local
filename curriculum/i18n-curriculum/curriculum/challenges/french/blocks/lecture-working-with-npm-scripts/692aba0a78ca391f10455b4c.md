# --description--

Maintenant que tu comprends le système de modules CommonJS, regardons le système de modules ES.

Les modules ES, ou modules ECMAScript, sont le format de module officiel et standardisé pour JavaScript défini par la spécification ECMAScript. Ils utilisent les instructions `import` et `export`, et dans Node.js, ils sont chargés de façon asynchrone, ce qui est plus efficace.

Node.js traite les fichiers comme des modules ES dans les cas suivants :

* Les fichiers avec une extension `.mjs`.

* Et les fichiers avec une extension `.js` quand le fichier `package.json` parent le plus proche contient un champ `"type"` de premier niveau avec une valeur de `"module"`.

Ici nous avons la même fonction `multiply` que tu as vue auparavant, mais maintenant nous allons utiliser le système ESM. Pour cela, nous assignons une extension `.mjs` aux deux modules.

Pour exporter la fonction `multiply` depuis le module `math.mjs`, utilise le mot-clé `export` suivi du nom de la fonction, variable ou objet que tu veux exporter entre accolades :

```javascript
function multiply(a, b) {
  return a * b;
}

export { multiply };
```

Tu peux aussi exporter la fonction directement en utilisant le mot-clé `export` avant le mot-clé `function`. C'est ce qu'on appelle un export nommé. Tu peux avoir plusieurs exports nommés par module :

```javascript
export function multiply(a, b) {
  return a * b;
}
```

Ensuite, pour importer ce module, utilise le mot-clé `import` suivi d'accolades. Remarque que nous utilisons `import` au lieu de `require()`. C'est l'une des différences clés entre CommonJS et les modules ES.

Entre les accolades, nous écrivons le nom de la fonction, variable ou objet que nous voulons importer. Dans ce cas, c'est `multiply`. Ensuite, utilise le mot-clé `from` et le chemin relatif vers le module. Ce code s'exécutera avec succès et la sortie sera `42`.

```javascript
import { multiply } from './math.mjs';

console.log(multiply(6, 7)); // 42
```

Dans le système ES, tu peux définir un export par défaut par module. Ainsi, tu n'as pas besoin d'utiliser des accolades pour l'importer.

Voici un exemple où nous définissons la fonction `multiply` comme export par défaut pour tout le module `math.mjs` :

```javascript
export default function multiply(a, b) {
  return a * b;
}
```

Maintenant nous n'avons pas besoin des accolades, puisque la fonction sera importée et assignée par défaut :

```javascript
import multiply from './math.mjs';
```

Si tu n'utilises pas les extensions de fichier ni le fichier `package.json` pour dire explicitement à Node.js quel type de système de modules tu veux utiliser, il inspectera le code source pour chercher la syntaxe des modules ES. Si cette syntaxe est trouvée, il exécutera le code comme un module ES ; sinon, il l'exécutera comme un module CommonJS.

Bien que CommonJS ait servi de standard par défaut pour Node.js à ses débuts, alors que les développeurs adoptent de plus en plus ESM pour son efficacité et sa compatibilité avec le JavaScript moderne, il est important de connaître leurs différences et comment utiliser les deux.
