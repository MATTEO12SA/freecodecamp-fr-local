# --description--

Dans le développement web moderne, tu peux diviser ton code en plusieurs fichiers appelés « modules ».

Tu peux penser à un module comme un bloc de code autonome et réutilisable.

En important des modules dans d'autres modules, tu peux réutiliser leur fonctionnalité tout en gardant le code dans des fichiers séparés, ce qui est plus maintenable, surtout pour les applications web grandes et complexes.

Dans Node.js, chaque fichier est considéré comme un module.

Node a deux systèmes différents pour travailler avec les modules : CommonJS et ES.

CommonJS est la façon originale et par défaut de travailler avec les paquets dans Node.js. Il charge les modules de façon synchrone, ce qui signifie qu'il doit attendre qu'un module soit entièrement chargé avant de commencer à charger le suivant ou de continuer l'exécution du code.

Il est encore largement utilisé, mais il est progressivement remplacé par la syntaxe ES plus récente.

CommonJS utilise la fonction `require()` pour importer un module, en prenant son chemin relatif comme argument.

Par exemple, disons que nous avons un module appelé `math.js`, où nous définissons des opérations mathématiques de base.

Nous n'utiliserons qu'une fonction de multiplication ici pour garder cet exemple simple et ciblé :

```js
function multiply(a, b) {
  return a * b;
}
```

Comment pouvons-nous réutiliser cette fonction en dehors de notre module actuel ? Par défaut, les fonctions et variables définies dans un module Node.js sont **privées** — les autres modules ne peuvent pas y accéder sauf si nous les exportons explicitement. Il y a plusieurs façons de le faire.

Une façon courante est d'assigner une valeur à `module.exports`. Cet objet représente ce que le module renverra quand il sera importé ailleurs, donnant aux autres modules l'accès aux fonctions, variables ou objets que tu as choisi d'exposer.

Dans cet exemple, nous assignons un objet avec une propriété `multiply` à `module.exports`. La valeur de cette propriété est une référence à la fonction `multiply` que nous avons définie plus tôt. Cela exportera la fonction, pour que nous puissions l'appeler depuis d'autres modules si besoin.

```javascript
function multiply(a, b) {
  return a * b;
}

module.exports = {
  multiply: multiply
};
```

Disons que nous essayons d'importer le module `math.js` dans un autre module. Nous appelons la fonction `require()`, et passons le chemin relatif comme argument. Ensuite, nous assignons l'objet renvoyé par `require()` à la variable `math`.

```javascript
const math = require('./math');
```

Vérifions la valeur de `math` dans la console en l'affichant avec `console.log()` :

```javascript
console.log(math);
```

Voici la sortie. C'est un objet avec une propriété `multiply` et une fonction comme valeur :

```javascript
{ multiply: [Function: multiply] }
```

Si nous appelons cette fonction avec `math.multiply()`, en passant les nombres `6` et `7` comme arguments, la sortie est `42`. La fonction s'exécute avec succès et pourtant, elle est dans un autre fichier ! Donc notre instruction d'import a correctement fonctionné.

```javascript
const math = require('./math');

console.log(math.multiply(6, 7)); // 42
```

Mais il y a d'autres façons d'exporter une fonction, une variable ou un objet.

Par exemple, si tu n'as besoin d'exporter qu'une seule fonction, variable ou objet, tu peux l'assigner directement comme valeur de `module.exports` :

```javascript
function multiply(a, b) {
  return a * b;
}

module.exports = multiply;
```

Si tu as besoin d'exporter plusieurs fonctions, tu dois juste les ajouter à l'objet `module.exports`, séparées par une virgule.

Ici, tu peux voir que l'objet exporté a deux propriétés : `subtract` et `multiply`. Leurs valeurs sont des références à leurs fonctions correspondantes, donc tu auras accès aux deux dans tout module qui importe `math.js` :

```javascript
function subtract(a, b) {
  return a - b;
}

function multiply(a, b) {
  return a * b;
}

module.exports = {
  subtract: subtract,
  multiply: multiply
};
```

Quand l'objet `module.exports` a plusieurs propriétés, tu auras l'option de choisir si tu veux tout importer ou importer des propriétés individuellement.

Dans cet exemple, nous importons l'objet entier qui a été exporté par `math.js`, donc nous aurons accès à la fois à `subtract` et `multiply` :

```javascript
const math = require('./math');

console.log(math.subtract(6, 7));  // -1
console.log(math.multiply(6, 7));  // 42
```

Si nous voulons n'importer que `multiply` à la place, nous devons juste écrire son nom entre accolades, après le mot-clé `const`. En gros, tu utilises la syntaxe d'affectation par déstructuration pour obtenir sa valeur depuis l'objet exporté. Ensuite, nous pouvons y faire référence directement par son nom dans notre code :

```javascript
const { multiply } = require('./math');

console.log(multiply(6, 7));
```

Cela fonctionne aussi pour plusieurs éléments. Tu dois juste les séparer par une virgule entre les accolades. Ici, nous importons à la fois les fonctions `subtract` et `multiply` :

```javascript
const { subtract, multiply } = require('./math');
```

Par défaut, Node.js traitera ce qui suit comme des modules CommonJS :

* Les fichiers avec une extension `.cjs`.

* Les fichiers avec une extension `.js` quand le fichier `package.json` parent le plus proche contient un champ de premier niveau `"type"` avec une valeur de `"commonjs"`.

* Les fichiers avec une extension `.js` ou sans extension, quand le fichier `package.json` parent le plus proche ne contient pas de champ de premier niveau `"type"`, ou qu'il n'y a pas de `package.json` dans aucun dossier parent.

* Les fichiers avec une extension qui n'est pas `.mjs`, `.cjs`, `.json`, `.node` ou `.js`.

Bien que les modules ES remplacent progressivement les modules CommonJS, les comprendre reste essentiel pour les développeurs qui travaillent avec des bases de code Node.js existantes et de nombreux paquets npm.
