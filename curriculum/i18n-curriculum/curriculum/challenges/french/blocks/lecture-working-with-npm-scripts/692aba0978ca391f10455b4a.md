# --description--

Apprenons le registre npm, où tu peux partager tes paquets JavaScript avec le monde.

Le **registre npm** est une base de données de paquets publics et privés.

Les développeurs et les organisations peuvent publier des paquets sur ce registre pour partager leurs outils avec leurs communautés et membres d'équipe, et dans de nombreux cas, avec tous les autres développeurs Node.js.

Les paquets peuvent être publics ou privés. Les paquets publics sont accessibles par n'importe qui. Les paquets privés ne sont accessibles que par des utilisateurs spécifiques ou des membres d'une organisation.

Dans le registre npm, tu peux partager ce que tu as construit avec le monde en quelques clics. Ça a l'air génial, non ?

Voyons comment tu peux publier un paquet étape par étape.

## Étape 1 : Créer un compte

La première étape est de créer un compte npm gratuit. Pour créer ton compte :

* Va sur [https://www.npmjs.com/signup](https://www.npmjs.com/signup).

* Remplis le formulaire. Tu devras saisir ton nom d'utilisateur, ton e-mail et ton mot de passe.

Note que, selon la page d'inscription, « ton adresse e-mail sera ajoutée aux métadonnées des paquets que tu publies, elle pourra donc être vue publiquement. »

## Étape 2 : **Se connecter**

Une fois que tu as un compte npm, tu devras te connecter sur ton terminal en exécutant cette commande :

```bash
npm login
```

Ensuite tu devras t'authentifier avec les informations de ton compte.

## **Étape 3 : Créer un** fichier `package.json`

Avant de publier ton paquet, tu devras créer un fichier `package.json` avec cette commande :

```bash
npm init
```

(Si ton projet en a déjà un, tu peux aller directement à l'**étape 4**).

Tu devras saisir ces informations pour ton fichier `package.json` :

* **name** : C'est généralement le nom de ton projet/répertoire. Si tu prévois de rendre ton paquet public, ce nom doit être unique, sauf si tu utilises des scopes (nous en parlerons dans un instant).

* **version** : Tu devrais commencer par `"1.0.0"`, la valeur par défaut. Cela représente la version initiale de ton paquet et tu peux la mettre à jour au fur et à mesure des changements.

* **main** : Le point d'entrée de ton projet. C'est `index.js` par défaut.

* **author** : Tu peux écrire ton nom ou ton pseudo préféré.

* **license** : Choisis une licence spécifique. Quelques exemples incluent MIT et ISC.

* **description** : Un bref résumé de ton paquet.

Quand tu choisis le nom de ton paquet, assure-toi qu'il n'est pas déjà pris dans le registre npm. Pour cela, tu peux aller à l'URL suivante, en remplaçant `<your-package-name>` par le nom de ton paquet :

```bash
https://www.npmjs.com/package/<your-package-name>
```

S'il n'y a pas de paquet à cette URL, le nom du paquet est disponible et tu peux l'utiliser.

Cependant, si le nom est déjà pris et que tu veux vraiment le garder, tu peux utiliser ce qu'on appelle un **scope** pour le publier.

### **Scopes**

Quand tu crées un compte utilisateur ou organisation dans le registre npm, on te donne un scope avec ton nom d'utilisateur ou le nom de ton organisation.

Les scopes sont utiles pour éviter les conflits de noms car tu peux publier ton paquet sous ton scope, même si un autre paquet avec le même nom existe déjà.

Le nom d'un paquet scoped commence par le nom du scope. Par exemple, dans `package.json`, tu trouverais cette paire clé-valeur :

```bash
"name": "@<scope-name>/<your-package-name>"
```

Tu peux faire ce changement directement dans le fichier si besoin, ou tu peux créer le fichier `package.json` avec le scope dès le départ en ajoutant `--scope=@<scope-name>` à la commande `npm init`.

```bash
npm init --scope=@<scope-name>
```

Le nom du scope peut être ton nom d'utilisateur si tu utilises un compte personnel, ou le nom de ton organisation si tu utilises un compte organisationnel.

## Étape 4 : Créer README.md

Le README de ton paquet est un fichier markdown où tu décris ce que fait ton paquet et son usage prévu.

Quelques exemples de contenu important que tu pourrais vouloir inclure sont :

* Son objectif.

* Comment l'installer.

* Dépendances importantes et considérations.

* Comment démarrer.

* Exemples d'extraits de code.

* Directives de contribution (si tu acceptes des contributions).

* Lien vers un fichier changelog où tu suis les changements faits dans les différentes versions.

La structure du README est flexible, cependant. Tu peux l'adapter à tes besoins.

## **Étape 5 :** `.npmignore`

Le fichier `.npmignore` dit au registre npm quels fichiers inclure et quels fichiers ignorer lors de la publication de ton paquet. Il est très important pour éviter de partager des informations sensibles comme des clés privées, des mots de passe et des informations personnelles.

Dans ce fichier, tu peux écrire des motifs pour spécifier quels fichiers, répertoires et types de fichiers sont ignorés. Il suit les mêmes règles de correspondance de motifs que les fichiers `.gitignore`.

Si tu as travaillé avec Git, tu penses peut-être que ce fichier ressemble beaucoup à `.gitignore`, non ? Eh bien, c'est parce que c'est le cas. Selon la documentation npm, « S'il n'y a pas de fichier `.npmignore`, mais qu'il y a un fichier `.gitignore`, alors npm ignorera ce qui correspond au fichier `.gitignore`. »

Tu dois aussi savoir que npm cherche les fichiers `.npmignore` et `.gitignore` dans tous les sous-répertoires de ton paquet, pas seulement le répertoire racine.

Par défaut, ces chemins sont automatiquement ignorés, donc tu n'as pas besoin de les ajouter à `.npmignore` :

* `.*.swp`

* `._*`

* `.DS_Store`

* `.git`

* `.gitignore`

* `.hg`

* `.npmignore`

* `.npmrc`

* `.lock-wscript`

* `.svn`

* `.wafpickle-*`

* `config.gypi`

* `CVS`

* `npm-debug.log`

Le répertoire `node_modules` est aussi ignoré, sauf les dépendances bundled.

## **Étape 6 : Publier ton paquet**

Avant de publier ton paquet sur le registre npm, tu devrais le tester en exécutant cette commande :

```bash
npm install <full-path-to-package-directory>
```

Une fois prêt à le publier, la commande dépendra du type de paquet : scoped vs. unscoped.

Si ton paquet est unscoped, exécute cette commande :

```bash
npm publish
```

Si ton paquet est scoped, il sera publié comme paquet privé par défaut (si cette fonctionnalité est disponible sur ton compte). Si tu veux le rendre public, tu devras ajouter `--access public` à la commande.

```bash
npm publish --access public
```

Pour voir ton paquet public, va à cette URL :

```bash
https://npmjs.com/package/<your-package-name>
```

Tu devrais voir une indication de la visibilité de ton paquet (public ou privé) sous le nom du paquet.

## **Étape 7 (Optionnelle) : Installer ton paquet**

Maintenant que tout est en place, tu peux installer ton paquet dans un projet Node.js avec cette commande :

```bash
npm install <your-package-name>
```

## Mettre à jour ton paquet

Si tu dois apporter des changements à ton paquet après l'avoir publié, tu peux mettre à jour la version du paquet dans `package.json`.

Voici la convention standard pour le versionnage sémantique :

* **Première version :** `1.0.0`.

* **Version de patch :** Incrémente le troisième chiffre. Par exemple, passer de `1.0.0` à `1.0.1`.

* **Version mineure :** Incrémente le chiffre du milieu et remets le dernier chiffre à zéro. Par exemple, passer de `1.0.0` à `1.1.0`.

* **Version majeure :** Incrémente le premier chiffre et remets les chiffres du milieu et de la fin à zéro. Par exemple, passer de `1.1.0` à `2.0.0`.

Beau travail. Maintenant tu sais comment publier ton paquet sur le registre npm et comment le mettre à jour pour corriger des bugs et ajouter de nouvelles fonctionnalités.
