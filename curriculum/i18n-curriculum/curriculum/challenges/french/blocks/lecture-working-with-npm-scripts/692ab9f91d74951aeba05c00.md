# --description--

Maintenant tu vas apprendre les scripts npm.

Avant de plonger, revoyons quelques concepts importants :

* **npm** est un outil en ligne de commande que tu peux utiliser pour installer et gérer des paquets JavaScript.

* Un **paquet** est un répertoire qui regroupe du code lié dans une structure logique.

* Un **script** est une séquence d'instructions ou de commandes écrites dans un langage de programmation de scripting.

Les **scripts npm** sont des commandes personnalisées que tu peux définir dans le fichier `package.json` de ton application.

Ils sont utiles pour automatiser des tâches et des flux de travail que tu utiliseras de façon répétée pendant les phases de développement, de test et de déploiement de ton projet.

Par exemple, un cas d'usage des scripts npm est de personnaliser `npm start` pour démarrer tout ton environnement de développement. Au lieu d'écrire manuellement toutes les commandes une par une chaque fois que tu dois démarrer ton environnement de développement, tu peux juste exécuter `npm start` et tout le processus sera exécuté.

Tu peux aussi utiliser les scripts npm pour automatiser le linting dans toute ta base de code et pour exécuter des suites de tests, parmi d'autres cas d'usage.

Ils sont très puissants, alors voyons leurs fondamentaux.

## Comment créer un fichier package.json

Pour pouvoir créer et exécuter des scripts npm personnalisés, tu auras besoin d'un fichier `package.json`.

Le fichier `package.json` est essentiel pour les projets Node.js. Ce fichier contient les métadonnées, les dépendances et les scripts du projet.

Pour rappel, pour créer un fichier `package.json`, tu dois exécuter la commande `npm init` dans le répertoire racine de ton projet. Ensuite tu peux saisir manuellement le nom du paquet, la version, la description et d'autres détails, ou laisser ces champs vides pour utiliser les valeurs par défaut.

Une fois ce processus terminé, tu auras un fichier `package.json` dans le répertoire racine de ton projet.

Si tu as gardé toutes les valeurs par défaut, tu devrais voir ces paires clé-valeur quand tu ouvres `package.json` dans ton éditeur de code :

```json
{
  "name": "<project_name>",
  "version": "1.0.0",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "author": "",
  "license": "ISC",
  "description": ""
}
```

Remarque cette paire clé-valeur ici :

```json
"scripts": {
  "test": "echo \"Error: no test specified\" && exit 1"
}
```

C'est là que tu spécifieras tes scripts npm, sous la clé `scripts`.

Tu verras un script là par défaut, le script test :

```json
"test": "echo \"Error: no test specified\" && exit 1"
```

Ceci est un exemple de script npm défini dans `package.json`.

Voici la syntaxe de base pour définir un script npm :

```json
"<script_name>": "<commands>"
```

À gauche des deux-points, on trouve le nom du script. Les courants incluent `run`, `start`, `test`, `build`, `dev` et `lint`. Ces noms agissent comme des « raccourcis » pour leurs commandes sous-jacentes à droite.

À droite des deux-points, on trouve les commandes sous-jacentes elles-mêmes.

Par exemple :

```json
"scripts": {
  "start": "node app.js"
}
```

Pour exécuter le script, saisis ceci dans la ligne de commande :

```bash
npm run <script_name>
```

Et c'est ainsi que tu peux exécuter n'importe quel script personnalisé défini dans `package.json`.

Parfois tu peux utiliser cette version abrégée sans le mot `run` pour exécuter des scripts :

```bash
npm <script_name>
```

Mais cela ne fonctionne que pour des scripts npm spécifiques nommés `start`, `test`, `stop` et `restart`.

En revenant à notre exemple, si nous avons ceci dans `package.json` :

```json
"scripts": {
  "start": "node app.js"
}
```

Pour exécuter le script npm, tu dois saisir `npm run start` dans la ligne de commande. Quand tu le fais, la commande sous-jacente réellement exécutée est `node app.js`.

Comme ce script npm a une version abrégée, tu pourrais aussi utiliser `npm start` et le résultat serait le même.

Dans ce cas, tu remplaces juste une commande simple, `node app.js`, par une autre, `npm start`. Mais imagine si tu avais une séquence de commandes complexes à exécuter en séquence ou en parallèle, et que tu pouvais juste utiliser `npm start` pour toutes les exécuter. Cela te ferait gagner beaucoup de temps, non ? C'est là que la puissance des scripts npm brille vraiment.

Voici un aperçu rapide de certains des scripts npm les plus couramment utilisés :

* `npm run` : utilisé pour exécuter un script npm personnalisé.

* `npm start` : utilisé pour démarrer l'application principale ou le serveur de développement.

* `npm lint` : utilisé pour exécuter un vérificateur de style de code pour vérifier si ton code respecte les standards de style et les bonnes pratiques.

* `npm test` : utilisé pour exécuter la suite de tests du projet.

Il existe de nombreux autres scripts npm pour différents usages, mais ce sont certains des plus courants que tu verras.

Aussi, une convention courante est d'utiliser un deux-points pour regrouper des scripts liés sous le même namespace. Par exemple, `start:server` et `start:ui`.

## Comment exécuter des commandes séquentiellement

Si tu as besoin d'exécuter plusieurs commandes en séquence, tu as deux options. Tu peux soit utiliser l'opérateur logique AND (`&&`), soit le point-virgule (`;`). Voyons leurs différences.

L'opérateur logique AND exécute la commande suivante uniquement si la première s'exécute avec succès.

Par exemple :

```json
"scripts": {
  "build": "webpack --mode production",
  "start": "npm run build && node server.js"
}
```

Remarque qu'il y a un opérateur logique AND dans la commande `start` :

```json
"start": "npm run build && node server.js"
```

Ici, `npm start` essaiera d'abord d'exécuter `npm run build`, et seulement si ce script s'exécute avec succès, `node server.js` sera exécuté.

C'est une approche très courante car elle assure la fiabilité et évite de perdre du temps et des ressources sur des commandes suivantes qui pourraient échouer ou lever des erreurs si la précédente échoue.

Autrement, tu peux utiliser l'opérateur point-virgule pour exécuter des commandes séquentiellement, que la commande précédente ait réussi ou non.

Dans notre exemple, ce simple changement aurait un impact important sur la façon dont les commandes s'exécuteront :

```json
"scripts": {
  "build": "webpack --mode production",
  "start": "npm run build; node server.js"
}
```

Concentre-toi à nouveau sur la commande `start` :

```json
"start": "npm run build; node server.js"
```

Maintenant, comme nous utilisons un point-virgule au lieu de l'opérateur `&&`, la commande `node server.js` s'exécutera toujours après `npm run build`, même si `node server.js` n'a pas réussi.

```json
"start": "npm run build; node server.js"
```

## Comment exécuter des commandes simultanément

Si tu as besoin d'exécuter des commandes simultanément (en parallèle), tu peux utiliser l'opérateur `&`.

```json
"scripts": {
  "start:server": "node server/index.js",
  "start:client": "npm run build:watch",
  "dev": "npm run start:server & npm run start:client"
}
```

Cependant, tu dois savoir que cette option exécute les processus en arrière-plan.

Cela signifie que, si tu les exécutes dans la même session de terminal, tu pourrais voir leur sortie combinée, ce qui peut être difficile à comprendre.

D'autres options pour exécuter des commandes simultanément incluent des outils comme `concurrently` et `npm-run-all`.

## Comment passer des arguments aux scripts npm

Si tu as besoin de passer des arguments directement à la commande exécutée dans le script npm, tu peux les spécifier dans la commande en écrivant deux tirets (`--`) suivis des arguments.

Le `--` dit à npm que tout ce qui suit seront des arguments pour les commandes sous-jacentes que le script npm exécutera.

Voici la syntaxe générale :

```bash
npm run <script_name> -- <argument_1> <argument_2> <argument_3>
```

Par exemple, disons que tu définis ce script `npm start` :

```json
{
  "name": "project-example",
  "scripts": {
    "start": "node app.js"
  }
}
```

Comment pourrais-tu spécifier le port où tu veux faire tourner ton serveur si tu utilises `npm start` ?

Disons que nous voulons passer le port directement comme argument en ligne de commande. Tu écrirais ceci :

```bash
npm start -- 8000
```

Dans ton code, tu peux accéder à ces arguments dans le tableau `process.argv` en utilisant des indices :

```bash
process.argv[0] # The path to the node executable.
process.argv[1] # The script file being executed.
process.argv[2] # The first argument (8000).
```

Par conséquent, tu pourrais accéder et utiliser le numéro de port partout où tu en as besoin avec `process.argv[2]`. C'est la puissance des arguments en ligne de commande combinés aux scripts npm.

Comme tu peux le voir, les scripts npm sont des outils essentiels pour simplifier le flux de travail de développement. Ils t'aident à automatiser et transformer des séquences de commandes complexes et réutilisables en raccourcis simples et cohérents que tu peux utiliser dans ton travail quotidien.
