# --description--

À mesure que ton app grandit, gérer comment les données circulent entre les composants peut devenir complexe.

Au début, le Hook `useState` de React peut suffire, mais en ajoutant des fonctionnalités, tu pourrais rencontrer des problèmes avec :

- Passer des props à travers des composants qui n'en ont pas besoin, aussi connu sous le nom de prop drilling
- Garder les données synchronisées à travers différentes parties de ton app
- Gérer des mises à jour complexes qui affectent plusieurs composants simultanément

Ces défis et d'autres peuvent surgir, ce qui peut mener à une base de code plus dure à maintenir, déboguer et tester. C'est là qu'interviennent les bibliothèques de gestion d'état – elles fournissent un endroit centralisé où les composants peuvent obtenir ou mettre à jour les données dont ils ont besoin.

Voyons quelques options différentes de gestion d'état que tu as, et quand les utiliser.

L'API Context est un gestionnaire d'état intégré à React qui te laisse partager l'état entre composants sans utiliser une bibliothèque tierce. C'est une mise à niveau bien établie par rapport au Hook `useState`, donc elle est parfaite pour des cas comme le basculement de thème ou le statut d'authentification utilisateur.

Cependant, l'API Context ne gère pas bien les mises à jour fréquentes, et peut causer des re-rendus inutiles, ce qui la rend moins adaptée aux besoins d'état complexes dans des applications comme l'e-commerce et les plateformes de réseaux sociaux.

Voici un composant compteur qui démontre l'usage de base de l'API Context :

```jsx
import { useState, createContext } from 'react';

const CounterContext = createContext();

const CounterProvider = ({ children }) => {
  const [count, setCount] = useState(0);

  return (
    <CounterContext.Provider value={{ count, setCount }}>
      {children}
    </CounterContext.Provider>
  );
};

export { CounterContext, CounterProvider };
```

Ce code crée un context et un provider pour partager un état `count` à travers l'application.

`CounterProvider` utilise le Hook `useState` pour initialiser et gérer l'état `count` et son setter. Les deux sont ensuite passés aux composants enfants via le `Provider`.

Donc, quand tu enveloppes toute ton app avec le `CounterProvider`, l'état `count` est disponible partout dans ton application.

Voici comment tu peux envelopper `CounterProvider` autour de ton application :

```jsx
import { CounterProvider } from './context/CounterContext';

function App() {
  return (
    <CounterProvider>
        {/* App components */}
    </CounterProvider>
  );
}

export default App;
```

Et voici comment tu peux utiliser l'état `count` :

```jsx
import React, { useContext } from 'react';
import { CounterContext } from '../context/CounterContext';

const Counter = () => {
  const { count, setCount } = useContext(CounterContext);

  return (
    <>
      <div style={{ textAlign: 'center' }}>
        <h1>Context API Counter</h1>
        <button style={{ marginRight: '5px' }} onClick={() => setCount(count - 1)}>
          Decrease
        </button>
        <span>{count}</span>
        <button style={{ marginLeft: '5px' }} onClick={() => setCount(count + 1)}>
          Increase
        </button>
      </div>
    </>
  );
};

export default Counter;
```

Comme tu peux le voir, le `count` et sa fonction setter, `setCount`, sont initialisés via la fonction `useContext`.

L'état `count` actuel est ensuite affiché, et `setCount` est utilisé pour augmenter et diminuer l'état `count` quand l'utilisateur clique respectivement sur les boutons décrémenter et incrémenter.

Une autre bibliothèque populaire de gestion d'état est Redux, qui est l'une des bibliothèques de gestion d'état les plus populaires à utiliser avec React. Elle existe depuis longtemps, et est idéale pour de plus grandes applications comme l'e-commerce et les plateformes de réseaux sociaux, les forums, et ainsi de suite.

Redux gère l'état en fournissant un store central et un contrôle strict sur les mises à jour d'état. Il utilise un modèle prévisible avec actions, reducers et middleware.

Les actions sont des payloads d'information qui envoient des données de ton application au store Redux, souvent déclenchées par des interactions utilisateur.

Les reducers sont des fonctions qui spécifient comment l'état doit changer en réponse à ces actions, en s'assurant que l'état est mis à jour de façon immuable.

Le middleware, lui, agit comme un pont entre le dispatch d'action et le reducer, te permettant d'étendre la fonctionnalité de Redux (par exemple, logging, gestion d'opérations asynchrones) sans modifier le flux central.

La plainte la plus courante à propos de Redux concerne tout le code de base (boilerplate) dont tu as besoin pour démarrer. En réponse, l'équipe Redux a introduit « Redux Toolkit » et « RTK Query », qui simplifient assez le processus de configuration.

Tu définis typiquement actions et reducers dans un seul fichier en utilisant la fonction `createSlice()`. Il est courant de nommer le fichier pour qu'il se termine par le mot `Slice`, par exemple `productSlice`, `userSlice`, `counterSlice`, et ainsi de suite.

Voici un fichier `counterSlice` pour te montrer les bases :

```jsx
import { createSlice } from '@reduxjs/toolkit';

const counterSlice = createSlice({
  name: 'counter',

  initialState: { count: 0 },

  reducers: {
    increment: (state) => {
      state.count += 1;
    },
    decrement: (state) => {
      state.count -= 1;
    },
  },
});

export const { increment, decrement } = counterSlice.actions;

export default counterSlice.reducer;
```

À partir de là, tu dois ensuite envelopper toute l'app avec le `Provider`, sélectionner un morceau d'état depuis le slice avec `useSelector()`, puis utiliser `useDispatch()` pour activer l'état.

Une autre option à considérer est Zustand.

Zustand est une bibliothèque légère de gestion d'état avec une API simple. Elle est basée sur les Hooks, donc il y a moins de boilerplate par rapport à Redux, ce qui la rend plus facile et plus rapide à configurer.

Zustand est idéal pour les applications de petite à moyenne échelle. Il fonctionne en utilisant un Hook `useStore` pour accéder à l'état directement dans les composants et pages. Cela te laisse modifier et accéder aux données sans avoir besoin d'actions, reducers ou provider.

Voici un `useCounterStore` qui implémente une autre fonctionnalité de compteur :

```jsx
import { create } from 'zustand';

const useCounterStore = create((set) => ({
  count: 0,
  increment: () => set((state) => ({ count: state.count + 1 })),
  decrement: () => set((state) => ({ count: state.count - 1 })),
}));

export default useCounterStore;
```

Et voici comment initialiser et utiliser les états dans ton app :

```jsx
// Import the useCounterStore (it's just a hook)
import useCounterStore from '../useCounterStore';

const Counter = () => {
  // Initialize the states with the useCounterStore hook
  const { count, increment, decrement } = useCounterStore();

  return (
    <>
      <div style={{ textAlign: 'center' }}>
        <h1>Zustand Counter</h1>
        <button style={{ marginRight: '5px' }} onClick={() => decrement()}>
          Decrease
        </button>
        <span>{count}</span>
        <button style={{ marginLeft: '5px' }} onClick={() => increment()}>
          Increase
        </button>
      </div>
    </>
  );
};

export default Counter;
```

Même si l'écosystème front-end évolue constamment et que de nouvelles bibliothèques de gestion d'état émergent régulièrement, celles dont on a parlé sont largement utilisées dans l'industrie.
