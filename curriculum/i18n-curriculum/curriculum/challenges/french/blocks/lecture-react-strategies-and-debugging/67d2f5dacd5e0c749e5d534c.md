# --description--

Le navigateur a des outils de développement intégrés que tu peux utiliser pour déboguer le HTML, le CSS et le JavaScript.

Cependant, ils ne sont pas idéaux pour trouver et corriger des bugs dans les apps React. Donc l'équipe React a développé un outil appelé « React Developer Tools » (AKA React DevTools) pour que tu puisses inspecter, déboguer et profiler des apps React.

React DevTools est disponible comme extension de navigateur pour Chrome, Edge et Firefox. Si tu es sur Chrome ou Edge, va sur le Chrome web store, cherche « React Developer Tools », et ajoute-le à ton navigateur.

Et si tu utilises Firefox, va sur la page des Add-ons Firefox, cherche l'outil, et ajoute-le à ton navigateur.

Si tu utilises Safari, tu peux installer React DevTools depuis npm en exécutant `npm install -g react-devtools` ou `yarn global add react-devtools`.

Après avoir installé et activé React DevTools, si tu ouvres une app React dans ton navigateur, puis ouvres les outils de développement de ton navigateur, tu devrais voir deux onglets supplémentaires : Components et Profiler.

L'onglet Components affiche chaque composant pour toi dans un format d'arborescence. Avec lui, tu peux :

- Voir la hiérarchie des composants de l'app.
- Vérifier et modifier props, états et valeurs de context en temps réel.
- Vérifier le code source de chaque composant sélectionné.
- Journaliser les données du composant dans la console.
- Inspecter les éléments DOM du composant.

D'un autre côté, l'onglet Profiler t'aide à enregistrer et analyser les performances des composants pour identifier les re-rendus inutiles, voir les durées de commit, et les choses que tu peux optimiser.

Voici une app simple pour te montrer comment inspecter les composants et les props et l'état qu'ils ont. C'est similaire au code qu'on a utilisé dans une leçon précédente sur le prop drilling :

```jsx
import { useState } from "react";

export default function App() {
  const greeting = "Hello, Prop Drilling!";
  const response = "I'm not here to play!";

  return <Parent greeting={greeting} response={response} />;
}

const Parent = ({ greeting, response }) => {
  return <Child greeting={greeting} response={response} />;
};

const Child = ({ greeting, response }) => {
  return <Grandchild greeting={greeting} response={response} />;
};

const Grandchild = ({ greeting, response }) => {
  const [count, setCount] = useState(0);

  return (
    <>
      <h1>{greeting}</h1>
      <h2>{response}</h2>

      <button onClick={() => setCount(count + 1)}>Increase Count</button>
      <h2>Count: {count}</h2>
      <button onClick={() => setCount(count - 1)}>Decrease Count</button>
    </>
  );
};
```

Si tu regardes dans l'onglet Components de React DevTools, tu peux voir l'arborescence des composants. Le composant `App` est en haut, suivi des composants `Parent`, `Child` et `Grandchild`.

Si tu sélectionnes n'importe lequel de ces composants, tu peux voir les props et l'état dedans. Si tu sélectionnes le composant `Parent`, tu peux voir les props `greeting` et `response`, qui sont respectivement `Hello, Prop Drilling!` et `I'm not here to play!`.

Tu peux voir les props et mettre à jour l'état en temps réel, et les changer si nécessaire. Par exemple, tu peux sélectionner le composant `Grandchild` et changer la prop `greeting` de `Hello, Prop Drilling!` à `Hello, Welcome to Prop Drilling!`, et le voir reflété sur la page immédiatement.

Pour journaliser les données d'un composant dans la console, inspecter les éléments DOM correspondants et voir le code source du composant. Les icônes en haut à droite te permettent de faire ça. Si tu sélectionnes le composant `Grandchild` et cliques sur le bouton `Log the component data to the console`, cela journalisera les props, l'état, les Hooks, les nœuds et d'autres données dans la console.

Un bug courant que tu pourrais rencontrer en React s'appelle le props mismatch.

Par exemple, disons que pour le composant `Child`, tu passes par erreur `reply` comme prop au lieu de `response` :

```jsx
const Child = ({ greeting, response }) => {
  return <Grandchild greeting={greeting} reply={response} />;
};
```

Souviens-toi que `Grandchild` attend une prop `response`. Parce que le composant reçoit une prop différente, il ne peut pas afficher ce texte sur la page, et ajoute juste un `h2` vide au DOM. À la place, tu verras juste l'élément `h1` avec le texte `Hello, Prop Drilling!`, avec les autres boutons et textes déjà sur la page. L'élément `h2` vide est toujours là, mais comme il est vide, tu ne peux pas le voir sans inspecter le DOM.

Pour corriger ça, tu peux inspecter la progression des props depuis le composant `Parent` jusqu'au `Child` et éditer le nom de la prop directement. Si tu vas dans l'onglet Components, sélectionnes le composant `Child`, et changes la prop `reply` en `response`, tu verras l'élément `h2` sur la page avec le texte `I'm not here to play!`.
