# --description--

Les React Server Components (RSCs) sont une nouvelle tendance qui a changé la façon dont les développeurs React abordent les choses. Avec les RSCs, plus de travail se déplace vers le serveur, ce qui a beaucoup d'avantages.

Voyons ce que sont les server components, comment ils fonctionnent, et ce qui a mené à l'introduction des server components.

Les React Server Components sont des composants React qui se rendent exclusivement sur le serveur, lequel n'envoie que le HTML final au client. Cela signifie que ces composants peuvent accéder directement aux ressources côté serveur et réduire dramatiquement la quantité de JavaScript envoyée au navigateur.

Les apps React ont traditionnellement utilisé un système de « client component » qui gère tout dans une app React typique, comme le rendu, l'interactivité et les effets de bord. Le terme « client component » était rarement utilisé jusqu'à l'introduction récente des React server components.

Mais le système de client component vient avec des inconvénients comme de gros bundles JavaScript et des temps de chargement initial plus lents.

Des frameworks React comme Next.js et Gatsby ont trouvé des contournements pour décharger certains processus vers le serveur afin de corriger ces problèmes, mais aucun n'était standardisé. Si tu as utilisé l'un ou l'autre framework, tu as probablement entendu parler de `getServerSideProps` et `getServerData`.

Puis sont venus les React Server Components, qui te laissent exécuter certains composants entièrement sur le serveur pour pouvoir faire des choses comme la récupération de données et le calcul avant que du code ne tourne dans le navigateur de l'utilisateur.

Les server components ont d'abord été popularisés et sont facilement disponibles dans Next.js. D'autres frameworks comme Remix et Gatsby rattrapent, et il y a un plugin expérimental pour Vite appelé `vite-plugin-react-server` qui te laisse construire des server components.

Alors comment fonctionnent les server components ?

Une des meilleures façons de démontrer les React Server Components est avec la récupération de données.

Dans les client components React traditionnels, tu laisses le navigateur gérer les requêtes API. Comme la récupération de données est un effet de bord, tu fais cet appel API dans un Hook `useEffect`.

C'est aussi une bonne pratique de définir des variables d'état comme loading, data et error pour indiquer que les données chargent, afficher les données quand elles sont prêtes, ou afficher une erreur dans ton app.

Avec les React Server Components, tu peux déplacer le composant entier vers le serveur et y récupérer des données sans avoir à utiliser `useState` ou `useEffect` :

```jsx
const Users = async () => {
  const res = await fetch("https://jsonplaceholder.typicode.com/users");
  const users = await res.json();

  return (
    <>
      <h1 className="text-4xl text-center mt-6">Users</h1>
      <ul className="text-center mt-3">
        {users.map((user) => (
          <li key={user.id}>{user.name}</li>
        ))}
      </ul>
    </>
  );
};

export default Users;
```

Parce que les React Server Components ne tournent que sur le serveur, tu peux juste récupérer des données depuis une API et rendre une seule fois. Aussi, comme la récupération de données se passe sur le serveur, plus près de la source, ton app peut mieux performer, surtout pour les gens avec des connexions réseau lentes.

Un piège majeur est que tout le code des server components reste sur le serveur, et n'est pas envoyé au navigateur. Cela signifie que tu ne peux pas utiliser les Hooks React avec eux, et qu'ils n'ont pas accès aux Web APIs ou aux écouteurs d'événements du navigateur. Alors comment peux-tu ajouter de l'interactivité ?

Dans le app router de Next.js, tous les composants sont des server components par défaut. Si tu veux ajouter de l'interactivité, tu dois marquer le composant comme client component avec la directive `"use client"`.

Disons que tu veux faire du précédent exemple un client component. Voici comment tu peux le faire :

```jsx
"use client";

import { useState, useEffect } from "react";

const Users2 = () => {
  const [status, setStatus] = useState({
    users: [],
    loading: true,
    error: null,
  });

  async function fetchUsers() {
    try {
      const res = await fetch("https://jsonplaceholder.typicode.com/users");
      const data = await res.json();
      setStatus((prevStatus) => ({
        ...prevStatus,
        users: data,
        loading: false,
      }));
    } catch (err) {
      setStatus((prevStatus) => ({
        ...prevStatus,
        error: err.message,
        loading: false,
      }));
    }
  }

  useEffect(() => {
    fetchUsers();
  }, []);

  if (status.loading) {
    return <p>Loading Users...</p>;
  }
  if (status.error) {
    return <p>Error getting users: {status.error}</p>;
  }

  return (
    <>
      <h1 className="text-4xl text-center mt-6">Users</h1>
      <ul className="text-center mt-3">
        {status.users.map((user) => (
          <li key={user.id}>{user.name}</li>
        ))}
      </ul>
    </>
  );
};

export default Users2;
```

Si tu veux ajouter de l'interactivité comme des événements de clic, le composant doit aussi être marqué comme client component :

```jsx
"use client";

import { useState } from "react";

const Counter = () => {
  const [count, setCount] = useState(0);

  return (
    <>
      <h1>Counter</h1>
      <button onClick={() => setCount(count + 1)}>Increment</button>
      <h2>{count}</h2>
      <button onClick={() => setCount(count - 1)}>Decrement</button>
    </>
  );
};

export default Counter;
```

Si tu n'ajoutes pas la directive use client au composant, tu obtiens une erreur avec un message qui dit « You're importing a server component that needs `useState`. This React hook only works in a client component. To fix, mark the file (or its parent) with the `"use client"` directive. »

Les principaux avantages des React Server Components sont que la récupération de données devient plus simple, le code est plus facile à lire, et la complexité client est réduite.
