# --description--

Apprenons comment l'événement `submit` fonctionne avec les formulaires HTML. D'abord, nous devons comprendre comment soumettre un formulaire. Il y a trois façons de soumettre un formulaire.

La première est quand l'utilisateur clique sur un bouton du formulaire dont l'attribut `type` est défini à `submit`.

La deuxième est quand l'utilisateur appuie sur la touche Entrée sur n'importe quel champ de saisie éditable du formulaire.

La troisième passe par un appel JavaScript aux méthodes `requestSubmit()` ou `submit()` de l'élément formulaire.

Mais que se passe-t-il quand un formulaire est soumis ? Plusieurs choses se produisent, et le comportement du formulaire dépend de ses attributs.

Le premier attribut que nous devons examiner est l'attribut `action`. L'attribut `action` doit contenir soit une URL, soit un chemin relatif pour le domaine actuel. Cette valeur détermine où le formulaire tente d'envoyer les données. Si tu ne définis pas d'attribut `action`, le formulaire enverra les données à l'URL de la page actuelle. Voici un exemple de formulaire avec un attribut `action` défini sur une URL spécifique :

```html
<form action="https://freecodecamp.org">
  <input type="number" id="input" placeholder="Enter a number" name="number" />
  <button type="submit">Submit</button>
</form>
```

Quand ce formulaire est soumis, il enverra les données à la page d'accueil de freeCodeCamp, ce qui ne fera probablement rien.

Voici un autre formulaire, qui soumet vers un chemin relatif :

```html
<form action="/data">
  <input type="number" id="input" placeholder="Enter a number" name="number" />
  <button type="submit">Submit</button>
</form>
```

Celui-ci soumet vers le chemin `/data` sur le domaine actuel. Dans notre cas, il soumettrait vers `http://127.0.0.1:5500/data`.

Le deuxième attribut pour contrôler le comportement d'une soumission est l'attribut `method`. Cet attribut accepte une méthode HTTP standard, comme `GET` ou `POST`, et utilise cette méthode lors de la requête vers l'URL `action`.

HTTP signifie Hypertext Transfer Protocol et il est utilisé pour transférer des données sur le web.

Les méthodes HTTP sont utilisées pour définir les actions qui peuvent être effectuées sur des ressources, comme `GET`, `POST`, `PUT`, `DELETE`, et ainsi de suite. Tu en apprendras davantage sur ces méthodes dans de futures leçons.

Quand une méthode n'est pas définie, le formulaire utilisera par défaut une requête `GET`. Une requête `GET` est utilisée pour récupérer des données depuis une ressource spécifiée sans y apporter de modifications, et les paramètres sont typiquement ajoutés à l'URL sous forme de chaîne de requête.

Les données du formulaire seront encodées en URL sous forme de paires `name=value` et ajoutées à l'URL `action` comme paramètres de requête. Par exemple, en soumettant le formulaire de notre exemple précédent avec la valeur `3342` pour le champ `input`, le formulaire essaierait de faire un `GET` sur l'URL `http://127.0.0.1:5500/data?number=3342`.

C'est idéal pour quelque chose comme un formulaire de recherche, où ton utilisateur interroge des données. Mais si tu veux que ton utilisateur soumette de nouvelles données, comme dans un formulaire d'inscription, la méthode idiomatique à utiliser serait la méthode `POST`. La méthode `POST` est utilisée pour envoyer des données au serveur afin de créer ou mettre à jour une ressource.

Définissons l'attribut `method` à la valeur `POST` :

```xml
<form action="/data" method="POST">
  <input type="number" id="input" placeholder="Enter a number" name="number" />
  <button type="submit">Submit</button>
</form>
```

Quand tu envoies une requête `POST`, un corps peut être inclus qui contient les données de ta requête. Donc contrairement à un `GET`, les données ne sont pas ajoutées à l'URL, et notre formulaire envoie la requête `POST` à `http://127.0.0.1:5500/data`. Les données, à la place, se trouvent dans le corps de la requête, toujours sous forme de données de formulaire encodées en URL.

Les données de formulaire encodées en URL, c'est quand les données du formulaire sont converties en une chaîne de paires clé-valeur, comme `name=John+Doe&email=john%40example.com`, où les caractères spéciaux sont remplacés par des versions encodées pour envoyer les données en toute sécurité sur le web. Tu en apprendras davantage à ce sujet dans de futures leçons.

Mais peut-être que tu ne veux pas envoyer les données sous forme de charge utile de formulaire encodée en URL ?

L'élément `form` accepte un attribut `enctype`, qui représente le type d'encodage à utiliser pour les données.

Cet attribut n'accepte que trois valeurs : `application/x-www-form-urlencoded` (qui est la valeur par défaut, envoyant les données comme un corps de formulaire encodé en URL), `text/plain` (qui envoie les données en texte brut, en paires `name=value` séparées par des nouvelles lignes), ou `multipart/form-data`, qui est spécifiquement destiné à gérer les formulaires avec un téléversement de fichier.

Dans cette leçon, tu as appris les bases des soumissions de formulaires. Dans de futures leçons, nous irons plus loin dans le travail avec les formulaires et la façon dont ils interagissent avec le serveur.
