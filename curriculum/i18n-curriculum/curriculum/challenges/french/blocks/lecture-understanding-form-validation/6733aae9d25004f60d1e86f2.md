# --interactive--

Dans une leçon précédente, tu as appris comment utiliser HTML pour restreindre les valeurs que tes utilisateurs peuvent soumettre dans ton formulaire. Mais parfois, ce n'est pas suffisant. Si tu veux aller plus loin, comme afficher tes propres messages d'erreur à l'utilisateur, tu auras besoin d'utiliser JavaScript.

Certains éléments HTML, comme les éléments `textarea` et `input`, exposent une Constraint Validation API. Cette API te permet de vérifier que la valeur fournie par l'utilisateur pour cet élément passe toute validation au niveau HTML que tu as écrite, comme une longueur minimale ou une correspondance de motif.

Mais comment peux-tu réellement l'utiliser ? Imaginons que tu veuilles que les employés d'une entreprise envoient des messages de feedback via un formulaire comme celui-ci :

:::interactive_editor

```html
<link rel="stylesheet" href="styles.css" />
<form>
  <label>Enter your email: </label>
  <input required type="email" />

  <label>Enter your feedback: </label>
  <textarea required placeholder="Your feedback here..."></textarea>

  <button type="submit">Submit Feedback</button>
</form>
```

Nous utilisons l'`input` email qui vient avec une validation intégrée pour vérifier des validations de base, comme si la saisie contient le signe arobase (`@`).

Mais que se passe-t-il si l'utilisateur fournit une adresse e-mail comme `example@email.com` ? Cela passerait la validation de base, mais nous voulons être plus spécifiques en n'acceptant que les e-mails provenant d'une adresse e-mail d'entreprise.

C'est là que nous pouvons utiliser l'attribut `pattern` pour spécifier que l'adresse e-mail doit se terminer par une adresse e-mail d'entreprise. Voici à quoi ressemblera l'exemple mis à jour :

```html
  <label>Enter your feedback: </label>
```

Dans l'exemple ci-dessus, nous avons récupéré notre input depuis le DOM, et ajouté un écouteur d'événement input.

Nous savons que `e.target` fait référence à l'élément qui a déclenché l'événement. Dans ce cas, notre `input`. Mais qu'est-ce que la méthode `checkValidity()` ?

Cela fait partie de la Constraint Validation API. La méthode `checkValidity()` renvoie `true` si l'élément correspond à toute la validation HTML (selon ses attributs), et `false` s'il échoue.

Quand nous essayons avec une saisie invalide, nous voyons `false` s'afficher dans la console. Maintenant que nous savons que la saisie est invalide, reportons l'invalidité :

```js
  if (!e.target.checkValidity()) {
    e.target.reportValidity();
  }
})
```

Et en conséquence, tu verras le message d'erreur du navigateur "Please match the requested format."

Elle signale l'état invalide immédiatement, au lieu d'attendre que nous soumettions le formulaire. Mais elle utilise encore le message par défaut. C'est parce que la méthode `reportValidity` indique seulement au navigateur que la saisie est invalide. Le navigateur choisit encore comment afficher pourquoi elle est invalide. C'est là qu'intervient la méthode `setCustomValidity`.

```js
const input = document.querySelector("input");

input.addEventListener("input", (e) => {
  if (!e.target.checkValidity()) {
    e.target.setCustomValidity(
      "You must use a company email address that ends in @sampleCompany.com"
    );
  }
});
```

Cette méthode accepte un message d'erreur personnalisé, qui est affiché à l'utilisateur. En conséquence, tu verras le message d'erreur personnalisé `You must use a company email address that ends in @sampleCompany.com`.

La propriété `validity` est une instance de l'objet `ValidityState`. Voici un exemple de ce à quoi l'objet pourrait ressembler dans le navigateur :

```js
ValidityState {
  badInput: false,
  customError: false,
  patternMismatch: true,
  rangeOverflow: false,
  rangeUnderflow: false,
  stepMismatch: false,
  tooLong: false,
  tooShort: false,
  typeMismatch: true,
  valueMissing: false,
  valid: true
}
```

Il y a plusieurs propriétés utiles qui contiennent toutes la valeur d'un booléen `true` ou `false`.

Parmi ces propriétés utiles que tu peux explorer par toi-même, il y a la propriété `valueMissing` qui vaut `true` quand un champ de saisie obligatoire est laissé vide. Ou la propriété `patternMismatch` qui vaut `true` si la valeur ne correspond pas au motif d'expression régulière spécifié.

Après cette leçon, je t'encourage à jouer avec les exemples donnés dans cette leçon et à explorer davantage les différentes propriétés de validité.
