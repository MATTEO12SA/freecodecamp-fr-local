# --interactive--

En JavaScript, `null` et `undefined` sont deux types de données distincts qui représentent l'absence de valeur, mais ils se comportent différemment dans les comparaisons. Comprendre comment ces types interagissent dans divers scénarios de comparaison est crucial pour écrire un code robuste et sans bugs.

Commençons par le type `undefined`. Une variable est `undefined` quand elle a été déclarée mais qu'aucune valeur ne lui a été affectée. C'est la valeur par défaut des variables non initialisées et des paramètres de fonction auxquels aucun argument n'a été fourni.

Le type `null`, en revanche, est une valeur d'affectation qui représente une non-valeur délibérée. Il est souvent utilisé pour indiquer qu'une variable n'a intentionnellement aucune valeur.

Quand on compare `null` et `undefined` à l'aide de l'opérateur d'égalité (`==`), JavaScript effectue une coercition de type. Cela signifie qu'il essaie de convertir les opérandes vers le même type avant de faire la comparaison. Dans ce cas, `null` et `undefined` sont considérés comme égaux :

:::interactive_editor

```js
console.log(null == undefined); // true
```

:::

Cependant, quand on utilise l'opérateur d'égalité stricte (`===`), qui vérifie à la fois la valeur et le type sans effectuer de coercition de type, `null` et `undefined` ne sont pas égaux :

:::interactive_editor

```js
console.log(null === undefined); // false
```

:::

Cette différence est importante à garder à l'esprit quand tu écris des instructions conditionnelles ou que tu effectues des vérifications d'égalité dans ton code. Quand on compare `null` ou `undefined` avec d'autres valeurs à l'aide de l'opérateur d'égalité (`==`), le comportement peut être inattendu. Par exemple :

:::interactive_editor

```js
console.log(null == 0);  // false
console.log(null == ''); // false
console.log(undefined == 0); // false
console.log(undefined == ''); // false
```

:::

Ces comparaisons renvoient `false` car `null` et `undefined` ne sont égaux qu'entre eux (et à eux-mêmes) lorsqu'on utilise l'opérateur d'égalité. Le comportement de `null` dans d'autres comparaisons est particulièrement délicat :

:::interactive_editor

```js
console.log(null > 0);  // false
console.log(null == 0); // false
console.log(null >= 0); // true
```

:::

`undefined`, en revanche, se convertit toujours en `NaN` dans les contextes numériques, ce qui fait que toutes les comparaisons numériques avec `undefined` renvoient `false` :

:::interactive_editor

```js
console.log(undefined > 0);  // false
console.log(undefined < 0);  // false
console.log(undefined == 0); // false
```

:::

Compte tenu de ces nuances, il est généralement recommandé d'utiliser l'opérateur d'égalité stricte lors de la comparaison de valeurs, surtout quand on manipule `null` et `undefined`. Cette approche aide à éviter une coercition de type inattendue et rend le comportement de ton code plus prévisible.

En résumé, bien que `null` et `undefined` soient tous deux utilisés pour représenter l'absence de valeur, ils se comportent différemment dans les comparaisons. Comprendre ces différences est essentiel pour écrire un code JavaScript clair et sans erreurs.
