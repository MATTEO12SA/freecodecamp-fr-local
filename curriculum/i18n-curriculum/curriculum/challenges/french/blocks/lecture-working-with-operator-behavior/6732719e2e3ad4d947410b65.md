# --interactive--

Si tu écris une expression comportant plusieurs opérateurs en JavaScript, comment JavaScript décide-t-il lequel évaluer en premier ? C'est là qu'intervient la précédence des opérateurs. Explorons la précédence des opérateurs en détail avec des exemples de code, ainsi que ce qui se passe quand des opérateurs ont la même précédence.

La précédence des opérateurs détermine l'ordre dans lequel les opérations sont évaluées dans une expression. Les opérateurs ayant une précédence plus élevée sont évalués avant ceux ayant une précédence plus faible. Vois la précédence des opérateurs comme en mathématiques, où la division et la multiplication s'effectuent avant l'addition et la soustraction.

Sans suivre cette règle, des équations basiques te donneraient un mauvais résultat. JavaScript fonctionne de la même manière. Il a ses propres règles pour déterminer quels opérateurs viennent en premier, en deuxième, et ainsi de suite. Par exemple, regarde l'expression ci-dessous :

:::interactive_editor

```js
const result = 2 + 3 * 4;

console.log(result); // 14
```

:::

Si JavaScript évaluait cette expression de gauche à droite, tu t'attendrais à `2 + 3 = 5`, puis `5 * 4 = 20`. Mais comme la multiplication a une précédence plus élevée que l'addition, JavaScript évalue d'abord la partie `3 * 4`, ce qui donne `2 + 12 = 14`.

Parfois, tu peux vouloir que certaines parties de ton expression s'exécutent en premier, indépendamment des règles de précédence. Tu peux utiliser des parenthèses, `()`, pour cela. Tout ce qui se trouve à l'intérieur des parenthèses est évalué en premier, quoi qu'il arrive. Faisons en sorte que la partie `2 + 3` de l'exemple précédent soit évaluée en premier :

:::interactive_editor

```js
const result = (2 + 3) * 4;

console.log(result); // 20
```

:::

Dans l'exemple ci-dessus, les parenthèses forcent JavaScript à évaluer `2 + 3` en premier, puis à multiplier le résultat par `4`. Cela te donne `20` au lieu de `14`.

L'opérateur de division a lui aussi plus de précédence que l'addition ou la soustraction :

:::interactive_editor

```js
const result = 2 + 6 / 3;

console.log(result); // 4
```

:::

Si JavaScript évaluait cette expression de gauche à droite, tu pourrais t'attendre à `2 + 6 = 8`, puis `8 / 3 = 2.67`. Mais comme la division a une précédence plus élevée que l'addition, JavaScript évalue d'abord la division : `6 / 3 = 2`, puis additionne `2 + 2`, donnant le résultat `4`.

Ainsi, pour la multiplication comme pour la division, ces opérations auront toujours lieu avant l'addition et la soustraction, sauf si tu utilises des parenthèses pour changer l'ordre. Alors que se passe-t-il si les opérateurs ont la même précédence ? JavaScript utilise l'associativité pour déterminer l'ordre dans lequel les évaluer.

L'associativité, c'est ce qui indique à JavaScript s'il faut évaluer les opérateurs de gauche à droite ou de droite à gauche. Pour la plupart des opérateurs comme l'addition et la multiplication, l'associativité va de gauche à droite. JavaScript les traite donc depuis l'extrême gauche de l'expression vers la droite :

:::interactive_editor

```js
const result = 10 - 2 + 3;

console.log(result); // 11
```

:::

D'abord, `10 - 2 = 8`, puis `8 + 3 = 11`. JavaScript va de gauche à droite dans ce cas. Certains opérateurs, comme l'affectation (`=`), sont associatifs de droite à gauche. Cela signifie que le côté droit de l'expression est évalué en premier :

:::interactive_editor

```js
let a, b;
a = b = 5;

console.log(a); // 5
console.log(b); // 5
console.log(a + b); // 10
```

:::

Dans l'exemple ci-dessus, JavaScript affecte d'abord `5` à `b`, puis affecte `b` (qui vaut maintenant `5`) à `a`.

L'opérateur d'exposant est lui aussi associatif de droite à gauche :

:::interactive_editor

```js
const result = 2 ** 3 ** 2;

console.log(result); // 512
```

:::

D'abord, JavaScript évalue `3 ** 2`, qui vaut `9`, puis il évalue `2 ** 9`, qui vaut `512`. Si l'opérateur d'exposant avait une associativité de gauche à droite, JavaScript aurait d'abord calculé `2 ** 3` pour obtenir `8`, puis `8 ** 2` pour obtenir `64`.
