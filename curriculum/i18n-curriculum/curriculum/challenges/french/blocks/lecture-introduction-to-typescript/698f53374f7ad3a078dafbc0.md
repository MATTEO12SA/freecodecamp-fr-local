# --description--

Dans cette leçon, tu apprendras à ajouter des types pour les objets et les tableaux.

Regardons d’abord les tableaux.

Voici un exemple d’un tableau de langages de programmation :

```js
const programmingLanguages = ["Java", "C++", "Python"];
```

Si tu voulais typer explicitement ce tableau comme un tableau de chaînes, tu peux le typer comme `string[]` :

```ts
const programmingLanguages:string[] = ["Java", "C++", "Python"];
```

Comme tu l’as appris plus tôt, TypeScript sera assez intelligent pour inférer le type comme un tableau de chaînes si tu écris simplement ceci :

```js
const programmingLanguages = ["Java", "C++", "Python"];
```

Mais le typer explicitement aidera dans les situations où tu tentes d’ajouter un autre type au tableau comme ceci :

```ts
// Type 'number' is not assignable to type 'string'.(2322)
const programmingLanguages:string[] = ["Java", 9, "Python"];
```

Une autre façon de typer les tableaux est d’utiliser cette syntaxe :

```ts
const programmingLanguages:Array<string> = ["Java", "C++", "Python"];
```

Fondamentalement, ces deux syntaxes sont les mêmes, et le choix entre les deux est généralement une question de préférence.

Maintenant, regardons le typage des objets.

Voici un exemple d’un littéral d’objet :

```js
const developer = {
  firstName: "Jessica",
  isEmployed: true
}
```

Pour typer explicitement les propriétés de l’objet, tu peux utiliser cette syntaxe :

```ts
const developer: { firstName: string, isEmployed: boolean } = {
  firstName: "Jessica",
  isEmployed: true
}
```

Si tu essaies d’ajouter ou de retirer des propriétés de l’objet, tu obtiendras une erreur comme celle-ci :

```ts
// Property 'isEmployed' is missing in type '{ firstName: string; }' but required in type '{ firstName: string; isEmployed: boolean; }'
const developer: { firstName: string, isEmployed: boolean } = {
  firstName: "Jessica",
}
```

Tu peux rendre des propriétés d’objet optionnelles en utilisant `?` après le nom de la propriété, comme ceci :

```ts
const developer: { firstName: string, isEmployed?: boolean } = {
  firstName: "Jessica",
}
```

TypeScript n’affichera plus d’erreur parce que la propriété `isEmployed` a été marquée comme optionnelle.

Jusqu’ici, tous les exemples d’objets avaient des propriétés restrictives. Cela signifie qu’on a listé explicitement chaque propriété que l’objet est autorisé à avoir :

```ts
const developer: { firstName: string, isEmployed: boolean } = {
  firstName: "Jessica",
  isEmployed: true
}
```

Mais que se passe-t-il si tu ne connais pas à l’avance tous les noms de propriétés ? Et si tu veux un objet qui peut avoir un nombre quelconque de propriétés, mais dont toutes les valeurs doivent suivre un type précis ?

Eh bien, il y a deux façons d’y parvenir. La première est d’utiliser un `Record`, qui est un type utilitaire générique intégré en TypeScript.

Voici la syntaxe de base :

```ts
Record<Keys, ValueType>
```

Le premier type représente le type des clés, tandis que le second représente le type des valeurs.

Voici un exemple d’utilisation d’un `Record` pour un objet `userRoles` :

```ts
const userRoles: Record<string, string> = {
  admin: "full-access",
  editor: "limited-access",
  viewer: "read-only"
};
```

Cet objet `userRoles` peut avoir n’importe quelles clés de type string, et toutes les valeurs doivent être des chaînes. Si tu essaies d’assigner une valeur qui n’est pas une chaîne, tu obtiendras une erreur :

```ts
// Type 'number' is not assignable to type 'string'
const userRoles: Record<string, string> = {
  admin: 1
};
```

La deuxième façon d’écrire la même idée est avec une signature d’index :

```ts
const obj: { [key: string]: string } = {};
```

La syntaxe ci-dessus dit que toute propriété avec une clé string doit avoir une valeur string. Voici un exemple pour un objet `settings` :

```ts
const settings: { [key: string]: string } = {
  theme: "dark",
  language: "en",
  layout: "grid"
};
```

Comme précédemment, si tu as des types de valeurs incorrects, TypeScript affichera un message d’erreur :

```ts
// Type 'boolean' is not assignable to type 'string'
const settings: { [key: string]: string } = {
  darkMode: true
};
```

Les `Record` et les signatures d’index sont fondamentalement les mêmes. Choisir entre eux est surtout une question de préférence.
