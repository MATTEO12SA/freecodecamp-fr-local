# --description--

Dans cette leçon, tu apprendras à travailler avec les types primitifs de base et comment les annotations de type fonctionnent pour les variables.

Pour les types de données primitifs `string`, `null`, `undefined`, `number`, `boolean` et `bigint`, TypeScript propose des mots-clés de type correspondants.

Pour cette leçon, on se concentrera sur les primitifs couramment utilisés et on n’entrera pas dans les détails de `bigint`. Le type de données `bigint` est un type numérique en JavaScript pour représenter des nombres plus grands que le type entier standard.

Regardons chacun de ces types primitifs en commençant par `string`. Voici comment tu peux typer une chaîne en TypeScript :

```ts
let firstName: string = "Angie";
```

Contrairement au JavaScript classique, la variable `firstName` attend un type `string`. Donc si tu essaies de la réassigner avec une valeur numérique, tu obtiendras une erreur comme celle-ci :

```ts
let firstName: string = "Angie";
firstName = 9 // Type 'number' is not assignable to type 'string'.
```

Le prochain type que nous allons examiner est le type `number`. Voici un exemple :

```ts
let age: number = 16;
```

Tu peux assigner des entiers et des flottants au type `number`. Mais si tu essayais de réassigner une valeur de type `bigint`, tu obtiendrais une erreur comme celle-ci :

```ts
let age: number = 16;

// Type 'bigint' is not assignable to type 'number'.
age = 123n;
```

Le prochain type que nous allons examiner est le type `boolean`. Voici quelques exemples :

```ts
let isLoggedIn: boolean = true;
let isAdmin: boolean = false;
```

Les deux derniers types sont les types `null` et `undefined`.

Comme tu te souviens des leçons JavaScript précédentes, `null` représente une absence intentionnelle de valeur. `undefined` signifie qu’une variable a été déclarée mais qu’aucune valeur ne lui a été assignée.

Tu verras des exemples d’utilisation de ces types plus tard, quand tu apprendras les types de fonctions et les types union.

Maintenant que tu as vu comment les annotations de type fonctionnent avec les variables, la question se pose : faut-il toujours typer explicitement tes variables ?

Si tu as une annotation de type simple comme celle-ci, tu n’as peut-être pas besoin d’un type explicite.

```ts
let firstName: string = "Angie";
```

La raison est que TypeScript essaiera d’inférer automatiquement les types à partir de la valeur. Donc si tu écris ceci, TypeScript comprendra que c’est une chaîne.

```js
let firstName = "Angie";
```

Tu devrais typer explicitement tes variables quand TypeScript ne peut pas clairement inférer le type, ou quand tu veux imposer un type précis — par exemple pour des paramètres de fonction ou des objets complexes.
