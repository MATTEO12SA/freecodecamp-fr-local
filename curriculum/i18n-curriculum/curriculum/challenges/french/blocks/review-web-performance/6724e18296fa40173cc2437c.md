## Différences entre performance réelle et performance perçue

- **Performance perçue** : C'est la façon dont les utilisateurs perçoivent la performance d'un site web. Ils l'évaluent en termes de réactivité et de fiabilité. C'est une mesure subjective, donc difficile à quantifier, mais très importante, car l'expérience utilisateur détermine le succès ou l'échec d'un site.
- **Performance réelle** : C'est la performance objective et mesurable du site. Elle se mesure avec des métriques comme le temps de chargement de la page, le temps de réponse du serveur et le temps de rendu. Ces mesures dépendent de plusieurs facteurs liés au réseau et au code lui-même.

## Techniques pour améliorer la performance perçue

- **Lazy loading** : Cette technique réduit autant que possible le temps de chargement initial en chargeant les ressources non essentielles en arrière-plan.
- **Minimiser les délais de polices** : Si ton site utilise des polices personnalisées, tu devrais aussi essayer de minimiser les délais de chargement des polices, car cela peut provoquer un scintillement ou l'affichage de la police de secours pendant le chargement. Une suggestion est d'utiliser une police de secours proche de la police personnalisée, pour que le changement soit plus subtil.
- **Indicateurs de chargement** : Afficher un indicateur de chargement pour un processus long dès que l'utilisateur clique sur un élément peut l'aider à se sentir connecté et engagé, ce qui raccourcit la sensation d'attente.

## Concepts clés de performance

- **Ordre source** : Cela désigne la façon dont les éléments HTML sont structurés dans le document. Cela détermine ce qui se charge en premier et peut fortement impacter la performance et l'accessibilité.

Quelques bonnes pratiques pour l'ordre source incluent :

- Placer le contenu critique comme les titres, la navigation ou le texte principal plus haut dans la structure HTML.
- Différer les scripts non essentiels comme ceux d'analytique ou les widgets tiers, pour qu'ils ne bloquent pas le rendu.
- Utiliser l'amélioration progressive, pour que l'expérience de base fonctionne même avant le chargement des styles et scripts. L'amélioration progressive consiste à construire des sites et applications en partant du principe que ta page doit d'abord fonctionner avec HTML.

Voici un exemple de bon ordre source, en suivant les bonnes pratiques qu'on vient de voir :

```html
<h1>Welcome to FastSite!</h1>
<p>Critical information loads first.</p>
<script src="slow-script.js" defer></script>
```

- **Critical Rendering Path** : C'est la séquence d'étapes que suit le navigateur pour convertir le code en pixels à l'écran.
- **Latence** : C'est le temps qu'une requête met pour aller du navigateur au serveur. Autrement dit, une latence élevée égale des pages lentes.

Quelques façons de réduire la latence :

- Utiliser des CDN, ou Content Delivery Networks, pour servir les fichiers depuis des emplacements plus proches.
- Activer la compression avec des outils comme Gzip pour réduire la taille des fichiers.
- Optimiser les images et utiliser le lazy loading.

```html
<img src="placeholder.jpg" data-src="real-image.jpg" loading="lazy">
```

## Améliorer l'INP

- **Définition** : L'INP (Interaction to Next Paint) évalue la réactivité globale d'une page en mesurant le temps entre une interaction utilisateur (clic ou touche) et la prochaine mise à jour de l'affichage par le navigateur. Un INP plus bas indique une page plus réactive.

Voici quelques façons d'améliorer l'INP :

- Réduire le travail du thread principal en découpant les longues tâches JavaScript.
- Utiliser `requestIdleCallback()` pour les scripts non critiques. Cela met une fonction en file d'attente pour qu'elle soit appelée pendant les périodes d'inactivité du navigateur.
- Différer ou lazy-loader les assets lourds, comme vu plus tôt.
- Optimiser les gestionnaires d'événements. S'ils s'exécutent trop souvent ou font des opérations lourdes, ils peuvent ralentir la page et augmenter l'INP. La solution est le debouncing. Le debouncing fait en sorte que la fonction ne s'exécute qu'après que l'utilisateur a arrêté de taper pendant un court délai — par exemple 300 ms. Cela évite des calculs inutiles et améliore la performance.

## Comment le rendu fonctionne dans le navigateur

- **Comment fonctionne le rendu** : D'abord le navigateur parse le HTML et construit le DOM. Ensuite, il traite le CSS et construit le CSS Object Model, ou CSSOM. C'est une autre structure en arbre qui dicte comment les éléments doivent être stylés. Enfin, le navigateur peint les pixels à l'écran, en rendant chaque élément selon les styles et la mise en page calculés. Sur des pages complexes, cela peut impliquer plusieurs couches composées ensemble pour former le rendu final.

## Comment la performance impacte la durabilité

- **Contexte** : Internet représente environ 2 % des émissions mondiales de carbone — autant que l'industrie aérienne ! Chaque octet transféré consomme de l'électricité, des centres de données aux appareils des utilisateurs. Des fichiers plus lourds et des scripts inefficaces signifient plus de consommation d'énergie. Un site performant n'est pas seulement plus rapide : il réduit aussi le traitement et la consommation d'énergie inutiles.

## Façons de réduire les temps de chargement

- **Optimiser les médias** : Les grandes images et vidéos sont souvent responsables des chargements lents. En optimisant ces assets, tu peux accélérer nettement ton site. Cela inclut compresser les images, utiliser des formats modernes comme WebP et le lazy loading.
- **Tirer parti du cache navigateur** : Le cache permet aux navigateurs de stocker localement des parties de ton site, ce qui réduit les temps de chargement pour les visiteurs qui reviennent.
- **Minifier et compresser les fichiers** : Réduire la taille de tes fichiers accélère les téléchargements. Cela inclut réduire la taille des fichiers transmis et minifier le CSS et le JavaScript.

## Améliorer le « time to usable »

- **Définition** : Le « time to usable » est l'intervalle entre la demande d'une page par l'utilisateur et le moment où il peut interagir utilement avec elle. Pour l'améliorer, tu peux lazy-loader tes assets ou minimiser les ressources qui bloquent le rendu.

## Métriques clés pour mesurer la performance

- **First Contentful Paint ou FCP** : Elle mesure la vitesse à laquelle le premier contenu — texte ou image — apparaît à l'écran. Un bon FCP est en dessous de 1,8 seconde, et un mauvais FCP au-dessus de 3 secondes. Tu peux vérifier ton FCP avec Chrome DevTools, dans l'onglet Performance.
- **Total Blocking Time** : Cela montre combien de temps le thread principal est bloqué par de lourdes tâches JavaScript. Si le Total Blocking Time (TBT) est élevé, les interactions semblent lentes. Pour l'améliorer, découpe les longues tâches et diffère les scripts non essentiels.
- **Taux de rebond** : C'est le pourcentage de visiteurs qui partent sans interagir. Un taux de rebond élevé peut venir d'une page trop lente.
- **Utilisateurs uniques** : Cette métrique suit le nombre de visiteurs individuels. Pour voir le taux de rebond et les utilisateurs uniques, tu peux utiliser Google Analytics. Cela te permet de suivre ces métriques et d'améliorer l'engagement.

## Outils courants de mesure de performance

- **Chrome DevTools** : Chrome DevTools est un outil intégré à Google Chrome qui te permet d'analyser et de déboguer la performance en temps réel. DevTools montre les temps de chargement, l'usage CPU et les délais de rendu. C'est particulièrement utile pour mesurer le First Contentful Paint, ou FCP : la vitesse à laquelle un utilisateur voit le premier contenu visible. Si ton site semble lent, DevTools t'aidera à repérer les goulots d'étranglement.
- **Lighthouse** : C'est un outil automatisé qui vérifie la performance, le SEO et l'accessibilité.
- **WebPageTest** : Cet outil te permet de tester le chargement de ton site depuis différents lieux et appareils. Il te donne une analyse détaillée du Speed Index, du Total Blocking Time et d'autres métriques clés. Si tu veux savoir comment de vrais utilisateurs vivent ton site dans le monde, WebPageTest est l'outil adapté.
- **PageSpeed Insights** : Cet outil analyse ton site et suggère des améliorations rapides pour mobile et desktop. Il te dit ce qui ralentit ton site et donne des recommandations précises comme optimiser les images, retirer les scripts qui bloquent le rendu, et réduire les temps de réponse serveur. PageSpeed Insights est un moyen rapide et simple de voir comment Google perçoit la performance de ton site.
- **Real User Monitoring** : Les outils RUM suivent le comportement réel des utilisateurs, en montrant comment de vrais visiteurs vivent ton site. Parmi les outils RUM populaires : Google Analytics, qui suit les temps de chargement et les taux de rebond, et New Relic ou Datadog, qui surveillent les problèmes de performance en temps réel. Si tu veux des données de vrais utilisateurs, les outils RUM sont essentiels.

## Travailler avec les Performance Web APIs

- **Définition** : Les Performance Web APIs permettent aux développeurs de suivre dans le code l'efficacité du chargement et de la réactivité d'une page. Ces APIs te permettent de mesurer les temps de chargement, de suivre les délais de rendu et d'interaction, et d'analyser le temps d'exécution JavaScript.
- **`performance.now()`** : Cette API te donne des horodatages haute précision (en millisecondes) pour mesurer combien de temps différentes parties de ton site mettent à charger.

```js
const start = performance.now();
// Run some code here
const end = performance.now();

console.log(`Execution time: ${end - start}ms`);
```

- **Performance Timing API** : Cette API te donne une décomposition de chaque étape du chargement de page, de la résolution DNS à `DOMContentLoaded`.

```js
const timing = performance.timing;

const pageLoadTime = timing.loadEventEnd - timing.navigationStart;
console.log(`Page load time: ${pageLoadTime}ms`);
```

- **`PerformanceObserver`** : Cette API écoute les événements de performance comme les layout shifts, les longues tâches et les interactions utilisateur.

```js
const observer = new PerformanceObserver((list) => {
  list.getEntries().forEach((entry) => {
    console.log(`Long task detected: ${entry.duration}ms`);
  });
});

observer.observe({ type: "longtask", buffered: true });
```

## Techniques pour améliorer la performance CSS

- **Animations CSS** : Animer certaines propriétés CSS, comme les dimensions, la position et la mise en page, déclenche un processus appelé « reflow », pendant lequel le navigateur recalcule la position et la géométrie de certains éléments. Cela nécessite un repaint, coûteux en calcul. Il est donc recommandé de réduire le nombre d'animations CSS autant que possible, ou au moins de laisser l'utilisateur les activer ou les désactiver.

## Techniques pour améliorer la performance JavaScript

- **Code splitting** : Découper ton code JavaScript en modules pour les tâches critiques et non critiques est aussi utile. Ainsi, tu pourras précharger les modules critiques dès que possible et différer les non critiques pour rendre la page plus vite.
- **Manipulation du DOM** : Souviens-toi que la manipulation du DOM consiste à modifier dynamiquement le contenu d'une page avec JavaScript en interagissant avec le Document Object Model (DOM). Manipuler le DOM est coûteux en calcul. Réduire la quantité de manipulations DOM dans ton JavaScript améliorera la performance.
