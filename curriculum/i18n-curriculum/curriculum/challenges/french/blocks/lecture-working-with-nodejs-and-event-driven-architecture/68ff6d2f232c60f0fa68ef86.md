# --description--

Jusqu'ici, tu as écrit du code côté client avec JavaScript, du code qui s'exécute côté client d'une application web, généralement un navigateur web.

Le JavaScript côté client peut être très puissant, mais il a certaines limites pour des tâches plus complexes.

Par exemple :

- Il a un accès très restreint aux fichiers locaux.
- Il n'est pas vraiment conçu pour gérer une logique applicative complexe.
- Et il présente des risques de sécurité potentiels. Par exemple, tu ne voudrais pas exposer des informations sensibles, comme des identifiants de base de données, au code côté client.

Le JavaScript côté client a ces limites parce qu'il a été conçu initialement pour s'exécuter exclusivement dans les navigateurs web.

Les navigateurs web fournissent l'environnement nécessaire pour exécuter du code JavaScript, y compris le moteur JavaScript. Ils donnent aussi accès au Document Object Model (DOM), pour que tu puisses accéder aux éléments HTML dans ton code.

Auparavant, on ne pouvait pas exécuter JavaScript en dehors d'un navigateur, mais maintenant on le peut avec Node.js.

Node.js est un environnement d'exécution JavaScript. Il est officiellement défini comme « un environnement d'exécution JavaScript open source et multiplateforme ».

Voyons ce que cela signifie :

- Node.js est open source parce que son code est accessible publiquement et maintenu par une large communauté de développeurs.
- Il est multiplateforme parce qu'il fonctionne sur n'importe quel système d'exploitation, y compris Windows, macOS et Linux.
- Et c'est un environnement d'exécution JavaScript parce qu'il te permet d'exécuter du code JavaScript en dehors d'un navigateur.

Node.js est utilisé dans un large éventail d'industries. Les développeurs l'utilisent pour créer des serveurs web et des API qui gèrent des requêtes HTTP, ainsi que des applications web et mobiles.

Si tu utilises ou développes un site ou une application web qui interagit avec une base de données ou gère des données complexes, il y a de fortes chances que tu utilises Node.js en coulisses à un moment ou à un autre.

Il est efficace, scalable, et il dispose d'une large communauté de développeurs et de mainteneurs dans le monde entier.

Maintenant que tu sais ce qu'est Node.js, voyons quelques différences entre le navigateur et l'environnement d'exécution Node.

L'environnement du navigateur est principalement conçu pour le développement web front-end, donc il exécute du JavaScript côté client. En revanche, l'environnement d'exécution Node est principalement conçu pour le développement web back-end, donc il exécute du JavaScript côté serveur. Cela détermine aussi les API qu'ils proposent.

Par exemple, depuis le navigateur, tu peux accéder à l'API DOM, mais il y a des restrictions pour accéder au système de fichiers local. En revanche, depuis l'environnement d'exécution Node, tu peux accéder à presque toutes les ressources système, y compris le système de fichiers, mais pas au DOM.

Les deux environnements JavaScript fournissent un objet global. Dans l'environnement d'exécution JavaScript du navigateur, il s'appelle `window`. Cet objet `window` donne accès à des fonctionnalités liées au navigateur, comme des méthodes pour manipuler le DOM, gérer les cookies et traiter les événements du navigateur. Dans l'environnement Node.js, cet objet global s'appelle `global`. L'objet `global` donne accès à des fonctionnalités spécifiques à Node.js, comme des modules intégrés pour travailler avec les fichiers locaux, le réseau et interagir avec le système d'exploitation.

Enfin, une autre différence importante est que tu peux choisir la version de Node.js que tu veux utiliser sur ton serveur. En revanche, tu n'as aucun contrôle sur la version de l'environnement du navigateur que tes utilisateurs utiliseront pour visiter ton site.

Node.js est devenu très important pour les développeurs du monde entier. C'est un outil puissant, scalable et polyvalent qui a transformé le développement web en permettant aux développeurs d'utiliser JavaScript pour construire à la fois le front-end et le back-end d'applications full-stack. Cela a rendu le processus de développement plus efficace, car les développeurs n'ont pas besoin d'apprendre un nouveau langage de programmation uniquement pour développer le back-end.
