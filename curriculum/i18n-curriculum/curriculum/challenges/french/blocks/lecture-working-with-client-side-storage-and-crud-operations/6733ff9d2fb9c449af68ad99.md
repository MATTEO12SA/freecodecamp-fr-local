# --interactive--

Le stockage côté client permet aux sites web de stocker des données sur l'appareil d'un utilisateur. Cependant, comme beaucoup de technologies, il peut être mal utilisé.

Explorons quelques motifs négatifs associés au stockage côté client, en nous concentrant sur les cookies et leur mauvais usage pour le suivi et le fingerprinting.

Commençons par les cookies.

Dans une leçon précédente, tu as appris que les cookies sont des données stockées sur l'appareil d'un utilisateur lorsqu'il visite une application web. Un mauvais usage courant des cookies est le suivi excessif.

Les sites web utilisent des cookies pour suivre les interactions d'un utilisateur avec une application web, créant un historique de ses activités numériques. Cela est fait pour la publicité ciblée mais peut soulever d'importantes préoccupations en matière de vie privée.

Par exemple, un site de shopping pourrait utiliser un cookie de suivi comme ceci :

```js
document.cookie = "userID=123; path=/; expires=Thu, 18 Dec 2024 6:00:00 UTC";
```

Ce code définit un cookie nommé `userID` avec une valeur de `123`. Le cookie sera envoyé avec chaque requête vers le site, lui permettant de suivre les actions de l'utilisateur. Bien que cela puisse sembler inoffensif, imagine des centaines de sites partageant ces informations — cela pourrait créer une image très détaillée de ta vie en ligne et de tes choix.

Une autre pratique préoccupante est le fingerprinting de navigateur.

Cette technique utilise des informations côté client pour créer une « empreinte » unique du navigateur d'un utilisateur. Les sites web ont la capacité de collecter des informations sur ta version de navigateur, les plugins installés, la résolution d'écran et d'autres données pour t'identifier de façon unique.

Voici un exemple simple de la façon dont un site peut créer une empreinte de toi :

:::interactive_editor

```js
let fingerprintExample = navigator.userAgent + screen.width + screen.height;
console.log(fingerprintExample);
```

:::

Ce code combine l'agent utilisateur de ton navigateur avec les dimensions de ton écran. Bien que ce soit un exemple basique, les vraies méthodes de fingerprinting sont bien plus complexes et peuvent être très précises pour identifier les utilisateurs.

`localStorage` peut aussi être mal utilisé, car certains sites l'utilisent pour stocker des informations sensibles de façon non sécurisée. Par exemple :

```js
localStorage.setItem('userPassword', 'someonesPasswordHere');
```

Ce code stocke le mot de passe d'un utilisateur dans `localStorage`. C'est un risque de sécurité sérieux car les données dans `localStorage` ne sont pas chiffrées et peuvent être accessibles facilement.

En conclusion, bien que le stockage côté client offre de nombreux avantages, il est crucial de l'utiliser de façon responsable. Au fur et à mesure de ton parcours en développement web, considère toujours la vie privée et la sécurité des données de tes utilisateurs côté client.
