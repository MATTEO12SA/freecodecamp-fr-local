# --description--

L'API `Cache` est utilisée pour stocker des requêtes et réponses réseau, ce qui rend les applications web plus efficaces et leur permet même de fonctionner hors ligne. Elle fait partie de l'API Service Worker plus large et est essentielle pour créer des Progressive Web Apps (PWA) qui peuvent fonctionner dans des conditions réseau peu fiables ou lentes.

Avant de continuer avec l'API `Cache`, nous devons d'abord comprendre comment les service workers, les PWA et les requêtes réseau fonctionnent à un niveau de base.

Une requête réseau est une requête faite par un navigateur web ou une application à un serveur pour récupérer des données ou des ressources via Internet. Par exemple, lorsque tu visites un site web, ton navigateur envoie une requête réseau au serveur web pour obtenir les fichiers (comme le HTML, les images ou les vidéos) nécessaires pour afficher la page.

Un service worker est un type spécial de fichier JavaScript qui s'exécute en arrière-plan d'une application web, séparément du fil principal du navigateur. Il agit comme un intermédiaire entre la page web et le réseau, permettant aux développeurs d'intercepter les requêtes réseau, de mettre des ressources en cache, et de gérer des choses comme les notifications push ou la synchronisation en arrière-plan.

Une PWA, ou Progressive Web App, est un type d'application web qui utilise des technologies web modernes pour offrir une expérience proche d'une application native sur le web. Les PWA sont conçues pour fonctionner de façon fiable sur n'importe quel appareil, quelles que soient les conditions réseau, et peuvent être accessibles via un navigateur ou installées sur l'appareil d'un utilisateur comme une application traditionnelle.

Maintenant que nous comprenons mieux les service workers, les PWA et les requêtes réseau, nous pouvons approfondir l'API Cache.

L'API `Cache` est un mécanisme de stockage qui stocke des objets `Request` et `Response`. Lorsqu'une requête est faite à un serveur, l'application peut stocker la réponse et la récupérer plus tard depuis le cache au lieu de faire une nouvelle requête réseau. Cela réduit les temps de chargement, économise la bande passante et améliore l'expérience utilisateur globale.

Le navigateur fournit une zone de stockage appelée `CacheStorage`, où les développeurs peuvent enregistrer des paires clé-valeur de requêtes réseau et de leurs réponses correspondantes.

Avec l'en-tête `Cache-Control`, les développeurs peuvent spécifier combien de temps une ressource mise en cache doit rester stockée, ainsi que si elle doit être revalidée ou servie directement depuis le cache.

En utilisant l'API `Cache`, les développeurs peuvent construire des applications web offline-first, permettant par exemple à une PWA de servir des ressources mises en cache lorsque l'utilisateur est déconnecté du réseau.
