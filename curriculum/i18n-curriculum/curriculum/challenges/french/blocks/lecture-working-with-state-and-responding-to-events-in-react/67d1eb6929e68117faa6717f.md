# --description--

En React, le rendu est le processus par lequel les composants apparaissent dans l'interface utilisateur (UI), généralement le navigateur.

React prend tout ton code JavaScript, JSX et CSS, figure comment ça devrait apparaître, puis l'affiche dans l'interface utilisateur.

Le processus de rendu comporte trois étapes : trigger, render, et commit. Regardons-les plus en détail.

L'étape trigger se produit quand React détecte que quelque chose a changé et que l'interface utilisateur pourrait devoir être mise à jour. Ce changement est souvent dû à une mise à jour du state ou des props.

Par exemple, remarquer qu'il est l'heure du dîner peut te déclencher à aller dans la cuisine pour commencer à cuisiner.

Dans l'exemple `Counter` ci-dessous, cliquer sur le bouton d'incrémentation ou de décrémentation déclenche React pour afficher la nouvelle valeur de `count` :

```jsx
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <h1>{count}</h1>
      <button onClick={() => setCount(count - 1)}>Decrement</button>
      <button onClick={() => setCount(count + 1)}>Increment</button>
    </div>
  );
}

export default Counter;
```

Une fois le trigger survenu, React entre dans l'étape render. Ici, React réévalue tes composants et figure ce qu'il faut afficher.

Pour cela, React utilise une copie légère du « vrai » DOM. C'est ce qu'on appelle le virtual DOM. Avec le virtual DOM, React peut rapidement vérifier ce qui doit changer dans le composant.

Pense à cette étape comme le moment où tu es dans la cuisine, tu as rassemblé tes ingrédients, et tu cuisines ton dîner.

Pour le composant `Counter`, l'étape render est le moment où React exécute à nouveau les fonctions avec la nouvelle valeur de `count`. React recalcule à quoi la partie `<h1>{count}</h1>` du composant devrait ressembler d'après la valeur mise à jour de `count`, mais tu ne verras aucun changement à l'écran avant la prochaine étape – commit.

L'étape commit est celle où React prend les changements préparés depuis le virtual DOM et les applique au vrai DOM. Autrement dit, c'est l'étape où tu vois le résultat final à l'écran.

Pour y parvenir, React compare le virtual DOM au DOM réel, identifie uniquement les parties qui ont besoin de mises à jour, et applique ces changements au vrai DOM pour mettre à jour l'interface utilisateur.

Tu peux penser à cette étape comme le moment où tu sers la nourriture que tu as cuisinée, la rendant visible tout comme React le fait quand il commit les mises à jour au DOM réel.

Quant au composant `Counter`, l'étape commit est le moment où la nouvelle valeur de `count` est appliquée à l'élément `h1`, et tu peux voir le changement sur la page.

Ces trois processus sont extrêmement rapides car React minimise la manipulation directe du DOM en calculant d'abord les changements dans le virtual DOM, puis il ne met à jour que les parties qui doivent changer dans le vrai DOM.
