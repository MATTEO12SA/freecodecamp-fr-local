# --description--

La gestion des événements est une partie essentielle de tout site web interactif.

React fournit une façon puissante et cohérente de gérer les événements grâce à son Synthetic Event System, qui est une enveloppe autour des événements natifs comme `click`, `keydown`, et `submit` que tu as appris dans les leçons précédentes.

Cette enveloppe multi-navigateurs garantit que les événements fonctionnent de la même façon dans tous les navigateurs, sans incohérences.

Voyons comment les événements fonctionnent en React pour que tu puisses commencer à les utiliser dans tes projets.

En React, les gestionnaires d'événements fonctionnent de façon similaire aux événements natifs du navigateur, mais avec quelques ajustements.

Au lieu d'utiliser des noms d'attributs d'événement en minuscules comme `onclick` et `onsubmit`, React utilise le camelCase, comme `onClick` et `onSubmit`.

De plus, au lieu d'utiliser des chaînes pour spécifier le type d'événement, React attend une fonction pour le gestionnaire d'événement.

La fonction gestionnaire d'événement est passée à l'élément comme prop, et le type d'événement comme `onClick` ou `onSubmit` est utilisé comme attribut dans le JSX.

Voici un rappel de comment travailler avec un événement click en HTML classique :

```html
<button onclick="alert('Button clicked!')">Click Me</button>
```

Et voici comment tu fais la même chose en React :

```jsx
function handleClick() {
  console.log("Button clicked!");
}

<button onClick={handleClick}>Click Me</button>;
```

Dans cet exemple, `handleClick` journalise un message dans la console quand l'utilisateur clique sur le bouton.

Note que tu n'as pas besoin de parenthèses après `handleClick` dans l'attribut `onClick`, car tu passes une référence à la fonction, sans l'appeler.

En React, les fonctions gestionnaires d'événements commencent généralement par le préfixe `handle` pour indiquer qu'elles sont responsables de la gestion des événements, comme `handleClick` ou `handleSubmit`.

Quand une action utilisateur déclenche un événement, React passe un objet Synthetic Event à ton gestionnaire. Cet objet se comporte beaucoup comme l'objet événement natif en JavaScript vanilla, en fournissant des propriétés comme `type`, `target`, et `currentTarget`.

Tu peux passer `event` comme paramètre à la fonction gestionnaire et le journaliser dans la console pour regarder sa structure :

```js
function handleClick(event) {
  console.log(event);
}
```

Pour empêcher les comportements par défaut comme le rafraîchissement du navigateur pendant un événement `onSubmit`, par exemple, tu peux appeler la méthode `preventDefault()` :

```jsx
function handleSubmit(event) {
  event.preventDefault();
  console.log("Form submitted!");
}

<form onSubmit={handleSubmit}>
  <input type="text" />
  <button>Submit</button>
</form>;
```

Tu peux aussi empêcher un événement de remonter vers les éléments parents en appelant `event.stopPropagation()`.

Parfois, en gérant des cas spéciaux comme des fonctionnalités de suppression et d'édition, tu pourrais vouloir passer des données supplémentaires à un gestionnaire d'événement. Tu peux le faire en enveloppant le gestionnaire dans une fonction fléchée en ligne :

```jsx
function handleDelete(id) {
  console.log("Deleting item:", id);
}

<button onClick={() => handleDelete(1)}>Delete Item</button>;
```

Il est acceptable d'utiliser des gestionnaires d'événements en ligne en React car React gère efficacement les re-renders et évite les problèmes de performance.

En JavaScript vanilla, les gestionnaires d'événements en ligne peuvent entraîner des problèmes de performance en créant de nouvelles fonctions à chaque rendu, car il n'y a pas de virtual DOM pour optimiser le processus.
