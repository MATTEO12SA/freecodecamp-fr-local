# --description--

Il y aura des moments où tu as une valeur avec un type large et tu dois le restreindre à un type plus spécifique. Par exemple, tu dois peut-être t’assurer qu’un objet correspond à une interface que tu as définie. Ou qu’une chaîne fait partie d’une liste précise de valeurs. Il y a plusieurs façons d’y parvenir.

La première est le narrowing par vérité (truthiness). Prenons notre exemple de la leçon précédente :

```js
const email = document.querySelector<HTMLInputElement>("#email");
console.log(email.value);
```

On obtient une erreur de compilateur en essayant d’accéder à la propriété `value` de `email`, car `email` pourrait être `null`. Cependant, on peut utiliser une instruction conditionnelle pour confirmer que `email` est truthy avant d’accéder à la propriété :

```js
const email = document.querySelector<HTMLInputElement>("#email");
if (email) {
  console.log(email.value);
}
```

Dans cet exemple mis à jour, comme `null` n’est pas une valeur truthy, TypeScript peut déduire que `email` DOIT être un élément `input` dans le bloc conditionnel. Il ne lève donc plus d’erreur de compilateur.

Les vérifications de truthiness peuvent aussi fonctionner dans le sens inverse :

```js
const email = document.querySelector<HTMLInputElement>("#email");
if (!email) {
  throw new ReferenceError("Could not find email element!")
}
console.log(email.value);
```

Avec cette approche, on lève une erreur si `email` est falsy. `null` est une valeur falsy. Lever une erreur met fin à l’exécution logique de ce code, ce qui signifie que lorsqu’on atteint l’appel `console.log()`, TypeScript sait que `email` ne peut pas être `null`.

Le chaînage optionnel est aussi une forme de type narrowing, selon le même principe : l’accès à la propriété ne peut pas se produire si la valeur `email` est `null`.

```js
const email = document.querySelector<HTMLInputElement>("#email");
console.log(email?.value);
```

Mais qu’en est-il des autres types ? Eh bien, tu peux aussi restreindre les types avec l’opérateur `typeof`. Regardons l’exemple d’une variable indiquée comme pouvant être une chaîne OU un nombre :

```js
const myVal = Math.random() > 0.5 ? 222 : "222";
console.log(myVal / 10)
```

Dans cet exemple, on voit une erreur de compilateur car on ne peut pas faire d’arithmétique sur une valeur de type string. Mais on peut utiliser une condition pour vérifier le `typeof` de la variable `myVal` :

```js
const myVal = Math.random() > 0.5 ? 222 : "222";
if (typeof myVal === "number") {
  console.log(myVal / 10);
}
```

Parce qu’on a utilisé le mot-clé `typeof`, TypeScript sait maintenant que `myVal` doit être un nombre, et on peut faire de l’arithmétique en toute sécurité.

Mais qu’en est-il des types d’objets plus complexes ? Si l’objet en question vient d’une classe, tu peux en fait utiliser le mot-clé `instanceof` pour restreindre le type. En revenant à notre exemple `querySelector()` :

```js
const email = document.querySelector("#email");
```

Plutôt que de passer un type générique et de dire à TypeScript ce qu’est l’élément, on peut utiliser `instanceof` pour restreindre le type et écrire un code plus sûr :

```js
const email = document.querySelector("#email");

if (email instanceof HTMLInputElement) {
    console.log(email.value);
}
```

Cette approche peut sembler identique à la précédente, mais `instanceof` est une validation à l’exécution — ce qui signifie que si on s’était trompé sur le type TypeScript, notre code JavaScript confirmera quand même que `email` est un élément `input`.

Ensuite, regardons un exemple où on récupère un objet `User` depuis une API et on essaie d’afficher les informations :

```js
interface User {
    name: string;
    age: number;
}

const printAge = (user: User) =>
  console.log(`${user.name} is ${user.age} years old!`)

const request = await fetch("url")
const myUser = await request.json();
printAge(myUser);
```

On obtiendra une erreur de compilateur en essayant de passer `myUser` à la fonction car, même si on sait que l’API renvoie le bon objet, TypeScript ne le sait pas. Et la méthode `.json()` n’accepte pas de type générique.

La façon « facile » de résoudre ce problème serait de caster le type :

```js
interface User {
    name: string;
    age: number;
}

const printAge = (user: User) =>
  console.log(`${user.name} is ${user.age} years old!`)

const request = await fetch("url")
const myUser = await request.json() as User;
printAge(myUser);
```

Mais chaque fois que tu castes le type, tu affaiblis essentiellement la capacité de TypeScript à attraper d’éventuelles erreurs. Alors, au lieu de caster le type, tu peux écrire un type guard :

```js
interface User {
    name: string;
    age: number;
}

const isValidUser = (user: unknown): user is User => {
  return !!user &&
    typeof user === "object" &&
    "name" in user &&
    "age" in user;
}
```

Le type de retour est ici l’élément clé de cette définition de fonction. La syntaxe `user is User` indique que notre fonction renvoie une valeur booléenne, qui lorsqu’elle est `true` signifie que la valeur `user` satisfait l’interface `User`. On fait ensuite quelques vérifications de base pour s’assurer que la structure de l’objet `user` correspond — note l’utilisation d’un narrowing de truthiness (`!!user`) et d’un narrowing `typeof`. On doit le faire car `typeof null` renvoie `"object"` :

```js
interface User {
    name: string;
    age: number;
}

const isValidUser = (user: unknown): user is User => {
  return !!user &&
    typeof user === "object" &&
    "name" in user &&
    "age" in user;
}

const printAge = (user: User) =>
  console.log(`${user.name} is ${user.age} years old!`)

const request = await fetch("url")
const myUser = await request.json() as User;
if (isValidUser(myUser)) {
    printAge(myUser);
}
```

Maintenant, si on combine toute notre logique, on n’a plus d’erreurs de compilateur et on peut compiler notre code avec succès.

Le type narrowing est une fonctionnalité puissante qui t’aide à écrire un code plus sûr et moins sujet aux erreurs — mais souviens-toi que les types TypeScript ne sont pas complètement rigides, donc évite des pratiques comme caster le type d’une valeur sans le restreindre.
