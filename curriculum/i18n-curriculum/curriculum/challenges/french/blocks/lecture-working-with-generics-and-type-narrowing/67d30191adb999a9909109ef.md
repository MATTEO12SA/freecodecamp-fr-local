# --description--

Tu as déjà vu un type générique dans une leçon précédente : `Array<string>`. Mais tu utiliseras généralement les types génériques dans les fonctions. En fait, on peut les voir comme un paramètre spécial que tu fournis à une fonction pour contrôler le comportement de sa définition de type.

Revenons à notre exemple précédent d’une fonction qui récupère une valeur aléatoire dans un tableau :

```js
const getRandomValue = (array: string[]): string => {
  return array[Math.floor(Math.random() * array.length)];
}
```

Notre fonction accepte un tableau de chaînes et renvoie une chaîne. Mais que se passe-t-il si on voulait passer un tableau de nombres et renvoyer un nombre ?

Tu pourrais utiliser un type union :

```js
const getRandomValue = (array: (string|number)[]): (string|number) => {
  return array[Math.floor(Math.random() * array.length)];
}
const val = getRandomValue([1, 2, 4])
```

Mais avec cette approche, même si on a passé un tableau composé uniquement de nombres, TypeScript détermine que la variable `val` pourrait être un nombre OU une chaîne.

À la place, tu peux définir un type générique pour la fonction :

```js
const getRandomValue = <T>(array: T[]): T => {
  return array[Math.floor(Math.random() * array.length)];
}
const val = getRandomValue([1, 2, 4])
```

Il y a quelques éléments importants dans notre nouvel exemple. D’abord, la syntaxe `<T>` indique à TypeScript que tu définis un type générique `T` pour la fonction. `T` est un nom courant pour les types génériques, mais tu peux en fait le nommer comme tu veux (dans les conventions de variables JavaScript).

Ensuite, on dit à TypeScript que le paramètre tableau est un tableau de valeurs correspondant au type générique, et que la valeur renvoyée est un seul élément de ce même type. Cela permet à TypeScript de détecter correctement que `val` sera un nombre, car le tableau passé ne contient que des nombres.

Mais qu’en est-il des fonctions que tu ne contrôles pas ? Regardons la méthode `document.querySelector()` :

```js
const email = document.querySelector("#email");
console.log(email.value);
```

Parce qu’on interroge avec un sélecteur d’ID, TypeScript ne sait pas quel type d’élément on interroge. Il sait que c’est un `Element` d’une certaine sorte, mais notre tentative d’accéder à la propriété `value` lèvera une erreur car l’interface d’élément de premier niveau n’a pas cette propriété.

Heureusement, on peut passer un argument de type à l’appel de fonction :

```js
const email = document.querySelector<HTMLInputElement>("#email");
console.log(email.value);
```

Remarque qu’on utilise à nouveau la syntaxe des chevrons (`<HTMLInputElement>`), mais cette fois dans un appel de fonction. Cela indique à TypeScript que l’élément qu’on s’attend à trouver sera un élément `input`, et on n’a plus d’erreur sur la propriété value car les éléments input ont bien cette propriété. Bien sûr, `querySelector` peut renvoyer `null` si un élément n’est pas trouvé, et TypeScript lèvera une erreur de compilateur ici car on ne gère pas ce cas.

Mais tu apprendras cela dans la prochaine leçon.
