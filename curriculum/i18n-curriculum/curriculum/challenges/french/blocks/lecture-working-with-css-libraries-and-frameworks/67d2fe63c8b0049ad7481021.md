# --description--

Un préprocesseur CSS est un outil qui étend le CSS standard avec des fonctionnalités puissantes comme les variables, les mixins, l'imbrication et l'héritage de sélecteurs.

Certaines de ces fonctionnalités, comme les variables et l'imbrication, sont maintenant prises en charge ou le sont de plus en plus en CSS natif, et cette tendance a de fortes chances de continuer. Cependant, les versions antérieures du CSS natif ne prenaient pas en charge ces fonctionnalités.

C'est pourquoi les préprocesseurs CSS sont devenus si largement utilisés au départ. Ils prennent les règles et styles CSS que tu écris, avec leur syntaxe étendue, et les compilent en un fichier CSS natif que les navigateurs peuvent comprendre.

En utilisant un préprocesseur CSS, tu peux structurer ton code CSS de façon plus réutilisable et logique. Tu auras aussi accès à des fonctionnalités puissantes, comme les mixins, qui ne sont pas directement prises en charge par le CSS.

Parmi les préprocesseurs CSS les plus populaires, on trouve Sass, Less et Stylus.

Parlons de Sass.

Sass signifie « Syntactically Awesome Style Sheets ». Il est compatible avec toutes les versions de CSS et maintenu par une large communauté de développeurs.

Sass prend en charge des fonctionnalités comme :

- Les variables, pour stocker et réutiliser des valeurs dans toute la feuille de style.

- Les règles CSS imbriquées, pour créer une hiérarchie visuelle dans ton fichier.

- Les modules, pour découper tes styles en plusieurs feuilles de style.

- Les mixins, pour réutiliser des déclarations CSS dans tout ton site.

- L'héritage, pour que plusieurs sélecteurs CSS puissent partager des propriétés.

- Et les opérateurs, pour des opérations mathématiques de base.

Sass prend aussi en charge deux syntaxes.

La syntaxe SCSS signifie Sassy CSS, qui est un surensemble du CSS. Cela signifie que SCSS étend la syntaxe de base du CSS.

SCSS est la syntaxe la plus courante que tu utiliseras et trouveras en travaillant avec Sass. Elle exige l'utilisation d'accolades (`{` et `}`) autour des propriétés CSS et de points-virgules (`;`) à la fin des déclarations CSS, tout comme le CSS natif.

Ces fichiers ont une extension `.scss`. Voici un exemple :

```scss
$primary-color: #3498eb;

header {
  background-color: $primary-color;
}
```

Ce que tu vois ici, en haut, est une variable définie en SCSS. Cette variable est utilisée dans la règle CSS ci-dessous.

Comparons SCSS avec une syntaxe moins fréquemment utilisée, la syntaxe indentée. Elle est aussi connue sous le nom de « syntaxe Sass » car c'était la syntaxe originale de Sass.

Cette syntaxe s'appuie sur l'indentation pour définir les règles. Voici un exemple :

```scss
$primary-color: #3498eb

header
  background-color: $primary-color
```

Remarque qu'il n'y a pas d'accolades autour de la règle CSS, ni de points-virgules à la fin des déclarations CSS. En haut, tu peux aussi voir une variable. Remarque que son nom commence par un signe dollar (`$`) dans cette syntaxe, ce qui est différent des variables CSS natives, mais fonctionne de façon très similaire.

Sass prend aussi en charge une fonctionnalité puissante, appelée mixins.

Les mixins te permettent de regrouper plusieurs propriétés CSS et leurs valeurs sous un nom et de réutiliser ce bloc de code CSS dans toute ta feuille de style.

Cela rend ton code CSS moins répétitif et plus facile à maintenir car, si tu changes quelque chose dans ce bloc, le changement est appliqué partout où tu utilises le mixin.

Comme les mixins peuvent avoir des noms personnalisés et descriptifs, ils peuvent aider à comprendre ce que fait chaque bloc de code CSS, ce qui peut rendre tes feuilles de style plus faciles à comprendre.

Et les mixins favorisent aussi la cohérence dans les feuilles de style en appliquant des styles uniformes.

Voici un exemple de mixin en syntaxe SCSS :

```scss
@mixin center-flex {
  display: flex;
  justify-content: center;
  align-items: center;
}
```

Pour définir un mixin, tu commences par écrire l'at-rule `@mixin`, suivie du nom du mixin. Dans ce cas, le mixin s'appelle `center-flex`. Il a trois propriétés CSS pour centrer les éléments avec Flexbox.

Ensuite, une fois ton mixin défini, tu utiliserais l'at-rule `@include` pour inclure ces propriétés dans une règle CSS. Tu as juste besoin d'écrire `@include` suivi du nom du mixin. Dans ce cas, le nom est `center-flex` :

```scss
section {
  @include center-flex;
  height: 500px;
  background-color: #3289a8;
}
```

Voici le code complet avec le mixin et la règle CSS :

```scss
@mixin center-flex {
  display: flex;
  justify-content: center;
  align-items: center;
}

section {
  @include center-flex;
  height: 500px;
  background-color: #3289a8;
}
```

Tu peux inclure le mixin dans autant de règles CSS que nécessaire. Si tu dois faire des changements, tu n'aurais qu'à modifier le mixin lui-même et les changements seraient appliqués partout automatiquement. Cet exemple est en syntaxe SCSS. Remarque qu'il a les accolades et les points-virgules.

Voici l'équivalent en syntaxe indentée, aussi connue sous le nom de syntaxe Sass, sans les accolades ni les points-virgules :

```scss
@mixin center-flex
  display: flex
  justify-content: center
  align-items: center

section
  @include center-flex
  height: 500px
  background-color: #3289a8
```

Et voici le code CSS compilé, ce que le navigateur interprétera réellement après que le fichier soit compilé en CSS natif :

```css
section {
  display: flex;
  justify-content: center;
  align-items: center;
  height: 500px;
  background-color: #3289a8;
}
```

Remarque qu'il inclut les trois propriétés du mixin en haut : `display`, `justify-content` et `align-items`.

Ceci n'est qu'un exemple simple de ce dont les préprocesseurs CSS sont capables. Ils ont de nombreuses fonctionnalités puissantes qui valent la peine d'être apprises et appliquées dans ton workflow quotidien.

Cependant, ils ont des inconvénients potentiels dont tu devrais être conscient.

D'abord, les préprocesseurs CSS doivent compiler les règles CSS en CSS standard. Bien que la surcharge potentielle de ce processus de compilation soit souvent minimale en termes de temps et de ressources, c'est quelque chose que tu devrais considérer pour les projets réels.

Ensuite, ils peuvent créer des défis de débogage, puisque les navigateurs utilisent directement le CSS compilé. Découvrir ce qui génère un style problématique à partir de la syntaxe étendue peut prendre quelques étapes supplémentaires par rapport au CSS standard.

Cependant, les avantages des préprocesseurs CSS l'emportent généralement sur leurs inconvénients, surtout pour les projets complexes. Ils peuvent être très utiles pour écrire un CSS plus propre, réutilisable, moins répétitif et évolutif.
