# --description--

Les services web et les API REST alimentent la plupart des apps et sites que tu utilises chaque jour. Ils permettent à différentes applications de communiquer entre elles et de partager des données sur un réseau, le plus souvent Internet.

Une API (Application Programming Interface) est un moyen général pour un logiciel de communiquer avec un autre logiciel. Un service web est un type d'API spécifique qui utilise des technologies web, comme HTTP, pour échanger des données sur un réseau, en général Internet. De ce fait, tout service web est une API — mais toute API n'est pas un service web. Les API REST sont un type courant de service web qui suivent un ensemble de règles précis sur la façon dont les données sont demandées et renvoyées.

Cette leçon se concentrera sur ce que sont les services web à haut niveau, et la suivante entrera plus dans le détail sur le fonctionnement des API REST.

Tu peux voir un service web comme un pont logiciel-à-logiciel. Il n'a pas d'interface utilisateur et n'est pas destiné à être utilisé directement. Au contraire, il se concentre entièrement sur l'échange de données entre applications.

Pour qu'un système soit considéré comme un service web, il doit avoir les caractéristiques suivantes :

* **Tourne sur un serveur** : un service web doit être hébergé en ligne comme un site, mais au lieu de pages visibles par les utilisateurs, il expose des données ou une fonctionnalité

* **Communication machine-à-machine** : un service web n'est pas fait pour que des humains le consultent directement, mais pour que des apps mobiles et web le consomment, afin d'exposer des données ou une fonctionnalité que l'utilisateur pourra enfin voir

* **Indépendant du langage** : un service web peut être écrit dans n'importe quel langage comme Java ou C#, et toute app devrait pouvoir interagir avec lui, même si elle est écrite dans un autre langage

* **Indépendant de la plateforme** : peu importe la plateforme sur laquelle tournent les machines. Par exemple, un service web sous Linux ne devrait pas empêcher un appareil sous Windows de communiquer avec lui

* **Utilise des protocoles web standard** : un service web devrait en général utiliser HTTP/HTTPS pour transférer des données sur Internet, FTP pour le transfert de fichiers, et SMTP pour l'e-mail

**REST** et **SOAP** sont deux des types de services web les plus connus, même s'il existe d'autres approches, comme **XML-RPC**.

**REST**, qui signifie **Representational State Transfer**, est de loin le plus utilisé aujourd'hui. La plupart des applications modernes s'appuient sur des services web RESTful parce qu'ils sont simples, flexibles, et fonctionnent naturellement avec le web.

Les API REST exposent des ressources, généralement représentées par des chemins d'URL comme `/users` ou `/users/20`. Quand un client demande une ressource, le serveur renvoie une représentation de cette ressource. Cette représentation est souvent en JSON, mais elle peut aussi être dans des formats comme XML ou même du texte brut.

Les clients peuvent préciser le format qu'ils veulent en utilisant des en-têtes HTTP, comme l'en-tête `Accept`. Par exemple, un client peut demander une réponse JSON en définissant la valeur `Accept` appropriée.

```bash
Accept: application/json
```

Et tu peux préciser que tu veux du XML de cette façon :

```bash
Accept: application/xml
```

La ressource que tu reçois peut ressembler à ceci si c'est du JSON :

```json
{
  "id": 20,
  "name": "John Doe",
  "email": "john@example.com",
  "role": "admin",
  "createdAt": "2025-09-22T10:30:00Z"
}
```

Et à ceci, si c'est du XML :

```xml
<user>
  <id>20</id>
  <name>John Doe</name>
  <email>john@example.com</email>
  <role>admin</role>
  <createdAt>2025-09-22T10:30:00Z</createdAt>
</user>
```

SOAP signifie **Simple Object Access Protocol**. Il n'utilise que le format de données XML, et c'est le plus courant dans les systèmes d'entreprise qui ont besoin de standards et de sécurité plus stricts.

Voici à quoi pourraient ressembler des données SOAP :

```xml
<soapenv:Envelope xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/">
   <soapenv:Body>
      <getUser>
         <userId>20</userId>
      </getUser>
   </soapenv:Body>
</soapenv:Envelope>
```

XML-RPC utilise XML pour encoder ses requêtes et réponses. Cela le rend léger mais moins flexible que REST.

Quant à UDDI, ce n'est pas un service d'échange de données mais un annuaire basé sur XML où les entreprises peuvent lister, découvrir et décrire leurs services web disponibles.
