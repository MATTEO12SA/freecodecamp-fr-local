# --description--

**REST** signifie representational state transfer. Vois-le comme un ensemble de lignes directrices qui décrivent comment les clients web et les serveurs devraient communiquer entre eux sur Internet.

Dans cette leçon, tu vas apprendre ce qu'est REST, ses concepts clés, et comment il fonctionne.

REST définit une façon pour différents systèmes d'interagir en utilisant des technologies web standard. Avec REST, des clients comme les navigateurs web, les apps mobiles et les API communiquent avec un serveur en utilisant des méthodes HTTP courantes comme `GET`, `POST`, `PUT`, `PATCH` et `DELETE`, que nous avons vues dans une leçon précédente.

Parmi les concepts centraux de REST, on trouve **l'absence d'état**, les **ressources**, les **méthodes HTTP**, et les **codes de réponse ou de statut**.

**L'absence d'état** signifie que chaque requête qu'un client envoie au serveur est traitée indépendamment. Le serveur ne se souvient pas des requêtes précédentes. De ce fait, chaque requête doit inclure toutes les informations nécessaires pour la traiter. Par exemple, si un utilisateur est authentifié, son jeton d'authentification doit être envoyé avec chaque requête.

En REST, tout est traité comme une ressource. Une ressource est une donnée qui peut être consultée ou modifiée. Chaque ressource est identifiée par une URL, comme `/products` pour tous les produits, ou `/products/1` pour un produit spécifique.

Voici un aperçu des méthodes HTTP, des codes de statut, et un exemple étape par étape de comment l'architecture REST fonctionne.

## Méthodes HTTP

Les méthodes HTTP définissent l'action à effectuer sur une ressource :

* `GET` : Récupérer une ressource

* `POST` : Créer une nouvelle ressource

* `PUT / PATCH` : Mettre à jour une ressource existante

* `DELETE` : Supprimer une ressource

## Codes de statut HTTP

Après avoir traité une requête, le serveur répond avec un **code de statut** qui indique le résultat :

* `200` **(OK)** : La requête a réussi

* `201` **(Created)** : Une nouvelle ressource a été créée

* `400` **(Bad Request)** : Le client a envoyé des données invalides

* `404` **(Not Found)** : La ressource demandée n'existe pas

* `500` **(Internal Server Error)** : Une erreur s'est produite sur le serveur

## Comment REST fonctionne : un exemple étape par étape

### 1\. Le client envoie une requête

* Le client envoie une requête HTTP en utilisant une méthode comme `GET` ou `POST`

* La requête inclut une URL identifiant la ressource

* Elle peut aussi inclure des en-têtes, des métadonnées et un corps de requête

### 2\. Le serveur reçoit la requête

* Le serveur valide le format de la requête et l'authentification (si nécessaire)

* Il identifie la ressource cible à partir de l'URL

* Il détermine l'action demandée selon la méthode HTTP

* Il vérifie les permissions et le contrôle d'accès

### 3\. Le serveur effectue l'action

* `GET` : Récupérer la ressource

* `POST` : Créer une nouvelle ressource

* `PUT / PATCH` : Mettre à jour la ressource

* `DELETE` : Supprimer la ressource

* Toute autre logique nécessaire est exécutée

### 4\. Le serveur construit la réponse

* Le serveur choisit un code de statut approprié (par exemple, `200`, `201` ou `404`)

* Il formate les données de réponse, généralement en **JSON**

* Il ajoute des en-têtes pertinents comme `Content-Type` ou `Cache-Control`

### 5\. Le serveur envoie la réponse

* La réponse inclut un code de statut, des en-têtes et un corps optionnel

* Aucun état client n'est stocké sur le serveur (absence d'état)

### 6\. Le client gère la réponse

* Le client vérifie le code de statut pour déterminer le succès ou l'échec

* Il traite les données éventuellement renvoyées par le serveur
