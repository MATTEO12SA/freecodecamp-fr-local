# --description--

Le bubbling (ou propagation) d'événements désigne la façon dont un événement « remonte » vers les objets parents quand il est déclenché. Par exemple, considère ce code :

```html
<p>
  <span>Click me~!</span>
</p>
```

L'élément `p` ici serait considéré comme le parent de l'élément `span`.

Quand tu cliques sur l'élément `span`, comme on te le demande, l'élément `span` devient la cible d'un événement `click`. Cet événement remonte aussi vers le parent — l'élément `p` peut recevoir et consommer cet événement au besoin.

Mais qu'est-ce que cela signifie concrètement ? Eh bien, tu pourrais attacher un écouteur d'événement à l'élément `p` :

```js
const p = document.querySelector("p");
p.addEventListener("click", (event) => {
  console.log(event.target);
});
```

Ensuite, quand tu cliques sur l'élément `span`, tu verras le texte `Click me~!` s'afficher dans la console.

L'événement se propage vers l'élément parent `p`, qui le consomme dans un écouteur d'événement pour afficher la cible de l'événement.

Remarque que la cible est toujours l'élément `span`. C'est parce que l'élément `span` a reçu le clic initial.

Pour être sûr du fonctionnement, élargissons notre code :

```js
const p = document.querySelector("p");
const span = document.querySelector("span");
p.addEventListener("click", (event) => {
  console.log("P listener: ");
  console.log(event.target);
});
span.addEventListener("click", (event) => {
  console.log("Span listener: ");
  console.log(event.target);
});
```

Pour te donner une idée de la remontée de l'événement, voici ce que tu verras dans la console après avoir cliqué sur l'élément `span` :

```html
"Span listener: "
<span>Click me~!</span>
"P listener: "
<span>Click me~!</span>
```

Voyons maintenant ce qui se passe quand tu empêches la propagation d'un événement avec `stopPropagation()`. On l'appellera dans l'écouteur d'événement de notre `span` :

```js
const p = document.querySelector("p");
const span = document.querySelector("span");
p.addEventListener("click", (event) => {
  console.log("P listener: ");
  console.log(event.target);
});
span.addEventListener("click", (event) => {
  console.log("Span listener: ");
  console.log(event.target);
  event.stopPropagation();
});
```

Puis clique à nouveau sur notre `span` :

```html
"Span listener: "
<span>Click me~!</span>
```

Cette fois, on ne voit pas notre écouteur `p` se déclencher. L'événement ne se déclenche jamais pour l'élément `p`, parce qu'on lui a dit d'arrêter la propagation pendant qu'il était traité pour l'élément enfant `span`.

La délégation d'événements peut être vue comme l'inverse. C'est le processus de prendre un événement capturé et de le déléguer à un autre élément.

En revenant à notre code, mettons-le à jour pour que le clic sur un élément `span` le passe en rouge :

```js
const p = document.querySelector("p");
const span = document.querySelector("span");
p.addEventListener("click", (event) => {});
span.addEventListener("click", (event) => {
  event.target.style.color = "red";
});
```

Mais et si tu as vingt éléments `span` ? Ou si tu utilises JavaScript pour créer d'autres éléments `span` à la volée ?

Plutôt que d'attacher un écouteur d'événement à chaque élément `span`, tu peux utiliser l'écouteur sur l'élément `p` pour tous. Autrement dit, tu peux déléguer la gestion des clics sur les `span` à l'élément parent `p`.

Notre code pourrait maintenant ressembler à ceci :

```js
const p = document.querySelector("p");
p.addEventListener("click", (event) => {
  event.target.style.color = "red";
});
```

Remarque qu'on n'a plus du tout d'écouteur attaché à l'élément `span`. Tu as correctement délégué la gestion de l'événement à l'élément `p`. Mais est-ce que ça fonctionne ?

Générons quelques éléments `span` supplémentaires et voyons :

```html
<p>
  <span>Click me~!</span>
  <span>Click me~!</span>
  <span>Click me~!</span>
  <span>Click me~!</span>
</p>
```

Maintenant, chaque fois qu'on clique sur un `span`, le texte de cet élément passera en rouge.

Et voilà : avec un seul écouteur d'événement, on a bien laissé un événement `click` remonter des éléments `span` vers le parent `p`, et délégué la logique de cet événement `click` à l'élément `p`.

La propagation et la délégation d'événements peuvent être un sujet complexe, surtout avec des éléments très imbriqués comme les tableaux. Tu es encouragé à explorer davantage et à expérimenter avec une partie du code qu'on a écrit ici.
