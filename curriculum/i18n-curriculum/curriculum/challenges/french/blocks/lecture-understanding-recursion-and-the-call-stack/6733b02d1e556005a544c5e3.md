# --interactive--

La récursion est une fonctionnalité complexe qui te permet d'appeler une fonction de façon répétée jusqu'à atteindre un cas de base. Contrairement à une boucle traditionnelle, la récursion te permet de gérer quelque chose dont la profondeur est inconnue, comme des objets/tableaux profondément imbriqués, ou une arborescence de fichiers. Mais tu peux aussi l'utiliser pour des tâches plus simples, comme compter à rebours à partir d'un nombre donné.

Construisons une fonction qui fait exactement cela. Nous appellerons notre fonction `recursiveCountdown`, et elle doit accepter un nombre. Nous la ferons afficher ce nombre dans la console :

:::interactive_editor

```js
const recursiveCountdown = (number) => {
  console.log(number);
};

recursiveCountdown(5);
```

:::

Maintenant, si nous appelons cette fonction en passant le nombre 5, nous verrons ce nombre s'afficher dans notre terminal. Mais rien d'autre ne se passe – et le nombre 5 n'est certainement pas un compte à rebours.

Avant de commencer à construire la partie récursive de notre fonction, nous devons d'abord établir notre cas de base. Si tu n'as pas de cas de base établi, ton code s'exécutera jusqu'à dépasser ton allocation mémoire et planter.

:::interactive_editor

```js
const recursiveCountdown = (number) => {
  if (number < 1) {
    return;
  }
  console.log(number);
};

recursiveCountdown(5);
```

:::

Pour notre cas de base, nous voulons que le compte à rebours s'arrête si le nombre est inférieur à 1. Quand nous atteignons ce cas de base, nous pouvons renvoyer pour sortir de l'exécution de la fonction.

Maintenant que nous avons préparé en toute sécurité un cas de base, nous pouvons mettre en place la récursion. Le point clé qui rend une fonction récursive, c'est qu'elle s'appelle elle-même durant son exécution. Dans ce cas, nous voulons appeler la fonction après avoir affiché le nombre. Mais pour compter à rebours, notre nouveau nombre doit être diminué de un :

:::interactive_editor

```js
const recursiveCountdown = (number) => {
  if (number < 1) {
    return;
  }
  console.log(number);
  recursiveCountdown(number - 1);
};

recursiveCountdown(5);
```

:::

Cela afficherait les nombres 5, 4, 3, 2 et 1 dans la console.

Nous obtenons bien nos cinq nombres ! Mais que se passe-t-il si nous voulions compter en montant à la place ? Plutôt que d'écrire une fonction entièrement nouvelle, nous pouvons inverser l'ordre de notre log et de notre appel récursif :

:::interactive_editor

```js
const recursiveCountdown = (number) => {
    if (number < 1) {
        return;
    }
    recursiveCountdown(number - 1);
    console.log(number);
  };

recursiveCountdown(5);
```

:::

Cela afficherait les nombres 1, 2, 3, 4 et 5 dans la console.

Mais pourquoi est-ce que ça marche ? Eh bien, pour le comprendre, tu dois comprendre la pile d'appels. La pile d'appels est la façon dont JavaScript suit et résout les appels de fonction. La pile fonctionne comme une sorte de file dernier-arrivé-premier-sorti. Pour mieux comprendre cela, ajoutons quelques logs à notre fonction :

:::interactive_editor

```js
const recursiveCountdown = (number) => {
  console.log(`Function execution started for number: ${number}`);
  if (number < 1) {
    console.log(`Base case reached, begin resolving stack`);
    return;
  }
  console.log(`Calling recursiveCountdown with number: ${number - 1}`);
  recursiveCountdown(number - 1);
  console.log(`Function execution completed for number: ${number}`);
};

recursiveCountdown(5);
```

:::

Nous avons ajouté ici quatre instructions clés. Le premier log s'exécute quand un appel de fonction commence à s'exécuter. Le troisième log s'exécute juste avant que la fonction récursive ne soit appelée. Et le quatrième log s'exécute quand l'exécution de la fonction est terminée. Le résultat est :

```md
Function execution started for number: 5
Calling recursiveCountdown with number: 4
Function execution started for number: 4
Calling recursiveCountdown with number: 3
Function execution started for number: 3
Calling recursiveCountdown with number: 2
Function execution started for number: 2
Calling recursiveCountdown with number: 1
Function execution started for number: 1
Calling recursiveCountdown with number: 0
Function execution started for number: 0
Base case reached, begin resolving stack
Function execution completed for number: 1
Function execution completed for number: 2
Function execution completed for number: 3
Function execution completed for number: 4
Function execution completed for number: 5
```

Mais comment cela se produit-il ? Eh bien, c'est là que la pile d'appels entre en jeu. Quand nous appelons `recursiveCountdown(5)`, cet appel de fonction est ajouté à la pile d'appels.

Quand cet appel de fonction atteint le point où il doit appeler `recursiveCountdown(4)`, il doit s'arrêter et attendre ce résultat. Pendant ce temps, notre `recursiveCountdown(4)` est ajouté à la pile d'appels, au-dessus de `recursiveCountdown(5)`.

Quand cet appel de fonction atteint le point où il doit appeler `recursiveCountdown(3)`, il doit s'arrêter et attendre ce résultat. Pendant ce temps, notre `recursiveCountdown(3)` est ajouté à la pile d'appels, au-dessus de `recursiveCountdown(4)`.

Quand cet appel de fonction atteint le point où il doit appeler `recursiveCountdown(2)`, il doit s'arrêter et attendre ce résultat. Pendant ce temps, notre `recursiveCountdown(2)` est ajouté à la pile d'appels, au-dessus de `recursiveCountdown(3)`.

Quand cet appel de fonction atteint le point où il doit appeler `recursiveCountdown(1)`, il doit s'arrêter et attendre ce résultat. Pendant ce temps, notre `recursiveCountdown(1)` est ajouté à la pile d'appels, au-dessus de `recursiveCountdown(2)`.

Et enfin, quand cet appel de fonction atteint le point où il doit appeler `recursiveCountdown(0)`, il doit s'arrêter et attendre ce résultat. Pendant ce temps, notre `recursiveCountdown(0)` est ajouté à la pile d'appels, au-dessus de `recursiveCountdown(1)`.

Mais `recursiveCountdown(0)` n'appelle pas une autre fonction – elle atteint notre cas de base, où elle renvoie immédiatement. Comme l'exécution de cette fonction est terminée, l'appel de fonction peut être considéré comme « résolu ». Quand l'appel est résolu, il est retiré de la pile.

Maintenant, notre `recursiveCountdown(1)` n'attend plus cet appel – elle est en haut de la pile et peut reprendre son exécution.

`recursiveCountdown(1)` se résout, est retirée de la pile, et permet à `recursiveCountdown(2)` de reprendre son exécution.

`recursiveCountdown(2)` se résout, est retirée de la pile, et permet à `recursiveCountdown(3)` de reprendre son exécution.

`recursiveCountdown(3)` se résout, est retirée de la pile, et permet à `recursiveCountdown(4)` de reprendre son exécution.

`recursiveCountdown(4)` se résout, est retirée de la pile, et permet à `recursiveCountdown(5)` de reprendre son exécution.

Et `recursiveCountdown(5)` se résout et est retirée de la pile. Notre pile d'appels est maintenant vide, donc la récursion est terminée !

Ceci est un aperçu de base du fonctionnement de la récursion en JavaScript. C'est un concept complexe, et tu devrais expérimenter avec un peu de code et des instructions de log jusqu'à être à l'aise avec le comportement de la pile d'appels.

Pour une petite anecdote, nous avons parlé de la façon dont l'absence d'un cas de base peut faire planter ton code quand il n'a plus de mémoire. C'est parce que la récursion empile de plus en plus d'appels de fonction dans la pile d'appels jusqu'à ce que la pile déborde. Exactement comme le nom de la communauté de programmation populaire.
